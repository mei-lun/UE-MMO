### 1.1 为什么补装 Build Tools

原有 MSVC 14.42 被此版 UE 禁用。14.38 通过普通 C++ 测试，却在完整 UE PCH 编译时报 `ContainerAllocationPolicies.h` C7539。没有修改引擎源码，也没有替换已有 Community IDE，而是并行安装微软官方 Build Tools。

注意：工具链目录名为 **14.44.35207**，实际 cl.exe 为 **19.44.35229.0**，UBT 报告 **14.44.35229**。是否禁用应看实际检测结果，不能仅凭目录名判定。当前完整 Editor 构建已经通过。

`Scripts/local.settings.json` 保存本机路径和编译器家族覆盖，并被 Git 忽略。其他机器复制 example 文件，填写引擎目录；有兼容的首选编译器时可留空让 UBT 选择。

## 2. 必备与可选工具

### 必备

1. UE 5.8.x，含 Windows 编译支持、模板与功能包。本仓库按 5.8.3 验证。
2. 兼容 MSVC v143 和 Windows SDK；以本机 UE 的 Windows_SDK.json 和实际构建为准。
3. Git、Git LFS，用于代码和二进制资产版本管理。
4. 一个具有项目文件读写和终端执行能力的编程 Agent。
5. 现成角色/动作资产和来源许可。本工程 M0 已入库。

### 可选

- UE MCP：不是当前必需项；第三方兼容性未验证。
- Blender：只有需要查看/转换源模型或修正骨架时再安装；M0 直接使用 uasset 不依赖它。
- uv：仅当选择的 MCP 服务要求时安装。
- CMake：本项目由 UnrealBuildTool 构建，不作为必备入口。
- VS Code C/C++ 扩展：改善导航/调试，不影响脚本构建。
- Linux/Android/iOS SDK：本项目只面向 Win64，其他平台 INVALID 不等于本项目构建失败。

## 3. 新机器恢复步骤

仓库获取后在 Windows PowerShell 的项目根目录运行：

```powershell
git lfs install --local
git lfs pull
Copy-Item Scripts/local.settings.example.json Scripts/local.settings.json
```

编辑 local.settings.json，确认 UE 路径和编译器后：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/CheckEnvironment.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/AcquireResources.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/Build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/PrepareContent.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/Test.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/Test.ps1 -Render
```

Windows PowerShell 的 `ExecutionPolicy Bypass` 仅用于这个脚本进程，不修改系统级执行策略。当前用户全局要求 shell 以 RTK 开头时，用 `rtk proxy powershell.exe ...` 执行相同命令。

顺序原因：C++ 模块先构建；地图脚本加载该模块；资源入库后再启动游戏。首次运行会编译 Shader，耗时明显高于后续启动。不要看到几十秒无画面就反复启动多个编辑器。

## 6. 磁盘与版本管理

首次检查 C 盘约 32GiB、D 盘约 69GiB 可用；安装工具链和构建后会减少，以 CheckEnvironment 和系统实际可用空间为准。

- 保留源码、配置、脚本、Docs、Content 和许可清单。
- Git LFS 跟踪 uasset、umap、FBX、GLB、PNG、WAV 等。
- Binaries、Intermediate、Saved、DerivedDataCache、Artifacts、原始下载包不进入普通 Git。
- 不同时让两个 Agent 改同一 umap/uasset。编辑器保存与文件同步要串行。
- `PrepareContent` 不重建已有地图；它会更新自身命名的测试演员与基础灯光。开始手工设计关卡后应复制地图并停止让基础脚本管理该副本。
- 删除缓存前关闭 UE，并精确核实路径；磁盘紧张不自动删除用户其他内容。

## 7. 常见故障

### 编译器不受支持

读 Artifacts/Logs/build-Editor.log，确认实际 compiler 版本和被选路径。不要改 Engine 头文件规避。确认 local.settings.json 指向安装中的工具链家族；如果组件只是目录存在但安装未结束，不立即重试。

### 无法加载模块

检查 UE 版本一致性和 Editor 模块构建是否成功。关闭运行中的 Editor，再完整构建。不要接受未检查的自动升级/重新保存所有资源。

### 资源找不到

先 `git lfs pull`，防止 Content 中仍是 LFS 文本指针。确认 `/Game/Characters/Mannequins` 路径不被手工改名。PrepareContent 的 report 会给出具体缺失路径。

### Python 不认识 unreal

脚本必须由 UE 的 `-run=pythonscript` 执行，并启用 PythonScriptPlugin 和 EditorScriptingUtilities。普通系统 Python 用于文本/JSON，不负责写 UE 原生资产。

### 游戏黑屏/Shader 编译

检查日志是否仍在 ShaderCompileWorker 工作、地图是否存在、GameDefaultMap 是否指向 L_PrototypeArena。Test -Render 使用真实 GPU；Test 默认 NullRHI 不产生可视画面。不要把 NullRHI 成功描述为渲染验证。

### 素材站超时

已有基线不受影响。AcquireResources 有超时与 SHA256 检查；下载改变时停止并核对作者版本。Agent 不能伪造“下载完成”。
