# M1 本地连招切片实现计划

> 面向后续编程 Agent：按任务顺序执行并在每个任务后编译、测试、更新验证记录。若当前工具有 executing-plans 工作流，可用其分任务执行。本文件描述下一阶段工作，不意味着以下功能已实现。

**目标：** 在现有 M0 工程上完成“普攻两段 → 上挑 → 空中追击 → 落地”的本地可复位战斗切片。

**架构：** Character 负责输入/移动，CombatComponent 负责动作时间和命中调度，HealthComponent 负责扣血与死亡，数据资产描述窗口和动画。以本地确定的逻辑顺序工作，暂不实现网络和 GAS。

**技术栈：** UE 5.8.3、C++20、Enhanced Input、AnimSequence/Montage、UE 编辑器 Python、PowerShell。

**设计依据：** Docs/01-游戏与技术设计.md，特别是第 4–8、11–15 节。

## 全局约束

- Win64、单机；不接入用户服务端，不创建 Dedicated Server。
- X 横向、Y 纵深、Z 高度；地面 Y 不能被平面约束关闭。
- 当前已验证 M0 在 `Source/UEMMO/Prototype*`；逐步改造，不删除能运行的基线。
- 只使用现成素材；缺少专用动作时明确标注占位。
- 先用 C++ 自动化验证逻辑，再用运行场景验证碰撞和表现。
- 参考帧率 60Hz；任何攻击窗口使用半开区间 [start,end)。
- 每个任务验收独立，不一次重写全部战斗系统。
- 新增类型位于现有 UEMMO 模块，不先拆多个插件。

## 任务 1：可测试的输入缓存和动作时间线

文件：

- 新建 Source/UEMMO/Combat/CombatTimeline.h / .cpp。
- 新建 Source/UEMMO/Tests/CombatTimelineTests.cpp。
- 修改 Source/UEMMO/UEMMO.Build.cs，仅在确实使用新模块时添加依赖。

接口建议以实际编译为准，统一采用以下命名：

```cpp
enum class ECombatInput : uint8 { Light, Launcher, Jump };
struct FBufferedCombatInput
{
    uint64 Sequence = 0;
    ECombatInput Action = ECombatInput::Light;
    double PressedAt = 0.0;
};
class FCombatInputBuffer
{
public:
    void Push(FBufferedCombatInput Input);
    bool Consume(ECombatInput Action, double Now, double Lifetime, FBufferedCombatInput& Out);
    void Reset();
private:
    TArray<FBufferedCombatInput> Inputs;
};
struct FCombatWindow
{
    int32 Start = 0;
    int32 End = 0;
    bool Intersects(int32 PreviousFrame, int32 CurrentFrame) const;
};
```

步骤：

- [ ] 添加最小 Automation Test，先检查空缓存不消费、输入过期、消费后不可二次消费。
- [ ] 实现缓存最大 4 条，淘汰最早条目；过期清理不影响仍有效的其他输入。
- [ ] 定义区间交叉，例如窗口 [7,11)，从帧 6 跳到 12 应报告曾经过该窗口；处理逻辑和表现不能因低帧率漏掉。
- [ ] 下面的边界测试应全部通过：

```cpp
FCombatInputBuffer Buffer;
FBufferedCombatInput Out;
TestFalse(TEXT("empty"), Buffer.Consume(ECombatInput::Light, 1.0, 0.15, Out));
Buffer.Push({1, ECombatInput::Light, 1.0});
TestTrue(TEXT("fresh"), Buffer.Consume(ECombatInput::Light, 1.10, 0.15, Out));
TestFalse(TEXT("once"), Buffer.Consume(ECombatInput::Light, 1.11, 0.15, Out));
Buffer.Push({2, ECombatInput::Light, 2.0});
TestFalse(TEXT("expired"), Buffer.Consume(ECombatInput::Light, 2.16, 0.15, Out));
const FCombatWindow Window{7,11};
TestTrue(TEXT("hitch crosses active window"), Window.Intersects(6,12));
TestFalse(TEXT("past window"), Window.Intersects(11,12));
```

- [ ] Build.ps1，再通过 UE Automation 执行 `UEMMO.Combat.Timeline`，将报告导出至 Artifacts/Automation。为此增加 `Scripts/TestCombat.ps1`，必须验证导出 JSON 中测试通过，不能只检查进程退出。
- [ ] Git 本地提交此任务；不推远程。

完成标准：输入缓存可以纯逻辑测试；帧率变化不漏阶段。暂不改角色动画。

伤害接口：`ApplyHit(const FCombatHit& Hit)`；FCombatHit 包含 AttackInstanceId、Instigator 的弱引用、Damage、Impulse 和 HitGroupId。返回是否真正接受命中，以便只对有效命中播放反馈。

步骤：

- [ ] 测试 HP 夹取、同一攻击去重、死亡事件单次发出和已死亡拒绝受击。
- [ ] 创建训练敌人替换当前只预览的 Quinn Actor；保留独立的外观预览关卡用途。
- [ ] 在每个有效逻辑步用 Sweep/Overlap 查询，过滤自身和无效对象；全窗口使用同一 AttackInstanceId。
- [ ] 测试目标 Y=0 能命中、Y=150cm 能打空，距离阈值边缘行为一致。
- [ ] 长帧跨越窗口时至少执行一次合理扫掠，不能每跨一帧重复应用伤害。
- [ ] R 同时复位双方、恢复 HP、清除输入和已命中集合。

完成标准：看得见的敌人会掉血；不同纵深不会被横向距离近错误命中；一次动作只扣一次血。
