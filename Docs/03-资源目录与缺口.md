## 4. M1 必须验证的美术缺口

1. 专用上挑动作：上挥的视觉与逻辑起飞时机对齐。
2. 空中追击动作：不能出现角色站在空中走路的明显违和。
3. 空中受击和倒地恢复：区分死亡，不重复播放死亡动画作为复活。
4. 模型朝向与武器：首轮徒手；武器职业需新增握点与武器素材。
5. 脚步与命中音频触发：声音本身已具备，时机和并发限制未实现。

缺口不阻止 M0 运行。M1 的机制可以用现有动作占位验证，但用户对动作观感验收前不能声称连招美术完整。

## 5. 后续资源需求按阶段控制

- M1：现成攻击/受击动作、简洁命中特效、调试图标；优先复用已入库内容。
- M2：一套可辨认的敌人外观、出生/死亡/门解锁反馈；允许同骨架变色研究。
- M3：装备图标、选图缩略图、UI 音效；没有外观换装要求，不提前采购大量模型。
- M4：网络不新增美术依赖，主要是协议、同步和状态表现。

## 6. 资产清单字段与入库流程

manifest.json 记录 pack id、作者、来源 URL、本地路径、许可证据、SHA256、是否为启动必需项和实际状态。实际文件库存与动画库存独立保留。

新增流程：查作者原站→确认免费层→保存原包→核对许可→SHA256→解压至 SourceAssets/Unpacked→UE API 导入到独立命名空间→记录骨架/材质引用→保存→重启重载→渲染截图→提交 LFS 资产和文本清单。

禁止直接覆盖同名 Skeleton、未经预览批量重定向全部动作、在文件管理器中改 UE 资产文件名、把未下载包标成“已准备”。
