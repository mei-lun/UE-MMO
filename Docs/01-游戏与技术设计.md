# UE-MMO 游戏与技术设计

版本：0.1 · 日期：2026-09-25 · 状态：单机研究原型设计基线

## 1. 项目目标

用 Unreal Engine 5.8.3 构建一个固定横版视角、允许地面纵深移动的 3D 动作刷图原型。客户端实现工作交给 ZCode / CodeBuddy 等编程 Agent；用户提供玩法判断、反馈和未来服务端接口。美术使用现成免费或引擎附带素材，不要求 AI 从零生成角色、贴图或动作。

项目同时验证两个目标：

1. 开发方式：Agent 能否完成代码、UE 资产、编译、运行、错误定位、画面检查这一完整流程。
2. 游戏玩法：普攻、技能取消、浮空和追击是否形成可重复、有操作反馈的连招体验。

目录名 UE-MMO 是项目标识，不代表当前阶段是 MMO。首版没有在线账号、多人场景、匹配、聊天、交易或经济服务。单机玩法跑通后再接入用户已有服务端；本阶段不另建 UE Dedicated Server。

首个完整单机切片控制在：1 个徒手职业、1 种近战敌人、1 个房间、2 段普攻、1 个上挑、1 个空中追击、3 类装备属性。不要先扩展职业树、开放世界、程序化地图、换装系统、复杂商业 UI、商城或联机框架。

## 3. 玩家体验与完整循环

### 3.1 战斗体验

玩家从侧面观察角色，A/D 控制屏幕左右，W/S 控制场地远近，Space 跳跃。攻击通常朝角色当前左右朝向，不随纵深移动自动朝镜头转身。受击有短促音效、动作和可辨认的击退；上挑能把敌人送入可追击的高度。

成功标准不是动作数量，而是：按键不容易丢失，衔接规则可理解，碰撞与视觉基本一致，敌人在不同纵深时能明确打空，浮空后存在可操作的追击窗口。

### 3.2 M3 的游戏循环

启动→主菜单→选择一个可进入副本→读入本地角色与装备→进入房间→触发波次→战斗→敌人全部死亡→生成结算与掉落→拾取/结算入包→装备→保存→回到选图。

结算只能发生一次。战斗中的随机掉落由本局随机种子和一次性结算标识记录。关闭重开不会重复领取同一局奖励。研究版采用简单本地存档，不声称具备防作弊能力。

## 4. 坐标、移动与镜头

### 4.1 世界坐标约定

- UE 单位：厘米；角度：度；运行时间：秒。
- X：横向。+X = 屏幕右；-X = 屏幕左。
- Y：地面纵深。当前相机位于 +Y，W 向 -Y 远离镜头，S 向 +Y 靠近镜头。
- Z：垂直高度。跳跃和浮空只影响 Z，不以 Y 代替高度。
- Facing：+1 / -1，分别朝 +X / -X。Actor yaw = 0 / 180；模型有独立的轴向校准旋转。
- 地面位置为 X/Y；GroundZ 由有效地面获得；AirHeight = CapsuleBottomZ - GroundZ。

不得使用阻止 Y 运动的平面约束。CharacterMovement 保持 `bConstrainToPlane=false`。所有攻击判定同时考虑 X、Y、Z 范围。

### 4.2 初始参数

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 横向速度 | 420 cm/s | M0 基线 |
| 纵深速度 | M0 420，M1 调试目标 280 cm/s | 分开暴露参数后再调；不能把目标值写成当前实测 |
| Capsule 半径 / 半高 | 36 / 96 cm | 不用于最终精细受击体积 |
| 跳跃速度 | 620 cm/s | Z 方向 |
| GravityScale | 1.5 | M0，战斗浮空另由状态控制 |
| AirControl | 0.35 | 玩家普通跳跃 |
| Walking brake | 2400 cm/s² | 初始制动 |
| 房间内场 | 2400 × 1000 cm | 24m × 10m |

M1 分方向缩放输入时，先归一化二维输入，避免斜向同时按键提高总移动速度。纵深方向不改变 Facing；左右输入超过死区才允许转向。攻击进入有效段后锁定本次攻击方向，避免一帧内反向改变命中体积。

### 4.3 镜头

M0：SpringArm 1700cm、俯角约 18°、yaw -90°、FOV 55°，绝对旋转，禁止鼠标旋转镜头。相机当前跟随角色三轴位置，属于基础验证实现。

M1：相机跟随 GroundAnchor 而非浮空角色的完整 Z。横向加入平滑、房间边界夹取；纵深小幅跟随；普通跳跃不造成大幅上下摆动。FOV 和跟随距离独立配置。先用透视相机，不在未比较画面前改成正交投影。

视野必须同时覆盖玩家、主要被击目标和落点。屏幕边缘不能挡住输入提示。前景围栏应低矮或可淡出。相机不能因为角色朝向翻转而绕到场地另一侧。

## 5. 输入与动作时间

### 5.1 输入定义

| 输入 | 初始键位 | 目标行为 | 当前阶段 |
|---|---|---|---|
| MoveHorizontal | A/D | 左右移动与非攻击期转向 | M0 |
| MoveDepth | W/S | 地面远近移动 | M0 |
| Jump | Space | M0 固定高度跳跃；可变按住高度留给后续调参 | M0 |
| Reset | R | 复位玩家；M1 再复位测试敌人 | M0 |
| LightAttack | J | 普攻或空中追击 | M1 |
| Launcher | K | 上挑 | M1 |
| Dodge | L | 可选闪避，不作为首条连招依赖 | M2 可选 |
| DebugOverlay | F1 | 状态、攻击窗口和碰撞显示 | M1 |

M0 使用代码创建 Enhanced Input 映射，减少二进制输入资源的初始依赖。M1 可迁移到原生 InputAction/MappingContext 资产，但保留同一输入意图接口，不能同时叠加两套映射。

### 5.2 输入缓存

建议结构：`InputIntent { SequenceId, ActionId, PressedAtRealTime, AxisX, AxisY }`。缓存最多 4 条，初值保留 150ms。输入只在发生按下/方向变化时记录，不每 Tick 写入一个攻击。

规则：

1. 收到 J，若当前可开始普攻，立即消费。
2. 若处于可连击前置阶段，缓存到窗口开启；窗口内按优先级消费最早仍有效的匹配输入。
3. 过期输入删除；死亡、复位、地图切换必须清空缓存。
4. 一条 SequenceId 最多消费一次；技能被打断也不能回退重用。
5. Pause 不推进战斗时间；命中停顿期间保留输入，允许缓冲但不推进动作阶段。

### 5.3 战斗时间轴

M1 用整数逻辑帧表达窗口，设计基准 60Hz。渲染和角色移动仍由 UE 引擎管理，不宣称整个物理模拟确定性锁步。

Gameplay 模块积累 DeltaSeconds，按 1/60 秒推进攻击时间；每次 tick 处理最多 8 步，卡顿超限记录日志，不静默丢弃累计时间。窗口检测使用区间交叉而非 `time == threshold`，避免低帧率错过命中。

动画播放时间由 AttackFrame / LogicFPS 映射。逻辑决定伤害与状态；Animation Notify 触发音效、粒子等表现，不作为唯一权威伤害入口。命中停顿使用受影响角色的局部计时冻结，避免全局时间缩放影响菜单和其他敌人。

## 6. 战斗状态机

建议分成三组正交状态，避免一个枚举无限膨胀：

- LifeState：Alive / Dead。
- LocomotionState：Grounded / Rising / Falling。
- ActionState：Free / Attacking / HitStun / Knockdown / Recovering。

约束优先级：Dead > Knockdown/HitStun > Attacking > Free。被命中可打断普通攻击；霸体先不加入。浮空由 Locomotion + Action 组合描述，不能同时被普通地面移动覆盖速度。

关键事件：InputIntent、AttackStarted、WindowOpened、HitConfirmed、DamageApplied、LaunchApplied、Landed、Died、Reset。日志带 ActorId、AttackInstanceId、AttackId 和时间戳。

| 转移 | 条件 | 副作用 |
|---|---|---|
| Free→Attacking | 有合法输入、存活、状态允许 | 新建 AttackInstanceId，锁朝向，清空已命中集合 |
| Attacking→Attacking | 连击/取消窗口允许下个动作 | 消费一次输入，切换定义，记录衔接 |
| Attacking→Free | 动作结束且无合法接招 | 释放移动/转向限制 |
| AnyAlive→HitStun | 接受伤害且未死亡 | 停止当前攻击，写入硬直和冲量 |
| Grounded→Rising | 上挑命中或主动跳跃 | 设置垂直速度，记录起跳高度 |
| Falling→Knockdown | 被击目标触地 | 落地保护与倒地计时 |
| AnyAlive→Dead | HP ≤ 0 | 禁止输入/攻击，发送死亡一次，解除可命中注册 |

## 7. 第一套连招数据

下表是**待试玩调参的设计初值**，不是从素材动画自动推导的正确数值，也不是已实现效果。

| AttackId | 总帧 | 生效帧 [起,止) | 可衔接窗口 | 基础伤害 | 击退 | 硬直 | 下一动作 |
|---|---:|---|---|---:|---:|---:|---|
| light_01 | 26 | [7,11) | [12,24) | 10 | 90cm/s | 0.22s | light_02 / launcher |
| light_02 | 32 | [9,14) | [16,29) | 14 | 120cm/s | 0.28s | launcher |
| launcher | 40 | [12,17) | [18,32) 可跳跃取消 | 18 | 70cm/s + Z 700cm/s | 浮空期间 | aerial_01 |
| aerial_01 | 28 | [6,10) | [12,23) | 12 | X 80cm/s，Z 小幅补偿 | 0.18s | 落地或下一次追击 |

初版限制：每个 AttackInstance 对单一目标只造成一次伤害。持续多段技能以后用 HitGroupId 定义独立击中组。同一敌人浮空周期最多 2 次 launcher，Z 系数依次 1.0、0.7，第三次拒绝上挑反应但仍按规则扣伤害，落地恢复后重置。参数必须经过试玩才能成为正式值。

资源映射：light_01/02 使用已有 MM_Attack_01/02。launcher 暂用 MM_ChargedAttack 作为逻辑验证的表现占位；它不是已确认的精确上挑动作。aerial_01 暂复用 MM_Attack_03 的片段，只验证机制。专用上挑/空中受击素材在 M1 验收前继续寻找现成免费替代，不能把占位当作最终质量。

## 8. 命中、伤害与空间关系

### 8.1 判定方式

首版使用相对于角色逻辑原点的有向 Box Sweep 或 Capsule Sweep，不依赖高速手部骨骼逐帧 Overlap。近战框示例：中心在前方 95cm，高度 90cm；半尺寸 X=85、Y=50、Z=70。Facing=-1 时镜像 X 偏移，不镜像角色地面 Y。

查询流程：BroadPhase Overlap/Sweep→过滤自己/死亡/阵营→检查 HitGroup 去重→地面纵深/垂直重叠→应用伤害和反应→记录 HitConfirmed→播放表现。

需要测试：敌人纵深偏移 0/60/150cm；角色跳高后不能打到不重叠的地面目标；一次生效窗口持续数帧也只有一条伤害；跨多个逻辑步不漏判。

### 8.2 伤害初值

`damage = max(1, round((baseDamage + attacker.AttackPower × coefficient) × 100 / (100 + max(0, defender.Defense))))`。

研究版先关闭暴击、元素伤害、穿透和随机浮动，便于可重复测试。HP 夹取到 [0, MaxHP]。DamageApplied 记录实际扣除值；死亡事件只发一次。

### 8.3 浮空与落地

保留 CharacterMovement 的地面碰撞和重力；战斗组件在命中时控制 LaunchCharacter/速度与状态。不要用 Ragdoll 作为连招阶段的运动驱动。倒地阶段可以播放已有死亡/跌倒动作片段，但必须区分倒地与真正死亡。

每个目标跟踪 AirComboCount、LastLauncherId、GroundContact、RecoveryRemaining。遇到天花板、边界、墙角时通过碰撞调整，不能穿墙追击。玩家死亡、敌人销毁、地图卸载时清理彼此引用，使用弱引用保存目标。

## 9. 敌人和房间

M1 敌人是可复位练习目标：固定位置、HP 可配置、可开关自动恢复，默认不主动攻击。M2 再加入简单近战状态机：Idle→Approach→Telegraph→Attack→Recover→Chase。先在房间平面内直接寻向，不需要为了一个规则矩形房间引入复杂行为树。

近战敌人先对齐 Y 纵深，再到 X 攻击距离；不能无限叠在玩家同一点。攻击有至少 0.35s 可读前摇。出生 0.5s 内不攻击。玩家倒地/死亡后停止追击。

RoomDefinition 字段：RoomId、LevelPath、PlayerSpawn、BoundsXY、WaveDefinitions、RewardTableId、ExitCondition。RoomSession 维护 Seed、AliveEnemyIds、WaveIndex、State 和 SettlementId。玩家进入后触发波次；只有已出生且属于此波次的敌人都死亡，才进入下一波。退出/重开取消未完成刷怪定时器。

## 10. 装备、掉落和存档（M3）

定义与实例必须分开：

- ItemDefinition：DefinitionId、DisplayNameKey、Slot、Icon、BaseStats、Rarity、VisualId。
- ItemInstance：InstanceId、DefinitionId、RollSeed、RolledStats、Level、EquippedSlot。
- Inventory：容量初值 30，装备槽初值 Weapon/Armor/Accessory；M3 暂不改变角色外观。
- DropDefinition：权重列表和数量范围；独立随机流，种子可记录重现。

拾取与结算使用稳定实例 ID 去重。背包满则提示并保留未领取奖励，不丢失装备。装备属性重算从基础属性+所有已装备物品重新求和，避免反复穿脱累积误差。

SaveGame：SchemaVersion、CharacterId、Level、Experience、Inventory、EquippedIds、CompletedSettlementIds、Settings。使用两个槽位 A/B 轮换，成功保存后再更新索引。加载时校验装备 ID 是否存在；损坏时回退上一个有效槽，不静默清空用户数据。研发用清档必须显式操作。

## 11. 软件架构与 UE 类型分工

M0 已有一个运行时模块 UEMMO，先不拆成大量插件。功能增长后在模块内按职责分目录：Character、Combat、Enemy、Room、Items、UI、Persistence、Tests。

| 单元 | 职责 | 不承担 |
|---|---|---|
| APrototypeCharacter | 输入意图转发、角色移动、表现组件所有权 | 掉落、存档、房间结算 |
| UCombatComponent（M1） | 当前动作、缓存、阶段推进、受击与取消 | 网络传输、UI 直接绘制 |
| UAttackDefinition（M1） | 攻击参数和软资源引用 | 运行时生命值 |
| UHealthComponent（M1） | HP、伤害入口、单次死亡事件 | 敌人决策 |
| UCombatPresentationComponent（M1） | Montage、音效、特效和 HitStop | 权威伤害公式 |
| URoomSessionSubsystem（M2） | 单局波次和结果 | 跨局背包数据 |
| UProfileSubsystem（M3） | 本地角色、背包、存档 | 战斗 Tick |
| ULocalSessionAdapter（后续） | 对外表达输入和结果的窄接口 | 现在不实现网络连接 |

推荐事件：OnHealthChanged、OnAttackStarted、OnHitConfirmed、OnActorDied、OnRoomFinished。避免 HUD 每 Tick 扫描全场。C++ 日志分类独立为 LogUEMMOCombat、LogUEMMOAssets、LogUEMMOSession。

GAS：当前不采用，理由是首版技能少且服务端结构未知。触发评估条件：多个职业、大量 Buff/属性叠加或需要与已选网络预测方案协作。不要提前维护一套自研技能系统和 GAS 双份状态。

## 12. 动画与美术资产管线

### 12.1 本次基线

已从本机 UE 官方模板获取 Manny/Quinn、共用骨架、材质、纹理和现成动作。`Content/Characters/Mannequins` 保持原始挂载路径，避免重命名导致引用损坏。项目自制的地图和简单材质位于 `Content/UEMMO`；这类编辑器几何不是生成外部角色美术。

M0 用单动画播放实现待机/跑步/下落切换，它不包含平滑 BlendSpace、完整起跳/落地过渡或连招 Montage。M1 必须升级动画层，在仍保持逻辑可测试的情况下平滑表现。

### 12.2 来源与导入

SourceAssets 分 Downloads（原始包）、Unpacked（临时解压）、Licenses（长期保留）、Manifest（来源和状态）。原始包不进入普通 Git，UE 资产用 Git LFS。每个资产登记作者、URL、获取日期、SHA256、许可证据、用途、UE 路径和验证状态。

Quaternius 三份 Standard 免费包是备用候选。当前下载网络不通，不作为构建硬依赖。Mixamo 需要账号的获取流程不自动代替用户登录。不能使用游戏解包、盗版动作包、来源不明转载。

### 12.3 动画接入验收

骨架根节点唯一、比例符合厘米、双脚贴地、朝向正确；重定向后检查肩肘膝、手脚漂移和下蹲。优先原地动画，角色位移由逻辑统一控制；Root Motion 仅在明确设计时启用。不要在导入时无差别覆盖已有 Skeleton。

首轮看完整动作串，不只看单个动画预览。普通走位需要八方向资源与左右 Facing 的一致映射；纯纵深移动目前使用正向跑步占位，M1 要明确换成合适侧移表现。

### 12.4 音频与 VFX

Kenney Impact Sounds 的拳击、落地和脚步音已作为原始包准备；按角色动作事件触发，限制同帧重复与最大并发。音量调节初值 Master=0.7、SFX=0.7；M0 不自动播放战斗音。

第一轮命中表现可用短暂色彩变化、轻微相机反馈和已有声音。不把大体积 VFX 商城包列为必需；连击数和伤害数字属于 M1 调试 UI。正式粒子按实际缺口选现成免费资源，保持许可清单。

## 13. 数据格式与验证

研发源数据放 `Data/*.json`，UTF-8。字段使用稳定英文 snake_case ID，显示文本单独处理。编辑器脚本后续将源数据生成 DataAsset/数据表，运行时不依赖开发机器的源文件路径。单位写在字段名里，如 active_start_frame、knockback_cm_per_s。

校验规则：ID 唯一；总帧>0；0≤active_start<active_end≤duration；取消窗口范围合法；引用的下一动作存在；资源路径可加载；伤害和半尺寸非负；不存在永远无法退出的零耗时循环；升级曲线单调。

M0 不额外创建一套未消费的数据运行时。后续添加配置时先补字段校验，再接入游戏。

## 14. Agent 开发与 MCP

仓库中的 AGENTS.md、设计文档、README 和 Scripts 是跨 Agent 的事实来源。ZCode/CodeBuddy 负责读文件、改代码、调用脚本、分析测试结果。AI 写入二进制资产必须通过 UE 接口。编辑器 UI 自动点击仅作兜底，不能替代可靠的资源 API。

推荐任务大小：一次只实现一个可验收行为，例如“W/S 在地面深度移动且不旋转相机”或“light_01 一次命中只扣一次血”。每次提交包含改动理由、执行命令、结果文件和已知限制。

MCP 不是启动项目的必需依赖。第一步通过 PowerShell 命令打通闭环；社区 MCP 放在隔离分支评估。只有能在 UE 5.8.3 下通过资产创建→保存→重启→重载检查，才允许成为主要编辑器入口。MCP 服务保持本机访问，不暴露公网执行编辑器代码。

## 16. 性能目标与调试

初始目标：本机 RTX 4060 Ti 8GB、1080p、单房间 10 个活动敌人，稳定 60fps；这是设计目标，未测得的指标不可写成已达成。M0 使用简化动态光照，暂不开 Lumen 与虚拟阴影，避免学习原型在视觉质量上过早消耗性能。

关心 GameThread、GPU frame、活动动画数、碰撞查询次数、内存和显存；用 stat unit / stat game / Unreal Insights 按问题启用。首次 ShaderCompileWorker 工作时间不算稳定运行帧率。无测量证据不做复杂对象池和多线程战斗重构。

日志禁止每帧打印全部状态。调试模式可画命中框、受击框、Facing、AirHeight、动作帧和当前缓存输入。截图和 JSON 报告放 Artifacts，不混入 Content。

## 17. 后续服务端接入边界

M4 前收集现有协议、ActorId、tick/time 单位、地图实例规则、技能编号、移动权威、伤害结算和掉落规则。根据服务端已有能力决定本地预测、插值、纠正或只做表现同步。

现在保留 InputIntent 和 GameplayEvent 的边界即可，不要求把整个单机游戏写成可替换纯函数服务器。不要从 UE Actor Replication 推导自定义协议已经可接，也不要把客户端当前 SaveGame 当成线上权威数据。

## 18. 主要风险与处理

| 风险 | 当前处理 | 触发进一步动作的条件 |
|---|---|---|
| UE 编译器不兼容 | 安装匹配的 Build Tools，验证 Editor 编译 | 引擎升级后重新验证 |
| 社区素材下载失败 | 用已安装官方模板作为基线，保留候选清单 | 免费包可访问后按清单导入 |
| 动作不适合上挑/空中追击 | 明确占位映射，逻辑先验证 | M1 手感验收前补动作 |
| Agent 只写代码不验证画面 | 脚本报告+渲染截图+用户试玩 | 修改资产/镜头必须重跑 |
| MCP 不支持 5.8 | MCP 非硬依赖 | 在隔离实验中证明兼容后再引入 |
| 磁盘紧张 | 只引必要包，忽略缓存和构建产物 | 可用空间低于 15GB 停止大型下载 |
| 工程描述超出实际完成度 | 验证报告明确 M0/M1 状态 | 每里程碑更新 README 和状态表 |

## 19. 决策记录

- ADR-001：3D 横版固定视角，支持纵深走位，避免按单轴平台游戏设计。
- ADR-002：先单机、本地完整流程，再接现有服务端。
- ADR-003：C++ 核心、薄蓝图、编辑器脚本；不手工编辑 uasset。
- ADR-004：M0 使用官方现成模板资产，社区免费资产按获取情况补充；不生成角色美术。
- ADR-005：MCP 可选，CLI 构建/测试必须独立存在。
- ADR-006：当前不引入 GAS、联机预测和开放世界系统。
- ADR-007：编译器按实际 UE 5.8.3 配置和构建结果选择，不仅依据已安装 VS 的产品名。
