## 根因（两项，均有实机证据）

1. **普通启动被劫持**：M6-026 的"交互启动即经验模式"使每个正常打包 boot 置
   `bResourceExperience=true` → HUD 的 `ConsumeResourceExperienceAutoEntry()` 返回真 →
   `HandleGuildPlaytestEntry` 自动进工会图并 `HideMenuOverlay()`——**主菜单被跳过**（用户包
   日志与自跑日志双证：无 `-UEMMOPlaytestGuild` 开关也出现 PLAYTEST 进入行）。
2. **火山切片从未真正通过**：M8-029 测试假设出生点与触发器重叠（干等 2.5s 不走位），而竹林
   同类测试是走位进触发器（`DevSetMoveAxes(1,0)`）；其"全绿"证据实为被 MSYS 路径转义毁掉的
   运行（命令行 `C:/Program Files/Game/...`，无 Success 行）——报告代理证据失误（与 M8-031
   带红上线同型，教训第二次触发）。

## 实现要求

1. **启动契约修正**（`GameFlowSubsystem.cpp`）：交互启动=正常启动（菜单展示、M8-022 主进入
   生效）；经验模式仅显式 `-UEMMOResourceExperience` 启用。
2. **经验验收契约同步**：`TestResourceExperience.ps1` 显式传 `-UEMMOResourceExperience`；
   `ResourceExperienceAcceptanceTests` 断言措辞更新为显式启动语义（断言逻辑不变）。
3. **火山切片测试修正**（`VolcanoSliceTests.cpp`）：照竹林生产路径走位进触发器（8s 预算），
   出生重叠的错误假设删除。
4. 验证：编辑器渲染版切片绿 → 重打包 → 包内切片绿 → 经验验收绿 → 正常启动零自动进入 +
   菜单可见。
