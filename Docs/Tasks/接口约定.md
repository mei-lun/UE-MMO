# 小任务之间的接口约定

版本：1，2026-09-25。这些是后续实现的约定，不是目前已经存在的类。类型首次出现的任务负责创建；后续任务在同一类型上扩展。必须改名或改语义时，在该任务报告和本文件同步更新所有受影响任务卡，不维护两个近似版本。

## 2. 输入与时钟

首次定义：M1-003；过期扩展：M1-004。

```cpp
enum class ECombatInput : uint8 { Light, Launcher, Jump };
struct FBufferedCombatInput {
    uint64 Sequence = 0;
    ECombatInput Action = ECombatInput::Light;
    double PressedAt = 0.0;
};
class FCombatInputBuffer {
public:
    bool Push(FBufferedCombatInput Input);
    bool ConsumeFirst(ECombatInput Action, FBufferedCombatInput& Out);
    void PruneExpired(double Now, double Lifetime);
    bool Consume(ECombatInput Action, double Now, double Lifetime, FBufferedCombatInput& Out);
    int32 Size() const;
    void Reset();
};
```

容量4；新会话Sequence从1递增，同会话拒绝重复/回退。先剔过期再消费最早匹配动作。恰好150ms仍有效，超过则过期。

PressedAt使用**输入游戏时钟**：正常游戏推进，Pause/本角色HitStop不推进；停顿期间仍可收输入。禁止混用系统UTC时间、UE WorldTime和动作帧来比较同一输入寿命。早期测试显式传时间，M1-033接入停顿行为。

首次定义：M1-005/006。

```cpp
struct FCombatWindow {
    int32 StartFrame = 0, EndFrame = 0;
    bool IsValid(int32 Duration) const;
    bool Contains(int32 Frame) const;
    bool Crosses(int32 PreviousFrame, int32 CurrentFrame) const;
};
class FCombatClock {
public:
    int32 Advance(double DeltaSeconds, bool bFrozen);
    void Reset();
};
```

窗口[start,end)；推进检查(previous,current]中的整数帧，初始previous=-1。例：[7,11)的Crosses(6,12)=true、Crosses(10,11)=false。Advance返回最大8步，保留积压；冻结时丢弃被冻结期间Delta，不在解除时补跑。这个时钟仅用于动作逻辑，不承诺UE物理确定性。

## 3. 攻击定义与源数据

M1-007定义 `UAttackDefinition : UPrimaryDataAsset`，M1-008填源JSON，M1-009生成4份资产，M1-010建立只读目录。

| C++ 字段 | JSON | 单位/初值 |
|---|---|---|
| AttackId | attack_id | FName/string |
| DurationFrames | duration_frames | 正整数 |
| ActiveWindow | active_start_frame / active_end_frame | 半开帧窗 |
| CancelWindow | cancel_start_frame / cancel_end_frame | 半开帧窗 |
| AllowedNextAttacks | next_attack_ids | 稳定ID数组 |
| BaseDamage | base_damage | 非负浮点 |
| AttackCoefficient | attack_coefficient | 1.0 |
| HitOffsetFromFeet | hit_offset_cm | (95,0,90) |
| HitHalfExtent | hit_half_extent_cm | (85,50,70) |
| KnockbackSpeed | knockback_cm_per_s | X冲量大小 |
| LaunchSpeed | launch_cm_per_s | Z冲量大小 |
| HitStunSeconds | hit_stun_seconds | 秒 |
| HitStopSeconds | hit_stop_seconds | 0.04秒 |
| Animation | animation_path | TSoftObjectPtr<UAnimSequence> |
| ClipStartSeconds / ClipEndSeconds | clip_start_seconds / clip_end_seconds | 源动画片段 |
| bPlaceholderAnimation | placeholder_animation | 明确占位标志 |

四条帧/伤害初值沿用主设计：light_01=(26,[7,11),[12,24),10)，light_02=(32,[9,14),[16,29),14)，launcher=(40,[12,17),[18,32),18)，aerial_01=(28,[6,10),[12,23),12)。launcher取消窗允许Jump；aerial暂每浮空周期一次。动画片段的实际时长先读取库存，不猜帧数。

`UAttackCatalog::Find(FName AttackId) const`返回只读定义指针或nullptr。缺失ID不可静默回退。运行时不读取Data/原始JSON，需显式Cook规则/引用确保独立包可加载。

## 4. CombatComponent 与事件

M1-011创建组件，后续按任务扩展，建议接口：

```cpp
bool TryStartAttack(FName AttackId, int32 Facing);
void QueueInput(FBufferedCombatInput Input);
void TickCombat(float DeltaSeconds);
void CancelCurrentAttack(FName Reason);
void ResetCombat();
FCombatSnapshot GetSnapshot() const;
bool CanAcceptMovement() const;
bool CanTurn() const;
```

Snapshot至少包含AttackId、InstanceId、Frame、Facing、ActionState、BufferSize。ActorId/InstanceId用稳定会话内标识，不用裸指针值序列化。Started/Finished/HitConfirmed使用委托；具体UE动态/原生委托形式由首次实现选择，但其他组件不得另维护一套攻击计时。

生命、地面/空中和动作分开：Alive/Dead；Grounded/Rising/Falling；Free/Attacking/HitStun/Knockdown/Recovering。死亡最高优先级。动作中断后旧实例不能再命中。

## 5. 空间与命中

X横向、Y纵深、Z垂直。Facing±1只镜像X。**脚底原点**由Capsule中心减半高，所有HitOffset从脚底算；不能在胶囊中心再加角色腰部高度。

M1-017创建 `ComputeHitBox(FeetLocation,Facing,Definition)`返回center/extent。M1-018创建 `QueryTargets`，M1-019创建命中键和应用步骤。

`FCombatHit`包含Instigator弱引用及ID、AttackInstanceId、HitGroupId、目标、Damage、Impulse、WorldHitLocation、AttackId。去重键至少包含攻击者实例来源，防两个角色的本地InstanceId碰撞。

`UHealthComponent::ApplyDamage(float)`返回实际扣血；负数/非有限数拒绝，死亡一次。只有成功接受的命中才出HitConfirmed，声音/伤害数字不能根据Overlap直接触发。

## 6. 浮空与复位

M1-025落地前最多两次launcher，Z系数1.0、0.7，第三次不再产生上挑冲量。主设计旧的“最多2次且还有40%第三档”存在歧义；该任务必须同步删除第三档，不能私下实现另一版本。

M1-026：受击空中落地→Knockdown0.45s→Recovering0.25s→Free，恢复期拒绝伤害；Dead不恢复。普通玩家跳跃不倒地。M1-027统一Reset清理输入、事件、计时、速度、HP、朝向、浮空和命中集合。

## 7. M2 房间与敌人

- `UEnemyDefinition`：HP60、Speed220、AlignYTolerance35、AttackRangeX160、Telegraph0.35s、SpawnGrace0.5s。
- `AMeleeEnemy / AMeleeEnemyController`复用Health/Combat，不另实现直接扣血路径。
- `URoomSessionSubsystem : UWorldSubsystem`：RunId、SettlementId、Seed、WaveIndex、AliveIds、PendingSpawns、State。
- `FRoomResult`：RunId、SettlementId、RoomId、Seed、Cleared、KilledCount、ElapsedSeconds。
- 单局状态Idle/Running/Cleared/Failed/Exiting；最后一波pending=0且alive=0才Cleared。
- 事件重复、旧RunId回调和地图卸载统一幂等处理。

## 8. M3 Profile / 装备 / 存档

- `FItemDefinition`：DefinitionId、DisplayName、Slot、BaseStats、IconPath、Rarity。
- `FItemInstance`：InstanceId(FGuid)、DefinitionId、RollSeed、RolledStats、Level。实例ID存档重载不变。
- `FInventoryModel`：容量30；`TryAdd`/`Remove`返回明确枚举结果，重复ID拒绝。
- `FEquipmentModel`：Slot→InstanceId，仅引用背包实例。不得循环加减属性；`FStatCalculator`从基础与装备完整求和。
- `UProfileSubsystem : UGameInstanceSubsystem`：跨地图角色与背包，不持有World Actor。
- 等级1..10，下一级XP=100×当前Level；满级XP0；HP100+10×(L-1)，Attack2×(L-1)，Defense(L-1)。初值是设计选择，后续调参须记录。
- `FPendingReward`：SettlementId、XP50、预先生成的物品实例；满包保留。随机结果生成一次，重试不得重新Roll。
- `UProfileSaveGame` schema_version=1；A/B槽含Generation及完整性校验；写新槽并读回后才提交索引。
- `UProfileSaveService`：只操作指定slot前缀；自动化固定独立测试前缀，禁止覆盖用户档。
- 奖励领取必须与AppliedSettlementIds/背包/XP同快照持久化；保存成功才能显示领取成功。
