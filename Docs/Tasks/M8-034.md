# M8-034 · 攻击与技能失效回归修复（M8-031 状态机门控回退）

## 边界

- 前置任务：M8-031、M8-032（均为 DONE，但合入包存在玩家可见回归）。
- 必留报告：`Docs/Tasks/Reports/M8-034.md`。
- 用户证据：第十四版包试玩反馈"攻击完全失效了，技能也没有了，之前还是正常的"。

## 背景根因（用户包日志 + 回归测试双重实证）

用户包日志（`Artifacts/Package/Windows/UEMMO/Saved/Logs/UEMMO.log`，2026-11-10 会话）唯一战斗警告：

```
the consumed Light chain input could not start 'light_02'; the component stays Free.
```

**核心机制（M8-034 新增回归测试复现实锤）**：M8-031 把相位推导注入放在 TickCombat 的
Attacking 路径末尾，而 `ActionState != Attacking` 分支无条件提前 return——**攻击一旦结束
（FinishCurrentAttack/跳取消/受击中断都归非 Attacking 态），推导永远不再执行，相位冻结在
最后一次攻击相位**。冻结在 CancelWindow 时 CanStartAttack 侥幸为真（短测试侥幸通过）；冻结
在 Active/Recovery 时 `CanStartAttack` 永久为假 → 之后所有攻击/技能门控静默拒绝（直启拒绝
无日志，用户视角即"攻击完全失效、技能消失"）。新回归测试 `TeardownNeverLocksThePhaseMachine`
在修复前精确复现：ResetCombat 后相位仍非 Idle、CanStartAttack=false。

次级缺陷（同轮修复）：①teardown（Frame<0）走表撞 Active→Idle 非法（销毁是事实不是转换，
改为 ForcePhase 绕表归位）；②链式判定用实时帧而相位滞后一帧，窗口首帧按键被消费后遭拒
（日志中 light_02 警告即此）；③直启拒绝无 Warning 日志且现有验收测试杀怪走 `ApplyDamage`
直调未走玩家真实攻击链，套件全绿仍漏网。

技能"消失"同源：M5 技能路径（`TryActivateSkill`）为下一次攻击上增益（`NextInstanceDamageScale`），
攻击起不来则增益永不到账，技能从玩家视角失效。

## 实现要求

1. **回退门控**：`UCombatComponent::TryStartAttack` 与 `USkillAbilityComponent::TryCast` 的 `CanStartAttack()` 门控注释停用（保留代码与说明）；Free 状态检查保持唯一门禁（M8-031 之前的行为）。状态机保留为纯观察层（`OnPhaseChanged` 当前无生产监听者，已核实）。
2. **推导全覆盖**：相位注入抽为 `UCombatComponent::UpdatePhaseMachine()`，TickCombat 顶部（一切状态分支早退之前）+ Attacking 路径末尾各调一次——非 Attacking 态（Free/HitStun/Knockdown/Recovering）每 tick 也推进相位，消除冻结族。
3. **状态机加固**：`UpdateFromFacts` 的 teardown 分支（Frame<0）改为 `ForcePhase(Idle)` 强制归位（绕表、广播、清 `bCancelWindowOpen`），Windup 分支清残留取消旗标——未来重启用门控时不再有卡死族。
4. **回归测试**（`Tests/AttackLifecycleTests.cpp` 新增两条，`Scripts/TestCombatAttackLifecycle.ps1` 运行）：
   - `M8_031.TeardownNeverLocksThePhaseMachine`：mid-Active teardown 后相位必须回 Idle 且 CanStartAttack 恢复、新攻击可起。
   - `M8_031.ChainWindowStartAcceptsTheFollowUp`：真实缓冲输入路径（QueueInput+tick），取消窗口首帧链式必须吃掉按键并起 light_02（Started==2）。
5. 验证：完整构建 + 两条新测试绿 + 全量回归绿；重打包到唯一输出目录供用户复测。
