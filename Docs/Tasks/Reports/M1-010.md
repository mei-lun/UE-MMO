## 目的

按接口约定第 3 节建立只读运行时攻击目录 `UAttackCatalog`：启动/初始化时显式引用加载 M1-009 生成的 4 份攻击 DataAsset（DA_light_01 / DA_light_02 / DA_launcher / DA_aerial_01），提供 `Find(FName) const` 只读查找（缺失 ID 返回 nullptr 并记录一次诊断、不静默回退第一条），重复 ID 或加载失败时 fail-fast 初始化失败（错误信息指明问题 ID/路径，不半初始化），并提供四条定义的完整序列访问；运行时不读取 `Data/combat-attacks.json`，Cook 依赖以显式规则追踪（独立包最终由 M1-039 验证）。

## 实际修改

1. `Source/UEMMO/Combat/AttackCatalog.h`（新建；纯 ASCII；相对 include 同目录约定，头内仅前向声明 UAttackDefinition）
   - `UAttackCatalog : UObject`，`UCLASS(BlueprintType, Config = Game)`。
   - **加载方式选择（方案②：Config/DefaultGame.ini 显式引用）**：`UPROPERTY(config)` `TArray<FSoftObjectPath> AttackAssetPaths` 由 `[/Script/UEMMO.AttackCatalog]` 段注入 CDO，`InitializeFromConfig()` 读取默认对象后调 `InitializeFromPaths()` 逐条 `LoadObject<UAttackDefinition>`。不选 AssetManager 扫描的理由：显式路径清单可整表注入单元测试、范围外资产永远不会被静默拾取（与"仅包含 /Game/UEMMO/Combat"的语义一致），且不引入 PrimaryAssetType 注册这一额外运行时机制。
   - `InitializeFromPaths(const TArray<FString>&, FText&)`：路径必须以 `/Game/UEMMO/Combat/` 开头（越界直接失败，先于任何加载）；任一资产加载失败即失败；成功后调 `BuildFromDefinitions`。
   - `BuildFromDefinitions(const TArray<UAttackDefinition*>&, FText&)`：**可注入资产的纯构建函数**（满足卡面单元级重复 ID 测试要求）。局部数组/TMap 构建成功才整体提交——null 条目、无 AttackId（NAME_None）条目、重复 ID（错误文本含该 ID）三种情况返回 false 且目录保持原状（不半初始化）。
   - `Find(FName AttackId) const`：`TMap<FName,int32>` 索引返回 `const UAttackDefinition*`；未知 ID 返回 nullptr，**绝不回退到其他条目**，并以 `mutable TSet<FName>` 保证每次构建周期每个未知 ID 至多一条 UE_LOG 警告（文件内静态 Log category `LogUEMMOAttackCatalog`，Find 为 const 不受影响）。
   - `GetEntries() const`：配置顺序的四条定义完整序列访问（`UPROPERTY(Transient) TArray<TObjectPtr<UAttackDefinition>>` 持引用防 GC）。
2. `Source/UEMMO/Combat/AttackCatalog.cpp`（新建；实现上述语义；唯一 Include 依赖 `AttackDefinition.h` 与 `UObject/UObjectGlobals.h`）
3. `Config/DefaultGame.ini`（最小追加，两处）
   - 新段 `[/Script/UEMMO.AttackCatalog]`：`+AttackAssetPaths=` 列出 4 条完整对象路径 `/Game/UEMMO/Combat/Definitions/DA_light_01.DA_light_01` 等（`Package.Asset` 形式，与 M1-009 资产实际命名一致）。
   - 既有 `[/Script/UnrealEd.ProjectPackagingSettings]` 段追加 **`+DirectoriesToAlwaysCook=(Path="/Game/UEMMO/Combat")`**。
   - **Cook 依赖追踪说明**：目录内容不依赖运行时硬引用链（LoadObject 在运行时建立引用，编辑器 Cook 看不到），因此以打包配置为显式 Cook 规则——UE 5.8 引擎源码 `CookCommandlet.cpp`（第 487 行起）确认 `ProjectPackagingSettings.DirectoriesToAlwaysCook` 的每个目录作为命令行目录条目进入 Cook 源，目录按 Cook 收集规则递归包含子目录（Definitions 下的 4 份资产）。该规则把 Cook 范围钉在与目录内容校验相同的 `/Game/UEMMO/Combat` 前缀上（代码内 `AllowedContentRoot` 与 ini 规则同前缀）。**独立包可加载性属配置说明级证据，端到端验证由 M1-039 执行。**
4. `Source/UEMMO/Tests/AttackCatalogTests.cpp`（新建；纯 ASCII；相对 include `../Combat/`；前缀 `UEMMO.Tasks.M1_010.*`，EditorContext | ClientContext | EngineFilter）
   - `CatalogFindsAllFourKnownIds`：InitializeFromConfig 成功后 Find 四条 ID 全部非空且返回定义的 AttackId 与查找 ID 相同。
   - `CatalogSequenceMatchesContractValues`：GetEntries 恰 4 条、顺序 light_01/light_02/launcher/aerial_01；逐条直接断言 DurationFrames 与窗口字面量：26/[7,11)/[12,24)、32/[9,14)/[16,29)、40/[12,17)/[18,32)、28/[6,10)/[12,23)（契约值以常量镜像，运行时不读 JSON）。
   - `CatalogUnknownIdReturnsNull`：未知 ID 返回 nullptr、重复查找仍 nullptr、且 `Find(unknown) != Find(light_01)`（显式断言不回退第一条）。
   - `BuildRejectsDuplicateIds`：注入 `{light_dup, launcher, light_dup}` → false 且错误含 `light_dup`；失败后 GetEntries=0、Find(light_dup)=nullptr；正向对照：注入两个不同 ID → true、2 条、按 ID 可查。
   - `InitializeFromPathsFailsFast`：越界路径 `/Game/Other/...` 拒绝且错误含 `/Game/UEMMO/Combat`；根内不存在资产 `DA_missing` 失败且错误含 `DA_missing`；混合列表（1 正确 + 1 缺失）整体失败且目录为空。

## 独立验收对照

- **Find(light_01) 返回匹配 ID，Find(unknown)=nullptr**：绿灯 `CatalogFindsAllFourKnownIds` 断言四条 ID 的 Find 结果非空且 AttackId 相等；`CatalogUnknownIdReturnsNull` 断言未知 ID 为 nullptr、重复查找仍 nullptr、且不等于 Find(light_01)（不静默回退第一条）。
- **重复 ID 初始化失败，错误指明 ID**：`BuildRejectsDuplicateIds` 以注入数组验证构建返回 false、错误文本含 `light_dup`、失败后目录为空且无可查条目（fail-fast 不半初始化）；加载任一资产失败同样初始化失败并指明路径（`InitializeFromPathsFailsFast`：越界路径、根内缺失资产、混合列表三例，均保持目录为空）。
- **Cook 依赖可由配置说明追踪**：`DefaultGame.ini` 的 `DirectoriesToAlwaysCook=/Game/UEMMO/Combat` 显式规则（经引擎源码确认进入 Cook 目录源且递归），与代码级 `/Game/UEMMO/Combat/` 前缀校验同前缀互相锚定；独立包最终验证归 M1-039。
- **运行时不读 Data/combat-attacks.json**：目录与测试代码无任何文件/JSON 读取（仅 `LoadObject` 加载 `/Game` 资产）；测试期望值为镜像契约的字面量常量，与 M1-009 资产逐字段断言互补。

## 已知限制

1. **目录初始化尚未接入游戏启动流程**：卡面文件范围（AttackCatalog.h/.cpp、DefaultGame.ini、测试）没有 GameMode/组件挂接点。`InitializeFromConfig()` 即为启动入口且已在全新 `-game` 进程验证；下游 M1-011 创建 CombatComponent 时接线（其卡依赖本卡）。
2. **Cook 依赖为配置说明级**：`DirectoriesToAlwaysCook` 已配置并核对引擎 Cook 路径，但本卡未做独立打包加载验证（超出卡面范围，属 M1-039）。
3. **路径形式要求**：`AttackAssetPaths` 需 `Package.Asset` 完整对象路径形式；`InitializeFromPaths` 不做短形式归一化（错误时 fail-fast 并点名路径，宁可明确失败）。
4. 未知 ID 诊断按"每次成功重建清零"去重：同一 ID 在一次目录生命周期内只记一条警告；如需按调用点定位需查日志上下文。
