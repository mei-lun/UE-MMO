## 目的

针对用户第四轮试玩反馈（X/空中攻击与 C 跳可用，但 Z 上挑"没有用"、攻击怪物无反馈、怪物不动、怪物无血条），在包内日志证实机制层全部正常（RunStarted/两波生成/18 次命中/3 击杀/波次推进）的前提下，离屏复现真实游戏会话，逐帧取证诊断四个呈现缺口，做最小增量修复并复验。

## 诊断过程与证据

### 复现方式

编辑器离屏进程走真实生产链（同 M3-024 staged 截图先例）：

```
UnrealEditor-Cmd.exe UEMMO.uproject -RenderOffscreen -unattended -nosplash -nosound
  -NoVSync -ResX=1280 -ResY=720
  -ExecCmds="Automation RunTests UEMMO.Tasks.M3-027.RoomCombatVisualDiagnostics"
```

### 四条反馈的取证结论

1. **"怪物不动"——机制层在动，呈现层在滑步**：遥测显示敌人以 220 cm/s 追近玩家（`max_enemy_planar_speed_cm_s=220`），但单一 idle 循环动画在移动中滑步，视觉上读作"没动"。截图 `m3-027-analysis-pre-fix-jog-zoom.png`（放大）确认移动中姿态是 idle。修复见下。
2. **"攻击没有反馈"——伤害数字/血条被锁在 F1 调试层，受击无身体反应**：M3-026 血条只在首次命中后出现、M1-035 伤害数字/连击只画在 F1 调试面板后面，默认视图下两者都不在；且敌人无受击动画资产，命中后身体零反馈。
3. **"Z 上挑没有用"——真实循环存在吞键差异，浮空本身正常**：Launcher 按下需要战斗 Free 且输入缓冲为空（缓冲中的 Light 会让 Z 静默过期——正是用户手感的机制解释）；命中后敌人 Z 90→340（上升 250 cm，峰值向上速度 ~700 cm/s），落地进入 Knockdown。修复前截图 `m3-027-analysis-pre-fix-flash-zoom.png` 显示浮空帧只有运动模糊"幽灵"条——浮空可见但无任何命中着色。
4. **关键新发现（本会话渲染探针）——BasicShapeMaterial 叠加层在骨骼网格上完全不渲染**：前一会话的受击闪红用 `/Engine/BasicShapes/BasicShapeMaterial` 的红色 MID 做 `SetOverlayMaterial`，参数级测试通过但画面无色。本会话在套件中加材质探针（`m3-027-probe-*.png`）：以玩家 mesh 为载体，(a) BasicShape 红 MID 叠加 → 与未修改画面逐像素一致（完全不渲染）；(b) WorldGridMaterial 叠加 → 明显渲染（躯干暗灰）；(c) 网格自身 slot-0 材质为基、把全部继承向量参数写红 → **整个身体变红**（腿部像素 224,39,40）。结论：BasicShapeMaterial 仅 static-mesh usage，作骨骼网格叠加时静默丢弃；且 mannequin 材质没有"Tint"体色参数（运行时枚举仅 Paint Tint / LogoTint / Blend Offset——前一会话按"Tint"参数写也必然无效）。

## 实际修改

- `Source/UEMMO/Enemy/MeleeEnemy.cpp/.h`
  - 受击闪红改为**网格自身 slot-0 材质的 MID 作为叠加层**，BeginPlay 时把全部继承向量参数写成闪红（探针证实可渲染）；`PeekHitFlashTint` 改为回读真实 MID 参数（锚定首个向量参数名）。
  - 新增单节点移动动画切换 `RefreshLocomotionAnimation`：水平速度 > 20 cm/s 切 `MF_Unarmed_Jog_Fwd` 跑步剪辑，停下回 idle——消除"滑步=没动"。
  - 新增 `bLaunchedAirborne` 标记（M1-022 TrainingEnemy 先例）：被上挑的落地触发 M1-026 Knockdown→Recovering→Free 流程，上挑弧线以"倒地→爬起"收尾。
  - BeginPlay 注册 `Hud->TrackEnemyBarActor(this)`：血条从出生即显示（M3-026 的命中驱动 upsert 保留为数据刷新）。
