## 目的

提供纯几何函数 `ComputeHitBox(FeetLocation, Facing, Definition)`：以**脚底原点**（Capsule 中心减半高，接口约定第 5 节）为基准，把攻击定义的 `HitOffsetFromFeet` 平移成世界坐标命中盒中心——**仅 X 分量随 Facing 镜像**（Y/Z 两方向一致），`HitHalfExtent` 原样作为半尺寸。查询轴固定世界 X/Y/Z，不做人物模型 -90° 校准补偿（世界坐标即最终框）。本卡不读 World、不做碰撞/Overlap 查询（目标查询归 M1-018），并产出调试数据结构 `FCombatHitBox`（Center + Extent）。

## 实际修改

全部 C++ 纯 ASCII；未改 TASKS.md/HANDOFF.md/Docs/Tasks/Handoffs/Scripts/**/AttackDefinition.h/其他任务文件（协调者禁止清单一字未动）；全部为卡面文件范围内的新建文件。

1. `Source/UEMMO/Combat/CombatGeometry.h`（新建）
   - `struct FCombatHitBox { FVector Center = FVector::ZeroVector; FVector Extent = FVector::ZeroVector; }`：调试数据结构，世界轴（X 横向、Y 纵深、Z 高度）下的 AABB 中心与半尺寸；不携带任何旋转/朝向信息。注释明确"世界查询归 M1-018，本结构只承载几何"。
   - `FCombatHitBox ComputeHitBox(const FVector& FeetLocation, int32 Facing, const UAttackDefinition& Definition);` 自由函数；头文件只前置声明 `class UAttackDefinition`，不引 AttackDefinition.h（依赖仅 Core + 该类型）。
2. `Source/UEMMO/Combat/CombatGeometry.cpp`（新建）
   - `Center = FeetLocation + (Offset.X * Sign, Offset.Y, Offset.Z)`：偏移按脚底原点直接相加，**不在胶囊中心再加腰部高度**（高度项即 `Offset.Z` 本身）。
   - Facing 规范化：`Sign = Facing < 0 ? -1 : 1`——接口约定只有 ±1；本卡选择**符号化**：>0 → +1、<0 → -1、**0 → +1**（零朝向按默认右向框处理，避免退化）。该行为已用测试固化（见下）。
   - `Extent = Definition.HitHalfExtent` 原样拷贝，不随 Facing 改变。
   - 纯函数：无 World/无碰撞查询、无状态；`HitOffsetFromFeet`/`HitHalfExtent` 全部从定义实时读取，无硬编码默认值。
3. `Source/UEMMO/Tests/CombatGeometryTests.cpp`（新建，5 条 `UEMMO.Tasks.M1_017.*`；无 World：`NewObject<UAttackDefinition>` 构造定义并只设 Hit 几何字段，其余字段保持类默认且 `ComputeHitBox` 不读取）
   - 容差常量 `M1_017_Tolerance = 0.01`（匿名命名空间、唯一命名防 unity 复用冲突）；浮点断言一律 `FMath::IsNearlyEqual(..., M1_017_Tolerance)`，`TestTrue` 首参为描述。
   - `RightFacingCenterAndExtent`：Feet=(100,20,0)、Facing=+1、默认偏移 (95,0,90)/半尺寸 (85,50,70) → Center=(195,20,90)、Extent=(85,50,70) 逐分量断言。
   - `LeftFacingMirrorsXOnly`：同 Feet、Facing=-1 → Center.X=5（100−95），Center.Y/Z 与 +1 结果完全一致；Extent 与 +1 一致（半尺寸不镜像）。
   - `CustomOffsetMirrorsXOnly`：自定义偏移 (50,10,120)/半尺寸 (30,40,60)：Facing=+1 → Center=(150,30,120)；Facing=-1 → Center=(50,30,120)，Y/Z 不变；自定义半尺寸原样透传。
   - `FeetOriginFollowsJump`：Feet=(0,0,131) → Center.Z=221（131+90，脚底原点同步抬高），并显式断言 Center.Z ≠ 131；X=95、Y=0。
   - `FacingSignNormalization`：Facing=0 → 右向 X=195；Facing=2 → 右向 X=195；Facing=-3 → 左向 X=5；三者 Extent 相同。

## 已知限制

1. **Facing 规范化为符号而非报错**：接口约定第 5 节只有 ±1；本卡选择 `Facing<0 → -1，否则（含 0）→ +1`，零朝向按默认右向处理。若后续任务（如 M1-018 目标查询）需要"拒绝非法 Facing"的严格版本，应在此处扩展而不是私下另写一套镜像规则。
2. **纯几何、不验证定义合法性**：`ComputeHitBox` 不检查 `HitHalfExtent` 是否有限/为正（该职责在 `ValidateAttackDefinition`），不裁剪 FeetLocation 的非有限分量；非法输入将原样传播到结果。世界查询（Overlap）与合法值兜底归 M1-018。
3. **调用方负责提供脚底原点**：函数不做"Capsule 中心减半高"的换算（接口约定把该换算归入角色侧取 FeetLocation 的职责）；若调用方误传胶囊中心，会复现"重复加 90cm"的旧问题——本卡测试只用明确 FeetLocation 固化语义。
4. 无真实键盘/手柄试玩；本卡全部为纯函数自动化验证（H01 人工验收不在 AI 职责内）。Artifacts 证据目录不入库（同 M1-014 惯例）。
