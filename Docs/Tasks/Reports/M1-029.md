## 目的

按任务卡实现平面移动的分方向速度：X（横向）420 cm/s、Y（纵深）280 cm/s；核心为纯函数——先把二维输入向量归一化，再分别乘两轴速度，使对角输入 (1,1) 输出 420/√2 与 280/√2 而非两轴全速；同轴相反输入抵消为 0；输入夹取到 [-1,1]、非有限输入按 0 处理。同时把 M0"两个独立回调各自 AddMovementInput"的移动方式改为汇总两轴后集中计算，纵深输入不改 Facing，并为 M1-013 攻击门控留出单点接入结构。

## 实际修改

- `Source/UEMMO/Character/PlanarMovement.h`（新建，目录 Character/ 新建，仅依赖 CoreMinimal）：
  - 常量 `PlanarSpeedX = 420`、`PlanarSpeedY = 280`（cm/s）。
  - `struct FPlanarAxisState`：两轴原始输入状态（`AxisX/AxisY`），`AddAxisX/AddAxisY`（累加原始贡献，供测试与潜在逐键来源使用，+1 与 -1 相加抵消）、`SetAxisX/SetAxisY`（直接赋净值，供 Enhanced Input 已求和的净轴值使用）、静态 `SanitizeAxis`（非有限→0，其余夹取 [-1,1]）。
  - `ComputePlanarVelocity(AxisX, AxisY, SpeedX, SpeedY)` 纯函数：先 Sanitize，再归一化（`FMath::InvSqrt`），零向量输入直接返回零；输出 Z 恒为 0。另有接受 `FPlanarAxisState` 的重载。
- `Source/UEMMO/Tests/PlanarMovementTests.cpp`（新建）：5 个纯逻辑自动化测试（无 World），前缀 `UEMMO.Tasks.M1_029.*`：PureX、PureY、DiagonalNormalized、ZeroAndCancellation、ClampAndNonFinite。
- `Source/UEMMO/PrototypeCharacter.cpp`（修改，接线）：
  - 文件内新增匿名命名空间函数 `ApplyPlanarMovement(Character, Axes)`——**全部移动输入的唯一经过点**（M1-013 的 `CanAcceptMovement` 门控未来插在这一处即可，本次不实现其逻辑）。每帧：`ComputePlanarVelocity` 得到平面速度（cm/s），若速度非零则以 `AddMovementInput(归一化方向, 速度/MaxWalkScale)` 交给 `CharacterMovement`。经核对 UE 5.8 引擎源码（`CharacterMovementComponent.cpp` 的 `ComputeAnalogInputModifier`/`CalcVelocity`：`MaxInputSpeed = MaxSpeed * AnalogInputModifier`，输入模长≤1 时按比例限制行走速度），该接法使 CharacterMovement 沿输入方向把速度限制到目标平面速度（纯 X 420、纯 Y 280、对角 ≈356.9），保持正常加速、刹车与碰撞，不瞬移。`MaxWalkSpeed` 构造值 420 未改。
  - `MoveHorizontal/MoveDepth` 回调只记录净轴值（`PlanarAxes.SetAxisX/SetAxisY`），不再各自 AddMovementInput；Enhanced Input 对同一 Action 的多个按键（D 与取反 A、S 与取反 W）已按 `Cumulative` 求和，同轴相反按键在动作层抵消后进入状态。两轴各补绑 `ETriggerEvent::Completed`（松开最后一键时事件值为 0，已对照引擎 `EnhancedPlayerInput.cpp` 的 `ActionData.Value.Reset()` 逻辑确认），保证松键后轴状态归零、角色正常刹车停下。
  - Facing 逻辑移入 `ApplyPlanarMovement`：仅当 `AxisX > 0` 设 yaw 0、`AxisX < 0` 设 yaw 180，`AxisX == 0`（含纯 W/S 纵深）不动朝向——沿用 M0 的翻转角度与 `SetActorRotation` 行为。跳跃（StartJump/EndJump）与复位（ResetPosition）未动。
- **PrototypeCharacter.h 有最小改动**（超出门卡三个文件，理由如下）：需要在两个独立输入回调之间跨帧持久化两轴输入状态，最合理归属是角色实例成员；最小改动为头文件加一行 `#include "Character/PlanarMovement.h"` 与一个非 UPROPERTY 成员 `UE::UEMMO::Tasks::M1_029::FPlanarAxisState PlanarAxes;`（类型来自 PlanarMovement.h 的小 struct）。备选文件级静态变量会破坏多实例正确性，故选择该最小头文件改动。

## 已知限制

- 自动化与运动回归均不模拟真实键盘事件（smoke 由脚本直接调 `AddMovementInput`）：分轴速度/斜向归一化在真机键盘上的最终手感属 H01 人工验收，本报告不代签。
- 接线依赖引擎既有"输入模长缩放限速"机制（`AnalogInputModifier`），对角加速度与速度同比例缩放（420×356.9/420 档），加速到目标速度的时间各方向接近，属正常模拟输入行为；如后续任务要求"任意方向固定加速度"，需改用 `ScaleInputAcceleration` 覆写。
- 按键松开依赖 `ETriggerEvent::Completed` 归零轴状态；若窗口失焦导致按键事件丢失（Enhanced Input 层固有行为），轴状态可能残留——与 M0 行为一致，未在本卡扩大处理。
- M1-013 尚未实现，本卡只留出门控单点 `ApplyPlanarMovement`，未写任何门控逻辑。
- 本卡不涉及画面变更，未跑 `Test -Render`。
