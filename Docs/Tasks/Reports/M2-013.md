## 步骤与结果

### 目的

交付单局终态后的结果查询与一次性结算标识：每个终态 run 的 `FRoomResult` 快照按 RunId 归档，`GetRunResult` 以**不可变值副本**交出（UI 离开 World 后引用不失效）；`GetSettlementId(RunId)` 重复请求返回同一结算号（绝不重新生成）；`IsRewardEligible` 只对 Cleared 结果放行（Failed 结果永不进奖励入口）；M3 消耗接口以注释声明（按 SettlementId 领取），本卡不实现存档/奖励。

### 设计决定（如实说明）

- **归档在 ResetToIdle 后保留**：`FinishedRunResults` 不属于被 reset 清空的"当前 run 簿记"，而是终局结果档案——重试循环把状态洗回 Idle 后，失败局结果仍可按 RunId 查询（测试 4 显式断言），这也是 M3"按 SettlementId 领取"的前提。只有 Deinitialize（世界销毁）丢弃归档。
- **GetSettlementId(RunId) 是重载而非改动**：M2-006 的无参 `GetSettlementId()`（当前/最近 run）原样保留。
- **每 World 归档**：查询 API 挂在 per-World Subsystem 上，跨 World 不共享归档（结算号唯一性本身是进程级的，M2-006 已锁定）。

### 已知限制

- 不实现存档/奖励：M3 的 FPendingReward、AppliedSettlementIds、存档快照均未实现（卡面明确不提前做）；IsRewardEligible 只是入口守卫，不是发放。
- 归档按 World 生命周期无上限（原型规模，run 数量少；M3 接入存档后由其负责长期保存）。
- 无跨 World 结果查询；世界销毁后其归档随之消失（值副本正是为此设计——UI 持有副本不悬垂）。
