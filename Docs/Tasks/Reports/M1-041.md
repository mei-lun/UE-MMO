## 目的

修复用户试玩发现的集成缺口（M1-H01 阻断项）：`APrototypeCharacter::Tick` 只调 `TickCombat`，从未调 `SetInputClockSeconds`，`bInputClockInjected` 恒 false → M1-021 Free 态起手与 M1-014/M1-021 取消窗消费被门控关闭，X/Z 按键意图进缓存后永不消费；朝向来源同样未接线（组件存储值 0）。本卡完成游戏侧每帧注入与朝向来源，并新增真实角色在环自动化验证防回退。

## 实际修改

### 接线顺序（`PrototypeCharacter.cpp` Tick）

- 每帧顺序固定为：`SetInputClockSeconds(World->GetTimeSeconds())` → `TickCombat(DeltaSeconds)`，满足接口约定第 2 节"每帧恰一次、先于 TickCombat"的注入契约。
- 时钟源用 World `GetTimeSeconds()`（double），与 `SubmitCombatInput` 记录 PressedAt 的时钟同源；暂停与 HitStop 不推进该时钟（引擎语义）。
- M1-033 冻结期无需特殊处理：组件 `SetInputClockSeconds`（CombatComponent.cpp 703-750 行）已实现冻结钉死——冻结期注入仅测量真实推进并消耗 stop 余量，余量未尽时丢弃注入值钉住时钟，结束注入原样生效。游戏侧逐帧注入正好是该实现的驱动源。
- World 为空的调用方（早期测试）跳过注入，保持接线前语义（缓存消费仍被门控）。

### 朝向来源（BeginPlay，与 AirStateProvider 同位注入）

- `Combat->SetFacingProvider(...)`（TFunction<int32()>），返回当前朝向 ±1：由 `GetActorRotation().Yaw` 推导，yaw ∈ (-90°, 90°) → +1（右），否则 → -1（左）。与 M1-029 平面翻转逻辑一致：翻转代码只写 yaw 0/180 且攻击期锁 facing，因此 yaw 半平面就是移动代码最后锁定的朝向，±1 与 `TryStartAttack` 镜像约定一致。
- 取消窗连锁（TryChainFromBuffer）沿用运行实例的既有 Facing——攻击期朝向锁定，两条来源必然一致。

### 组件最小新增（`CombatComponent.h/.cpp`）

- 新增 `FCombatFacingProvider` typedef、`SetFacingProvider`（空函数=解绑）与私有成员 `FacingProvider`。
- `TryStartFromBuffer` 起手处改为 `const int32 StartFacing = FacingProvider ? FacingProvider() : Facing;`：未注入保持存储值 0（裸组件行为逐字不变）；既有组件级测试（M1-021/023/024 显式注入时钟、不绑定 provider）不受影响。
- 组件自带 tick 保持禁用（`PrimaryComponentTick.bCanEverTick = false`），未扩大改动面。

### 在环测试方案（`Tests/GameCombatWiringTests.cpp`，新建，2 条）

- **选型**：临时 World 手动全量真实 Tick（方案 A），未用 -game+exec 方案。载体是引擎公开先例 `FTestWorldWrapper`（Engine/Public/Tests/AutomationCommon.h，引擎网络自动化同款）：`CreateTestWorld(EWorldType::Game)` → `BeginPlayInTestWorld()`（SetGameMode + InitializeActorsForPlay + BeginPlay 全量初始化）→ 逐帧 `TickTestWorld(1/60)`（内部 `UWorld::Tick(LEVELTICK_All)`）：真实角色 Tick、真实 CharacterMovement 积分、真实物理、世界时钟逐帧推进（TimeSeconds，未暂停），全部在标准 `-game` 自动化进程内运行（TestAutomation.ps1）。
- **场景**：已 Begin 的世界中按正常会话路径 Spawn 地板（BoxComponent + BlockAll 档，显式 SetWorldLocation——无根组件 actor 的 SetRootComponent 不会回灌出生变换，M1-022 同款处理）+ 真实 `APrototypeCharacter` + 真实 `ATrainingEnemy`（敌人脚点 +95/-95，三种现行攻击盒 offset/extent 相同可全程覆盖）；地板阻挡探测（真实下落物理同款胶囊 sweep）作为前置断言；`EnsureCollisionTreeIsBuilt()` 补上手造 World 缺失的地图加载步骤（不补则本世界所有场景查询必 miss）；玩家 `bRunPhysicsWithNoController` + M1-022/M1-027 激活两步使无控制器物理照常落地。
- **按键**：只走生产意图入口 `SubmitCombatInput(ECombatInput::Light/Launcher)`（真实 X/Z 绑定的最终目标），按世界时钟排程（settle 后 +0.10/+0.45/+0.85 s），PressedAt 由角色自身从世界时钟读取。
- **关键红线**：测试**不调用** `SetInputClockSeconds`/`SetFacingProvider`/`TryStartAttack` 于被测的玩家路径——玩家组件的输入时钟只来自其自身 Tick（世界 Tick 驱动），断言 `GetInputClockSeconds() > 0` 即接线 pivot。
- **断言**（XXZ 组合测试）：3 次 Started 顺序 light_01→light_02→launcher、每次起手 Facing=+1、3 次命中 HP 100→90→76→58（容差 0.01）、launcher 后目标浮空（Z 速度>0）、3 次 Finished（两次连锁退役+launcher 自然结束）、组件回 Free。朝向测试：玩家 yaw 180 + 敌人站位镜像，单按 X，断言起手 Facing=-1 且命中左侧敌人 HP→90。
- **已知缺口代偿（仅敌侧）**：见"已知限制"第 1 条——测试对**敌人**战斗组件逐帧做了 `SetInputClockSeconds + TickCombat` 代偿（`TickEnemyCombatStandIn`），玩家被测路径零测试侧注入。

## 已知限制

1. **敌侧战斗组件无驱动（既有缺口，非本卡引入，文件不在本卡范围）**：游戏代码中只有 `APrototypeCharacter` 驱动自己的战斗组件；`ATrainingEnemy` 的战斗组件无任何逐帧驱动（组件自带 tick 亦禁用），其 M1-033 目标侧 HitStop 一旦开启就永不结束、M1-020 眩晕/M1-026 倒地恢复永不推进。后果：真实游戏中敌人第一次被命中后移动永久冻结（可继续被命中、HP 继续下降，但 launcher 不会令其浮空），F2 重置（ResetCombat→EndHitStop）可解冻。本卡测试以 `TickEnemyCombatStandIn` 显式代偿该缺口以使浮空断言可达；玩家被测路径零测试侧注入。建议开后续任务（敌侧战斗驱动：TrainingEnemy 逐帧 SetInputClockSeconds + TickCombat）后再交用户复测浮空手感。
2. 测试以 `SubmitCombatInput` 驱动按键（真实输入绑定的最终目标），非物理键盘事件，亦不等价于手动试玩；用户复测（M1-H01）仍以真机试玩为准。
3. 在环测试使用 1/60 s 固定帧步，真实帧率抖动/掉帧路径未覆盖；按键排程时间点为固定值，非随机。
4. 朝向来源按 M1-029 约定只认 yaw 0/180 两态（半平面推导对中间角度返回最近侧）；当前游戏不会产生中间角度。
5. Package 冒烟（打包侧复验）按卡面属可选，由协调者负责重建包后验证。
