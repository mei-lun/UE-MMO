## 已知限制

- **TryAdd 检查顺序为设计选择**：InvalidInstance → Duplicate → InventoryFull。因此满包时重复添加同一 ID 返回 `Duplicate` 而非 `InventoryFull`（身份问题优先于容量问题：非法或已持有的实例无论满不满都不可能入库）。若下游（如 M3-012 满包奖励）需要相反优先级，属显式语义调整，需改本卡测试。
- `GetByIndex` 越界返回 `nullptr`（查询永不崩溃，调用方判空），不使用 check 断言；`GetAll()` 返回内部数组 const 引用，外部不可变更。
- 仅校验 InstanceId 的 FGuid 有效性；DefinitionId/数值合法性仍是 `ValidateItemDefinition`（M3-001）的职责，背包不做重复把关。
- Remove 为线性查找 + `RemoveAt`（保序）；30 容量下性能足够，若后续需要 O(1) 可加 TMap 索引（属后续任务，不改变本卡行为面）。
- 纯逻辑模型，无序列化、无 UI、无 Profile 接线：存档 schema 属 M3-013，界面属 M3-011，Profile 装配属 M3-003。
- 红灯运行退出码经管道转发未单独捕获（见红→绿证据第 1 条）；绿跑与全量回归的 exit=0 均为直接捕获。
- 本卡无视觉变更，未跑 `Test.ps1 -Render`；测试为 `-nullrhi -game` 纯逻辑自动化，不涉及真实键鼠事件。
