## 目的

针对用户试玩反馈"人物角色移动没有动画"（移动时滑步/站桩），诊断 M1-031 建的 ABP_Prototype（BlendSpace + BlendListByInt + Slot）与 UPrototypeAnimInstance 链路的断点，做最小修复，并以站桩 vs 移动截图 + 变量断言复验。

## 诊断过程与证据（链路逐段取证）

复现方式沿 M3-024/M3-027 先例：编辑器离屏 `-RenderOffscreen -game` 走真实生产链（L_CombatRoom01 默认图），由 `AddMovementInput` 生产入口驱动玩家移动；另用 M1-041/M3-024 的 FTestWorldWrapper 临时世界在环断言。新建 `Tests/AnimationStateTests.cpp`（4 测试，前缀 `UEMMO.Tasks.M3_028.*`）就是诊断仪器本身。

### 逐段排除（先证明"没断的"）

1. **AnimBP 已应用**：`Mesh->GetAnimInstance()` 是 `UPrototypeAnimInstance`（在环断言绿）。
2. **NativeUpdateAnimation 正常**：420 cm/s 匀速移动中导出 `Speed=420.0`，与真实平面速度 173/173 帧零偏差；`Direction=0/180` 正确；`PoseIndex=0`；无 Montage 侵入。
3. **Speed→BlendSpace 绑定正常**：资产侧 `X` 引脚确有 `K2Node_VariableGet(Speed)` 链接（静态普查断言绿）；运行时节点 `GetPosition()` 返回 (420,0)/(420,180)，`GetFilteredPosition()` 同步到达 (420,180)，`PlayRate=1.0`、`bLoop=true`、`IsEvaluator=false`、BlendListByInt 活动子项=0（引擎调试数据实测——注意：序列化的节点 X/Y UPROPERTY 在引脚已连接时运行时恒为默认值 0，是假线索，权威读数走节点虚函数）。
4. **Slot 旁路排除**：Slot Weight 0%（无 Montage）、Source Weight 100%（引擎 live-tree 实测），M3-024 接线无恙。

### 断点（实锤）

引擎自身调试数据（GatherDebugData，即 Anim 调试面板同源）显示：移动全程 **`BlendSpacePlayer ('BS_Prototype_Locomotion' Play Time: 0.000)`——播放时间恒 0**。结合渲染截图（`m3-028-move-02/03/04.png` 修复前版本：420 cm/s 全速下玩家呈站姿，旁边 M3-027 修过的敌人却在正常跑动），定位为：**BlendSpace 求值层每帧采样失败，角色永远冻结在采样剪辑首帧（跑步剪辑首帧恰是站姿——"站桩/滑步"）**。

再向下游追：`UBlendSpace::TickAssetPlayer` 里过滤器推进（filtered 到 420）之后、时间推进之前，唯一开关是 `UpdateBlendSamples_Internal → GetSamplesFromBlendInput`。把该调用搬进测试对资产直接探针：

```
UEMMO M3_028 sampling probe [idle] at (0, 0):            （红：无任何采样输出）
UEMMO M3_028 sampling probe [forward jog] at (420, 0):   （红）
UEMMO M3_028 sampling probe [right jog] at (280, 90):    （红）
UEMMO M3_028 sampling probe [backward jog] at (420, 180):（红）
```

**根因：BS_Prototype_Locomotion 资产的运行时采样数据（`GridSamples`/`BlendSpaceData`，引擎实际采样所经的三角化网格）从未构建。** 引擎只有 `UBlendSpace::ResampleData()` 构建 它——正是 BlendSpace 编辑器面板每次手动编辑触发的重建；而 M1-031 的程序化建资产路径（Python `set_editor_property('sample_data', ...)` + C++ `ValidateSampleData()`）不含它：`ValidateSampleData()` 只校验样本合法性，且**样本列表变化时会把 `GridSamples` 清空**、从不重建。于是保存的资产带空网格：加载后所有位置采样返回空 → 每帧 `TickAssetPlayer` 在时间推进前提前返回 → 播放时间恒 0、采样缓存为空 → 角色冻结。旁证：资产原始 `SampleData` 十个采样全部可读（既有静态断言全绿），纯数据"看起来正常"，只有求值层死掉——这正是它逃过 M1-031/M3-024 验收的原因（两者的截图/断言只覆盖了待机单帧姿态与 Montage 路径，从未动态验证移动混合；M1-031 报告"无移动中截图"的已知限制正是这个缺口）。

## 已知限制

- BlendSpace 的运行时网格在编辑器进程构建后随 uasset 保存；若未来再用脚本改 SampleData，必须重跑含本修复的 `create_locomotion_assets.py`（或任何触发 `ResampleData` 的路径），否则会复现本缺陷——采样探针测试会立即拦住（红）。
- 打包（cooked）构建由编辑器期生成的网格数据直接进包；本卡在编辑器二进制 `-game` 渲染进程验证（WITH_EDITOR 生效的路径），未另起 TestPackage 打包轮。
- 在环测试临时世界里给玩家网格设了 `AlwaysTickPoseAndRefreshBones` 以让骨骼指标在无头环境生效（真实游戏每帧渲染本就刷新骨骼）；这是测试场景参数，不改变生产角色配置。
- 空网格时引擎无任何 LogAnimation 错误（静默失败），本次靠引擎调试数据 + 采样探针定位；未改引擎。
- `m3-028-idle.png`（移动前待机帧）两次采集均因与 move-01 同帧截图请求互相覆盖而未落盘；待机参照以 `m3-028-idle-after.png`（停止后站姿，与移动帧同机位同光照）为准。
- Python 普查对 K2Node_VariableGet 的 Nativize 报错为 M1-031 既有已知现象（informational）；权威普查以 C++ builder 日志与测试断言为准。
