## 目的

训练敌人的 EnemyCombat 组件在游戏中无人驱动（命中停顿永不结束、硬直/倒地不恢复、上挑无法浮空）。本卡接上驱动并在环验证。

M1-041 的游戏代码只驱动玩家自己的战斗组件（`APrototypeCharacter::Tick` 里 `SetInputClockSeconds` → `TickCombat`）；`ATrainingEnemy` 的 `EnemyCombat` 无任何逐帧驱动（组件自带 tick 亦禁用）。后果：M1-033 目标侧命中停顿一旦开启永不结束（受害者被钉在 MOVE_None，速度与移动模式冻结）、M1-020 HitStun 与 M1-026 Knockdown/Recovering 的输入时钟期限永不推进、launcher 的浮空 LaunchCharacter 被冻结态吞掉——用户复测会看到敌人首次被击中后永久冻住。本卡给敌人补上与玩家侧完全同构的每帧驱动，并用真实角色在环自动化锁住，防止回退。

## 实际修改

### 每帧驱动（`TrainingEnemy.cpp`，新增 `Tick` override，纯增量）

- 新增 `ATrainingEnemy::Tick`：`Combat != nullptr` 时先 `SetInputClockSeconds(World->GetTimeSeconds())` 再 `TickCombat(DeltaSeconds)`，顺序与 M1-041 玩家侧逐字一致（接口约定：每帧恰一次注入、先于 TickCombat）。
- 时钟源用 World `GetTimeSeconds()`（double），与 `Landed`/`NotifyLanded` 解析落地时间、`NotifyHitReceived` 记 stun 期限的时钟同源；暂停与 HitStop 不推进该时钟（引擎语义）。M1-033 冻结期无需特殊处理：组件 `SetInputClockSeconds` 已实现冻结钉死——冻结期注入仅测量真实推进并消耗 stop 余量，结束注入原样生效，本驱动的逐帧注入正是该实现的驱动源。
- World 为空的调用方（早期测试用 `NewObject<ATrainingEnemy>()` 无世界构造）无 Tick 可言，保持接线前语义；`Tick` 内亦保留 World 空跳过注入的保护，与玩家侧同构。
- 构造函数显式 `PrimaryActorTick.bCanEverTick = true`（ACharacter 默认已开，M1-041 在环诊断 enemyTick=1 可证；显式声明只为把 Tick 驱动依赖写进构造处）。
- 与既有接线不冲突：M1-034 Landed 音效、M1-026 NotifyLanded（`Tick` 不触碰落地路径）；M1-027 ResetEnemy——`ResetCombat` 清停顿/眩晕/缓冲后，下一帧注入原样恢复时钟推进，无状态竞争；死亡路径（`SetDead(true)`）本身清停顿，`TickCombat` 对 dead 组件只走注入消耗分支，无副作用。

### 朝向来源（BeginPlay，固定 Facing）

- 组件侧 `SetFacingProvider`（M1-041 随 `FCombatFacingProvider` 加入 `CombatComponent.h/.cpp`）已存在，本卡直接注入，**未改 CombatComponent 任何代码**。
- provider 返回固定 ±1：由 BeginPlay 捕获的出生锚点 yaw 推导（与玩家侧同一条半平面规则：yaw ∈ (-90°, 90°) → +1 右，否则 -1 左）。训练假人无 AI、游戏中无任何旋转来源，M1-016 场景放置 yaw 180 → 固定 -1（面向玩家出生方向）；`ResetEnemy` 恢复锚点旋转也不会使该值失步。敌人当前不攻击（无目录、无输入），Facing 是休眠簿记，供未来敌侧出手直接可用。

### 在环测试（`Tests/EnemyCombatDriverTests.cpp`，新建，4 条）

- 复用 M1-041 `GameCombatWiringTests` 的场景脚手架模式（该文件未改动）：引擎公开先例 `FTestWorldWrapper`（`CreateTestWorld(EWorldType::Game)` → `BeginPlayInTestWorld()` → 逐帧 `TickTestWorld(1/60)`，真实角色 Tick、真实 CharacterMovement 积分、真实物理、世界时钟逐帧推进）+ 远角场景基（44000,45000,600，与 M1-041 的 40000 角隔离）+ BlockAll 地板盒（显式 SetWorldLocation）+ `EnsureCollisionTreeIsBuilt()` + 地板阻挡前置探测 + 真实 `APrototypeCharacter`（两步物理激活）+ 真实 `ATrainingEnemy`（脚点 +95，三种现行攻击盒 offset/extent 相同全程可达）。辅助全部以 M1_043 前缀唯一命名复制进本文件，独立命名空间 `UE::UEMMO::Tasks::M1_043`。
- **关键红线：敌侧零测试注入**。测试不调用 `SetInputClockSeconds`/`TickCombat`/`SetFacingProvider`/`RequestHitStop` 于敌人组件——敌人的输入时钟只来自其自身 Tick（世界 Tick 驱动），断言 `GetInputClockSeconds() > 0` 即接线 pivot（M1-041 同款）。按键只走生产意图入口 `SubmitCombatInput(Light/Launcher)`，按世界时钟排程。
- 4 条测试：
  1. `EnemyLightHitStopEndsMovementRestoresAndRelaunchable`：轻击命中 → 命中帧断言受害者停顿已开（`IsHitStopActive` 且 MOVE_None）→ 停顿在 20 帧内自行结束 → 移动模式恢复 MOVE_Walking → 0.85s 后 launcher 再命中可浮空。
  2. `EnemyLauncherFloatsTargetThroughItsOwnTick`：launcher 作为第一击 → 冻结 observed → 停顿自行结束 → 敌人 Z 速度>0（浮空不再被冻结态吞掉；700 cm/s 经真实移动积分升起）。
  3. `EnemyHitStunAdvancesOnItsInjectedClock`：轻击 → 停顿结束后组件处于 HitStun → 按注入时钟自行回 Free，且「停顿结束→Free」的时钟跨度落在 (0.05, 0.30] s（0.22 s stun 的停顿后余量，证明按时钟而非按帧数推进）。
  4. `EnemyLaunchedLandingRunsFullRecovery`：launcher 浮空 → 真实 `ACharacter::Landed` → `NotifyLanded` → Knockdown 0.45 s → Recovering 0.25 s → Free，两段时钟跨度分别界于 (0.35, 0.55] / (0.17, 0.33] s；浮空循环计数在恢复期保持 1、恢复完成清 0（第四清零点经真实落地生效）。

## 已知限制

1. 在环测试使用 1/60 s 固定帧步，按键经 `SubmitCombatInput`（真实 X/Z 绑定的最终目标）驱动，非物理键盘事件，亦不等价于手动试玩；用户复测（M1-H01，含浮空手感）仍以真机试玩为准。
2. 朝向为出生锚点推导的固定值：游戏内敌人永不旋转（无 AI、无 OrientRotationToMovement），该值恒定；若未来加入会转身/攻击的敌人 AI，需要把 provider 改读实时 yaw 或接入 AI 朝向（当前卡面明示最小实现即可）。
3. `GameCombatWiringTests.cpp`（M1-041，文件不在本卡范围、禁止修改）中的敌侧代偿 `TickEnemyCombatStandIn` 仍然存在：M1-043 后该场景的敌人组件每帧被驱动两次（自身 Tick + 代偿）。效果上代偿的第二次注入同一世界时刻 `Advanced=0` 不多耗时钟，但其 `TickCombat` 会让该测试里敌侧停顿以至多双倍速度倒数（更早解除）——M1-041 断言不依赖敌侧停顿时长，全量 238 条回归全绿可证。建议后续清理任务移除该代偿（本次未动）。
4. 同一帧内敌人 Actor Tick 与玩家 Actor Tick 的先后为引擎注册序，两种顺序均满足契约（整帧注入同一世界时刻值；冻结余量的消耗每帧一次）。
5. Package 冒烟（打包侧复验）按卡面属可选，由协调者负责重建包后验证。
