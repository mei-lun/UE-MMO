## 关键设计决定

1. **显示读 fire book，不读 reload ledger**：bind 时 `AmmoModel.InitializeInstance(..., 0)` 使 model magazine 恒为 0（仅作装填账本）；面板的 Loaded/Capacity 读 M5-019 binding record 的 `LoadedRounds`/`MagazineCapacity`（TryFire 实扣的那本账），Reserve 读共享池。CompleteReload 后经既有同步回到 fire book。
2. **装填余量查询下放到组件**：窗口开在 per-cycle slot 上，实例 id 查询恒 0；新增 `GetRemainingReloadSeconds(NowSeconds)` 读 `ActiveReloadSlotId`，时钟由调用方给（HUD 用世界时钟），指纹按 0.1s 量化防止逐帧重建。
3. **诚实失败形态**：catalog 锁存 / 已装备武器槽无映射 / 绑定定义不可解析 三形态显式 ConfigFailure，绝不发明武器或弹药；staging 自动装备的 shipping 无映射物品就显示「Equipped weapon item has no weapon mapping」（红字），测试 3 先断言该诚实形态、再经真实 Unequip 按钮路径清槽回到显式 NoWeapon。
4. **生产入口 I 键，控制台降级为调试数据缝**：开/关走 `ToggleInventoryScreen`（关闭半程走 `HandleInventoryCloseRequested` 真实路径，焦点 capture/restore 每次呈现恰好一次）；`UEMMODebugInventory` 仅承担 staging 数据铸造（与 M3-011/M3-012 先例一致）。
5. **开火路径零改动**：开屏拒绝靠既有 menu-open 谓词（presence-based `HasInventoryScreen()||HasMenuScreen()`），关屏恰好恢复一次；装填状态只读展示，T 窗口的完成转移仍是 model 自己的。
