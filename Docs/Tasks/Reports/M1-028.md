## 目的

按任务卡实现 F1 切换的战斗调试覆盖层：开启时在 HUD 显示玩家快照（AttackId/InstanceId/Frame/Facing/ActionState/BufferSize）与目标（训练敌人）HP，仅调试开启时用与真实命中查询**同一** `ComputeHitBox` 路径画当前攻击命中盒；纯显示层，关闭后不画框、查询行为和伤害不变；目标销毁后安全显示无目标。文字明确标注 "DEBUG OVERLAY (M1)" 与当前占位动作名，不假装正式 UI。

## 实际修改

全部 C++ 纯 ASCII；完整构建验证（未用 Live Coding）；`PrototypeHUD.h`、`PrototypeCharacter.h/.cpp` 的最小新增在下方逐条声明。未改 TASKS.md、HANDOFF.md、Docs/Tasks/Handoffs/、Scripts/**、CombatHitTypes.h、CombatHitQuery.*、CombatGeometry.*、HealthComponent.*、CombatInputBuffer.h、AttackDefinition.h、TrainingEnemy.*、PrototypeAnimInstance.* 及任何其他任务文件（`git diff --stat` 仅 5 改 1 增，全部在卡面允许清单内）。

### 1. `Source/UEMMO/Combat/CombatComponent.h`（最小新增：两个内联只读访问器）

- **新增 include**：`AttackCatalog.h`（原先只有前置声明）。原因：任务卡文件范围只扩 `CombatComponent.h` 不扩 `.cpp`，`GetCurrentDefinition()` 必须内联，而内联体调用 `Catalog->Find()` 需要完整类型。AttackCatalog.h 头很轻（Text/SoftObjectPath），同模块无循环。
- `const UAttackDefinition* GetCurrentDefinition() const`（内联）：与 `TryApplyActiveWindowHits` 完全相同的守卫对（`ActionState == Attacking` + `Catalog->Find(ActiveAttackId)`），保证调试框永远不偏离真实查询；Free/硬直/倒地/恢复/死亡或无目录时返回 null（覆盖层不画框）。
- `FVector GetDebugFeetLocation() const`（内联）：直接转调私有 `ResolveFeetLocation()`（provider 优先、owner 次之），调试框与真实查询共用同一 feet 原点。
- 报告声明的 .h 新增即上述两条访问器与该 include，无成员/布局变化。

### 2. `Source/UEMMO/PrototypeHUD.h`（最小新增：开关状态机 + 引用缓存 + 私有绘制接口）

- 开关状态机：`ToggleCombatDebugOverlay()`（F1 入口）/ `SetCombatDebugOverlayEnabled(bool)` / `IsCombatDebugOverlayEnabled()`，成员 `bool bCombatDebugOverlayEnabled = false`（默认关）。
- `UFUNCTION(Exec) void UEMMODebugCombatOverlay(int32 Mode = 1)`：控制台入口（`UPlayer::Exec` 链含 `MyHUD`，已核对引擎 Player.cpp:125-153），供无头渲染取证：Mode 0=关、1=开、2=开+定格演示打击（仅此路径设置定时器，玩法代码永不调用）。
- `void RefreshDebugReferences()`：每绘制帧解析玩家/目标缓存（公开以便无世界自动化测试驱动）。
- 读缝：`PeekDebugPlayer()` / `PeekDebugTarget()`（弱引用失效即读 null）。
- 私有：`DrawCombatDebugOverlay()`、`DrawSharedHitBox()`、`StartDebugDemoStrike()`、两个 `TWeakObjectPtr` 缓存、两个演示定时器句柄。

### 3. `Source/UEMMO/PrototypeHUD.cpp`（主体实现）

- **DrawHUD 分层**：M0 基础面板原样保留；其后 `if (bCombatDebugOverlayEnabled)` 才解析引用并画调试面板。关闭时整段代码不执行——无引用解析、无文字、无框，查询与伤害零触碰（纯显示层）。
- **调试面板**：深色面板 + 黄色标题 `DEBUG OVERLAY (M1) | placeholder combat debug view, not final UI`；玩家行 `Player: AttackId=… Frame=… Facing=… State=… Buffer=… Dead=…`（State 由 `ECombatActionState` 枚举映射，死亡从 `IsDead()` 单独读取，因 FCombatSnapshot 按约定不含死亡位）；动作行 `Action: light_01 (placeholder animation)`（明确标注当前占位动作名）；目标行 `Target HP: 100.0 / 100.0`（走 `ATrainingEnemy::GetHealthComponent`）或 `Target: none`。
- **数据来源（选型声明）**：
  - 玩家：缓存弱引用 + 失效重查；优先 `PlayerOwner->GetCharacter()`（O(1)，无扫描），仅当其失败且无缓存才跑一次 `TActorIterator<APrototypeCharacter>`（仅该类过滤）。比任务卡提的"World 首个角色迭代器"更省——玩家定位零全场扫描。
  - 目标：缓存弱引用 + 失效重查；仅在缓存无效时跑一次 `TActorIterator<ATrainingEnemy>`（仅该类过滤，训练房敌人数 0-2，成本可忽略）；有效缓存期间完全无扫描，满足"不扫描全场获取数据"。
- **命中盒绘制（选型声明：Canvas 投影 + DrawLine）**：仅 `ActionState == Attacking` 且 `GetCurrentDefinition()` 非 null 时，`ComputeHitBox(GetDebugFeetLocation(), Snapshot.Facing, *Definition)` 得盒后取 8 角经 `UCanvas::Project` 投影到画布空间、`AHUD::DrawLine` 描 12 条边（绿色，线宽 2）。与真实查询共享同一函数、同一定义解析、同一 feet 原点、同一 Facing。加 behind-camera 守卫（盒中心与视线向量的点积 ≤ 0 跳过，防 Project 镜像）。
- **Exec 取证钩子（Mode 2）**：6.0s 定时器（避开冒烟跑者 2-4.3s 移动窗口）触发 `StartDebugDemoStrike()`：朝目标 Facing 起真实 `light_01`，再 0.15s 后冻结战斗时钟（落在 light_01 活动窗口 [7,11) 的第 8-9 帧），使 ~8s 的离屏截图能捕获 `Frame>=0` + 共享命中盒。lambda 按弱引用捕获，HUD/组件先拆也不崩。仅调试路径可达，注释明确声明永不用于玩法。

## F1 取证方式（冒烟跑者不能按键）

F1 是物理键，自动化与离屏渲染都无法注入真实按键（运动冒烟覆盖声明同样注明此局限）。取证改走**控制台 exec 同一路径**：`APrototypeCharacter` 把 F1 绑定到 `APrototypeHUD::ToggleCombatDebugOverlay`，而 `UEMMODebugCombatOverlay` exec 直接操作同一开关（Mode 1 与 F1 切开后的状态完全一致；Mode 2 额外起真实 light_01 并把战斗时钟冻结在活动窗口第 8 帧）。渲染运行 `-ExecCmds="UEMMODebugCombatOverlay 2"` 的日志证据链与截图：

- 日志三行：`debug overlay exec mode 2`（exec 经 UPlayer::Exec 链到达 HUD）→ `demo strike started (light_01, facing 1)` → `demo strike clock frozen inside the active window`。
- **F1 键本身**由自动化测试 7 证明绑定存在且唯一（IMC 映射 + Started 绑定 + 幂等）；按键→开关的剩余一跳（`OnDebugTogglePressed` → HUD toggle）是 3 行直调，无自动化可断言的独立行为。

## 已知限制

- **F1 物理按键未做真实人工试玩验证**：自动化证明绑定存在且幂等，离屏取证经 exec 同路径触发；真实键盘 F1 的手感与视觉确认留给用户试玩（H 类人工验收范畴）。
- **演示打击（exec Mode 2）会把战斗时钟永久冻结在第 8 帧**（该次运行内）：仅为离屏截图定格设计，控制台调试路径，玩法代码不可达；进程退出即消失。
- **玩家 HP 未显示**：M1-016 只给敌人配 `UHealthComponent`，玩家无血量组件可读（M1-027 报告同样记录此点），故面板只显示目标 HP；玩家死亡经 `IsDead()` 以 `Dead=yes/no` 显示。
- **地图差异**：GameDefaultMap 是 L_PrototypeArena（无训练敌人），完整"帧+HP"同屏需用训练房地图 `L_TrainingArena` 验证（取证已分别覆盖两种地图）。
- 测试 6 依赖临时世界 spawn 裸 `APrototypeHUD`（引擎对无 PlayerOwner 的 HUD 全程空指针守卫，已核对引擎源码并实测通过）。
- M0 面板第三行文案 "Combat is specified, not implemented in M0" 属 M0 文案，本卡未动（避免扩大范围，正式 UI/文案归后续任务）。
