## 目的

按 AttackDefinition 已有动画生成四份攻击 Montage；新增 `UCombatPresentationComponent` 持有攻击播放控制权（Started/Finished 事件驱动 + 每 Tick 快照兜底同步，中断停止 Montage，完成回 Locomotion）；PlayRate 纯函数使 Montage 时长映射到 DurationFrames/60。Notify 仅表现，不反向决定伤害。

## 实际修改

- `Source/UEMMO/Combat/CombatPresentationComponent.h`（新建）：
  - `UCombatPresentationComponent : UActorComponent`，攻击播放唯一所有者；只跟随战斗状态，不自建计时（CombatComponent 的 60 Hz 时钟仍是唯一时间源），不决定伤害，不加 Notify。
  - 纯函数 `static float ComputeMontagePlayRate(const UAttackDefinition&, float MontageLengthSeconds)` = `MontageLength / (DurationFrames / 60.0)`；`DurationFrames<=0`、`MontageLength<=0` 或非有限时返回 1.0 并每进程记录一次 Warning（不除零，退化为原速播放）。
  - `SetSources(UCombatComponent*, USkeletalMeshComponent*)`：注入战斗源与播放 Mesh，幂等重绑（先 RemoveAll 再 AddUObject），两参数均可空。
  - 播放/查找接缝（protected virtual，测试可覆写）：`PlayAttackMontage`（默认实现：同 Montage 已在播先 `Montage_Stop` 防叠加，再 `AnimInstance->Montage_Play(Montage, PlayRate)`）、`StopAttackMontage`（在播才 `Montage_Stop(GetDefaultBlendOutTime(), Montage)`）、`FindMontageForAttack`（命名约定 `/Game/UEMMO/Animation/Montages/MNT_<AttackId>`，`TSoftObjectPtr`+`LoadSynchronous`+小缓存；缺失优雅跳过、每 id 一次诊断、不崩溃）、`FindDefinitionForAttack`（`DA_<AttackId>` 同约定，供 PlayRate 映射）。
  - 私有 `ApplySnapshot(FCombatSnapshot)` 为唯一同步路径：`ActionState==Free`（含自然结束后、`ResetCombat` 拆除、未来受击/击倒中断到 Free 的路径）→ `StopPresentedMontage` 回 Locomotion；`InstanceId` 变化 → 切播对应 Montage；同一 Instance 稳态 → 无操作（不逐帧重启）。`PresentingInstanceId/AttackId` 记录当前表现实例，缺失 Montage 时状态照常推进（不会每 Tick 重试）。
  - 委托 `HandleStarted`（读快照走同一 ApplySnapshot）、`HandleFinished`（广播时快照已 Free，按已表现实例直接 Stop）；`TickComponent` 每 Tick 读 `GetSnapshot()` 兜底；`EndPlay` 解绑。

## Clip 实际方式

四条 JSON 条目均为整段（clip_start=0，clip_end=素材真实长度，与主检出 `Artifacts/animation-inventory.json` 库存一致），故采用**完整动画 + C++ PlayRate 压缩**：Montage 保留整段，播放速率由 `ComputeMontagePlayRate` 压进 DurationFrames/60。Montage 段 API（`FSlotAnimationTrack`/`FAnimSegment`）在 5.8 中 `SlotAnimTracks` 仅 `BlueprintReadOnly`，Python `set_editor_property` 不可写（引擎源码核实），截段需编辑器 C++ 辅助——脚本对任何未来子片段条目在 validate 阶段显式拒绝（不静默播长），报告如实记录。四份 Montage 的总逻辑时长：light_01 1.0/(26/60)=2.3077→0.4333s、light_02 1.875→0.5333s、launcher 2.75→0.6667s、aerial_01 3.5714→0.4667s。

## 已知限制

- **游戏内攻击演示缺失**：无人调用 `TryStartAttack`（M1-012 输入仅入缓冲），本卡无法提供普攻画面的运行时验证；“两段普攻画面连贯”仅完成组件级验证，需后续任务接线后由用户试玩确认。
- **Tick 兜底有一拍延迟**：组件 Tick 先于 Actor Tick（`TickCombat` 在后者），Reset/中断路径的停止最迟下一组件 Tick（约一帧）发生；同 Tick 的开始/结束由委托即时处理。若未来 HitStun 要求零帧停止，应让中断路径广播事件或改在 Combat Tick 后显式同步。
- **子片段不支持**：Montage Slot 轨道 Python 不可写（引擎反射面核实），当前四条全为整段故无影响；未来子片段条目会被脚本显式拒绝而非静默播长。
- **Notify 未添加**（卡面未要求）：命中数完全由 CombatComponent 时钟与命中任务决定，Montage/Notify 缺失不影响命中数——本卡无任何反向影响路径（组件无写口、无伤害逻辑）。
- `FindDefinitionForAttack` 默认依赖 `DA_<AttackId>` 命名约定（与 M1-009 生成器、DefaultGame.ini 目录一致）；定义缺失时 PlayRate 退化为 1.0 并有一次诊断。
