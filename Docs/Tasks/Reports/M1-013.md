## 目的

攻击进行中（`Attacking`）锁定移动与朝向：整个攻击期间主动 X/Y 走位输入被拒绝（首版全锁，限制值=输入速度缩放 0）、Facing 不因输入翻转；死亡最高优先级同样拒绝；动作自然结束或 `ResetCombat` 后立即恢复。接入点为 M1-029 预留的移动单点 `ApplyPlanarMovement`，读取 CombatComponent 现成的 `CanAcceptMovement()/CanTurn()`（M1-011），**不直接关闭 CharacterMovementComponent**，被击冲量（`LaunchCharacter`）保留。不实现取消窗/衔接（M1-014/021 的事）。

## 实际修改

全部 C++ 纯 ASCII；未改 TASKS.md/HANDOFF.md/Docs/Tasks/Handoffs/Scripts/CombatComponent.*/PlanarMovement.h（协调者禁止清单一字未动）。

1. `Source/UEMMO/Character/AttackMovementGate.h`（**新建，M1-013 自有文件**；偏离说明见"已知限制"第 5 条）
   命名空间 `UE::UEMMO::Tasks::M1_013`，两个内联纯函数（可无 World 单测），实现直接读组件现成 API：
   - `float ComputeAllowedMoveScale(const UCombatComponent*)`：允许的主动输入速度缩放（0..1）。
     - Free 且存活 → **1.0（原速度）**：M1-029 每轴速度 420/280 cm/s 原样保留；
     - Attacking → **0.0**（卡面"首版整个攻击中拒绝主动X/Y走位"=主动走位全锁）；
     - Dead → **0.0**（死亡最高优先级，接口约定 §4）；
     - 组件为 null → 1.0（无战斗源不设门的防御兜底，角色构造必建 Combat 子对象，实际路径不会遇到；测试固化该语义）。
   - `bool CanFlipFacing(const UCombatComponent*)`：Attacking 或 Dead → false（朝向锁定）；Free 且存活 → true；null → true。语义同 `CanTurn()`。
2. `Source/UEMMO/PrototypeCharacter.cpp`（最小增量修改，不重排既有代码）
   - 新增 `#include "Character/AttackMovementGate.h"`。
   - **门控点 = 匿名命名空间 `ApplyPlanarMovement`（M1-029 建立的移动入口单点，Tick 内唯一调用处）**：`AddMovementInput` 块包进 `ComputeAllowedMoveScale(...) > 0` 条件；`SetActorRotation` 朝向翻转块包进 `CanFlipFacing(...)` 条件。其余逻辑（方向归一、`speed/MaxWalkSpeed` 输入缩放、纵深不翻面）原样保留。
   - 未调用 `DisableMovement/StopMovementImmediately`、未改 `MaxWalkSpeed`：CharacterMovementComponent 保持启用，外部冲量路径完全不经过该门控（保留被击冲量）。
   - **恢复机制**：门控每帧读组件实时状态，攻击结束/Reset 后组件回 Free，下一次 Tick 门控自动全开——"立即恢复"由状态读取天然实现，无额外恢复代码；结束/Reset/中断统一走同一路径。
   - 攻击期间 actor 旋转不被输入改变 → 固定侧视镜头（SideViewCameraComponent 跟随 actor）不绕转。
3. `Source/UEMMO/Tests/AttackFacingTests.cpp`（新建，5 条 `UEMMO.Tasks.M1_013.*`；无 World：`NewObject` 组件 + DefaultGame.ini 目录，同 M1-011 的 Hermetic 模式）
   - `FreeStateAllowsMovementAndTurn`：Free 时 `CanAcceptMovement/CanTurn` 均 true、缩放 1.0、允许翻面；null 组件同样放行。
   - `AttackingBlocksMovementTurnAndLocksFacing`：朝左（-1）起手快照携带 Facing=-1，Attacking 时 `CanAcceptMovement/CanTurn` 均 false、缩放 0、`CanFlipFacing` false；攻击中 tick 5 帧后快照 Facing 仍 -1（LockedFacing 不被 tick/输入改变）；Reset 后朝右（+1）起手快照携带 Facing=1（左右两向快照方向）。
   - `DeadBlocksMovementAndTurnInEveryState`：Dead+Free 与 Dead+Attacking 两种状态下移动/转向均拒绝、缩放 0；死亡中 `TryStartAttack` 被拒；复活后仍在攻击中则仍受限，攻击打完回 Free 即恢复。
   - `FinishAndResetRestoreMovementAndTurn`：自然打完（light_01 26 帧）与攻击中 `ResetCombat` 两条路径都立即恢复 `CanAcceptMovement/CanTurn` 为 true、缩放回 1.0、允许翻面。
   - `GateScalesPlanarVelocity`：门控与 M1-029 平面速度的组合语义——Free → 原速度 420 cm/s；Attacking → 主动输入速度为 0；Dead → 0。

## 独立验收逐条对照

- [x] **攻击中反向输入不改变LockedFacing，也不绕转镜头**：组件层——起手后快照 Facing=-1/1 原样，攻击 tick 5 帧后仍 -1（`AttackingBlocksMovementTurnAndLocksFacing`）；角色侧——`CanFlipFacing(Attacking)==false` 时 `ApplyPlanarMovement` 整块跳过 `SetActorRotation`（门控纯函数断言），actor 旋转不被反向输入改变，固定侧视镜头因此不绕转。
- [x] **结束和Reset后左右/纵深输入都恢复**：`FinishAndResetRestoreMovementAndTurn`——自然结束与 ResetCombat 后 `CanAcceptMovement/CanTurn` 立即 true、缩放回 1.0；X 与 Y 轴输入走同一门控单点，恢复即两轴同时恢复（纵深 W/S 同样被锁、同样恢复）。
- [x] **外部LaunchCharacter仍可改变速度，不被输入限制归零**：门控只条件化 `ApplyPlanarMovement` 内的 `AddMovementInput` 调用与朝向翻转，未禁用/未清零 CharacterMovementComponent（无 `DisableMovement`、无 `StopMovementImmediately`、不改 `MaxWalkSpeed`），`LaunchCharacter` 冲量路径不经过该门控，按卡面"保留被击冲量"。

## 已知限制

1. 无 World 的自动化只能覆盖组件状态与门控纯函数；Character Tick 内 `ApplyPlanarMovement` 的端到端行为由 Build + 门开路径运动冒烟 + 纯函数断言间接保证，未做真实键盘试玩（H01 用户验收，AI 不代签）。
2. 跳跃（Space→`Jump()`）不经过 `ApplyPlanarMovement`，本卡未限制攻击中起跳；卡面只写"拒绝主动X/Y走位与转向"，跳跃/浮空交互留待 launcher/aerial 相关任务。
3. 卡面实现步骤"验证朝左时命中坐标将只镜像X偏移"依赖 M1-017 的 `ComputeHitBox`（尚不存在）；本卡验证到镜像的输入端——Facing=±1 正确进入快照（`AttackingBlocksMovementTurnAndLocksFacing` 左右两向断言），命中坐标镜像计算本身归 M1-017。
4. 取消/中断恢复：组件现无 `CancelCurrentAttack`（接口约定 §4 列出但未实现；衔接属 M1-014/021）；本卡覆盖自然结束与 `ResetCombat` 两条恢复路径。攻击实例无"半开残留"（到达末帧即回 Free），死亡期间在飞的攻击由 M1-011 语义保证继续走完/被后续任务接管。
5. **偏离说明**：`AttackMovementGate.h` 为卡面文件范围（CombatComponent.cpp/PrototypeCharacter.cpp/AttackFacingTests.cpp）之外的新建自有文件。原因：协调者要求把"允许的移动速度计算"提为可无 World 测试的纯函数，而 `CombatComponent.*` 与 `PlanarMovement.h` 均在禁止清单，无法挂入现有头文件；新建本卡自有头文件是影响面最小的承载方式（沿用 M1-029 `PlanarMovement.h` 纯函数头模式）。`CombatComponent.*`、`PlanarMovement.h` 及其他任务文件一字未改。
6. null 组件放行是防御性兜底（角色构造必建 Combat 子对象，游戏路径不会遇到）；红灯→中间修复环节曾将该分支写反，已被测试抓出并修正（见红→绿证据）。
