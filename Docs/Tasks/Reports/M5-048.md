### 1. `Data/CombatSystem/weapons.json`（新增 1 行，追加在 rows 数组末尾）

```json
{
  "weapon_id": "scatter_training",
  "mode": "projectile",
  "damage_profile_id": "",
  "ammo_id": "ammo_cell",
  "magazine_size": 6,
  "fire_rate_rpm": 75,
  "burst_count": 1,
  "pellet_count": 4,
  "spread_degrees_deg": 10.0,
  "range_cm": 0,
  "projectile_id": "bullet_linear",
  "melee_attack_ids": []
}
```

字段对齐说明（对照 `Source/UEMMO/Weapons/WeaponTypes.h` 校验器与 `CombatDataTableParser.cpp` 解析规则）：

- `mode: "projectile"`：projectile 模式要求 `damage_profile_id` 必须为空（伤害权威在弹丸行）、`range_cm` 必须为 0、`magazine_size >= 1`、`fire_rate_rpm > 0`、`melee_attack_ids` 必须为空数组——本行全部满足。
- `pellet_count: 4`（1..32 合法）：多弹丸交付复用 `weapon_pellet_sample` 的既有语义（该行 pellet_count=5），无新 C++ 分支。
- `ammo_id: "ammo_cell"`：与 `weapon_pellet_sample` 相同（pellet 样例用的是 ammo_cell，非 ammo_shell/ammo_light）；ammo_cell 已存在于 `Data/CombatSystem/ammo_types.json`（max_reserve 120 / magazine_size 12），交叉引用校验通过。
- `projectile_id: "bullet_linear"`：复用既有直线弹丸行。
- 数值定位：训练剑（近战 10-18/击）与 weapon_pellet_sample（5 弹 × physical_10 = 单轮上限 50）之间——4 弹 × 10 = 单轮上限 40；射速 75 rpm（样例 90）、散布 10°（样例 8°，"scatter" 定位略宽）、弹匣 6（与样例一致，且 weapon 级 magazine_size 允许与 ammo 级 12 不同——weapon_pellet_sample 先例）。
- id 规则：`scatter_training` 满足 a-z0-9_、1-64 字符（`IsValidDefinitionIdText`），表内唯一。

   - `Source/UEMMO/Tests/DropGeneratorTests.cpp`（:851 附近）：钉 "MakeStarterDropTable matches the loaded drops.json table (inline mirror stays in sync)"——C++ 内联镜像仍为 3 条目，与 4 条目的 drops.json 不再相等。
   - `Source/UEMMO/Tests/EquipmentUITests.cpp`（:245、:975）：钉"初始 staging 背包恰好 10 行 / 刷新后 11 行"（M5-056 的 8 武器+护甲+护符）——production staging 走遍全表武器行（`PrototypeHUD.cpp` M5-056 注释），第 9 件武器入包后变 11/12。
