### 目的

交付只读背包列表界面：从 Profile 背包（FInventoryModel，最多 30 格）+ 物品定义组合出行数据显示（名称、槽位、属性、已装备标记），空背包有明确空态，列表可滚动，UI 焦点可退出返回游戏；InventoryModel 无变化事件，刷新采用快照指纹节流，不每 Tick 重建全部列表。只浏览，不穿脱（M3-012 范围）。

### 实际修改

1. **`Source/UEMMO/UI/InventoryWidget.h/.cpp`（新建）**：
   - **ViewModel 纯函数**（无 World、无时钟，全部可无头测试）：
     - `MakeInventoryRowViewModel(Instance, Definition*, bEquipped)`：单个实例 + 可空定义组合一行。显示名取定义 `DisplayName`，定义缺失（nullptr、Catalog 查不到、失效 ID）→ `"<unknown item>"` 占位；槽位名取定义 Slot（Weapon/Armor/Accessory），定义缺失或槽位枚举越界 → `"-"`（不发明槽位）；属性行取**实例自带** RolledStats（实例拥有的真数据，定义失效仍显示），格式恒为三项 `"Atk+5 Def+0 HP+0"`——**零属性按显示 0 处理**（卡面允许"省略或显示 0"二选一，选择显式 0，避免"省略"被误读为无属性面板），整数去 `.0` 尾、小数保留、非有限值渲染为 0（不出现 nan/inf）、负值原样可见（校验数据不会产生，手改数据不静默掩盖）；`bEquipped` 完全由调用方传入的已装备 ID 集合判断。
     - `MakeInventoryListViewModel(Instances, Catalog*, EquippedIds)`：按背包插入序组合整表，防御性硬上限 30 行（FInventoryModel::Capacity；超出取前 30），空背包 → Rows 空 + `IsEmpty()=true`（空态条件）。
     - `MakeInventorySnapshotFingerprint(Instances, EquippedIds)`：快照确定性指纹（数量 + 每项 id/定义 id/等级/三属性/装备标记），渲染结果相同 ⇔ 指纹相同。
     - `FInventoryRefreshGuard::AcceptSnapshot`：首次或变化 → true（重建），相同 → false（跳过并计数）——"不每 Tick 重建"规则的纯状态化。
   - **`UInventoryWidget : UUserWidget`（原生构建，同 RoomResultWidget 模式）**：`NativeOnInitialized` 内 `WidgetTree->ConstructWidget` 全代码构建，无 UMG 资产：居中 560x440 深色面板 = 标题 "Inventory" + 空态行 "Inventory is empty"（仅空背包可见）+ **UScrollBox**（内嵌 VerticalBox 行文本，30 项超出面板高度可滚动）+ "Close (Esc)" 按钮。`BindInventory` 无条件填充并记录刷新基线；`RefreshIfChanged` 指纹门节流（相同快照不动任何控件）；`bIsFocusable=true` + `NativeOnKeyDown` 处理 Esc → `CloseRequested` 广播（关闭按钮同 delegate），HUD 执行真实关闭与焦点恢复。
2. **`Source/UEMMO/PrototypeHUD.h/.cpp`（最小增量，.h 新增见下方清单）**：
   - 挂接入口：**调试 exec `UEMMODebugInventory <Mode>`**（不绑定新键，与 M1-028/M2-012 exec 先例一致）：Mode 0 = 真实关闭路径（`HandleInventoryCloseRequested` → 隐藏 + 焦点恢复）；Mode 1（默认）= 一次性 staging（见下）+ 从真实数据打开；Mode 2 = staging 补满至 30 格 + 打开/节流刷新（滚动与重建证据）。
   - 数据源：`GetInventory().GetAll()`（真实 Profile 背包）+ 装备映射 + 显示 Catalog。**装备映射现状**：ProfileSubsystem 的 Equipment 映射为私有且恒空、FEquipmentModel 尚无运行时接线（M3-010 只接了属性行），故 HUD 持有 `EquippedInventoryIds` 集合（生产默认空 = 无标记），并留 `SetEquippedInventoryIds` 最小接缝；调试 staging 把首件标记为已装备用于证据渲染。**Catalog 现状**：运行时无 Catalog 拥有者（M3-019 才登记显示资源），HUD 的 `InventoryDisplayCatalog` 默认 nullptr → 全部行走 `"<unknown item>"` 占位；仅调试 staging 注入瞬态定义双打（M2-007+ 先例）供截图可读。
   - staging（仅 debug exec 路径）：无 Profile 时经生产入口 `NewProfile()` 铸造本地角色、3 条瞬态定义、3 件 starter 物品经生产入口 `TryAdd` 入包（一次 guard，`bInventoryStaged`）。
   - **刷新策略（卡面要求写明）**：InventoryModel 无变化事件，采用 HUD 侧变化点 + 指纹节流：所有变化点（奖励领取、装备 UI——今日为 debug exec/未来 M3-009/M3-012 接线）调用 `RefreshInventoryScreen()`；未呈现时 no-op，呈现时经 `RefreshIfChanged` 指纹门——相同快照直接跳过（计数），变化才 `ClearChildren` 重建行。**无 per-Tick 轮询、无 DrawHUD 参与**。
   - 焦点：复用 M2-012 的 `FRoomResultInputFocusTracker` 模式（独立实例 `InventoryInputFocus`）——呈现时 tracker 门控一次 `FInputModeUIOnly`（焦点=本 widget、显示光标），Esc/Close 经 `CloseRequested` → 隐藏 + `FInputModeGameOnly` 恢复；重复 capture/restore 被 tracker 拒绝，不会二次切换引擎输入。无 viewport 的无头环境优雅降级（widget 已建、不切输入）。
