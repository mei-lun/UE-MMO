## 目的

按接口约定第 8 节与任务卡，把 M3-003 内联在 `UProfileSubsystem` 里的等级/经验公式提取为独立纯逻辑模块 `FExperienceCurve`（无 World、无 UObject、无时钟），并让 Profile 复用同一实现：等级 1..10、下一级 XP=100×当前 Level、满级需求 0、MaxHP=100+10×(L-1)、Attack=2×(L-1)、Defense=(L-1)。新增多级连升入口 `AddExperience`（按曲线逐级循环消耗、溢出保留、满级 XP 夹 0、负数拒绝），并落位 `FStatCalculator` 雏形：从曲线派生属性完整重算 BaseStats，装备加成入口参数预留（M3-005 填充），纯计算不触碰任何 Health 实例——升级绝不自动回血。

## 已知限制

1. **两套满级 XP 语义并存（有意为之）**：纯曲线 `FExperienceCurve::AddExperience` 按本卡在满级把余量夹 0；而 `UProfileSubsystem::AddXP` 的计数器被不可修改的 M3-003 既有测试锁定为"XP 单调增、满级仍累加并饱和"（`ProfileTests.cpp` 断言满级加 MAX_int32 后 GetXP()==MAX_int32）。因此 Profile 只委托公式与需求查表，满级计数行为保持 M3-003 原样（行为不变约束）。若后续设计要求 Profile 也采用满级夹 0，需由 M3-008/M3-013 相关任务连同 M3-003 测试一起修订，并在报告中记录调参。
2. Profile `AddXP` 仍保留自身级联循环（未整体改调 `AddExperience`），原因是上述满级语义差异；曲线与 Profile 的级联算法目前是同构两份，公式本身单一来源。
3. `FStatCalculator` 的装备加成参数只是类型预留与完整求和形状；真实装备来源、防 NaN/负值加固、MaxHP 变化时的 CurrentHP 钳制均属 M3-005 卡面范围。当前 Sum 为纯 int 相加，不存在 NaN 路径。
4. `FStatCalculator` 定义于 `Profile/ExperienceCurve.h` 全局命名空间；M3-005 的卡面文件范围另列 `Items/StatCalculator.h`，届时应扩展/迁移本类型而非再造同名全局类型（头注释已写明衔接意图），否则会 ODR 冲突。
5. 本卡无资产与画面变更，未跑 Render；未做真实键盘试玩（不涉及输入/运动）。
6. 初值（100/10/2/1、每级 100×L）是设计选择，本次未调参；后续调参须按约定记录。
