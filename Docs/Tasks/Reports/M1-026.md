## 目的

按接口约定第 6 节实现"被击浮空 → 落地 → 倒地与恢复"的完整闭环：训练敌人**曾被击浮空**（launcher/aerial 命中实际施加了垂直 launch）后落地时，触发一次 **Knockdown 0.45s → Recovering 0.25s → Free** 的事件驱动恢复过程（一次落地只建一次，不每 Tick 重启计时）；**恢复期拒绝一切受击**（不扣血、不产生 HitConfirmed、不加冲量、不记 M1-019 去重键）；**恢复完成才重置 AirComboPolicy**（M1-025 三清零点之外新增第四个：Recovering→Free 时清 LauncherCycleCount，保证恢复后新周期从 700 开始）；**Dead 不恢复**，倒地/恢复/死亡互斥（死亡 > 倒地 > 硬直优先级）；普通跳跃/重力落地（无被击浮空标志）永不强制倒地。计时采用组件输入时钟显式注入（M1-020 同款），落地音效（M1-034）保持原路径工作。

2. `Source/UEMMO/Combat/CombatComponent.h` / `.cpp`（最小新增，状态机与拒绝点）
   - `ECombatActionState` 追加 `Knockdown = 3`、`Recovering = 4`（append only，不重编号）。

   - `BeginLandingRecovery(double NowSeconds)`（受害者侧入口）：非有限时刻/已死/已有过程在跑 → 拒绝且零状态变化（一次落地恰一次过程）；否则 `CancelCurrentAttack("LandingRecovery")` + 清硬直簿记，置 Knockdown，**两个截止时刻都在落地瞬间定死**：`KnockdownEnd = Now + 0.45`、`RecoveringEnd = KnockdownEnd + 0.25`（同一注入输入时钟时基，总时长恒 0.70s，与 Tick 间距无关）。
   - `IsInLandingRecovery()`：只读判定（Knockdown 或 Recovering）。
   - `TickCombat`：Knockdown/Recovering 两分支（M1-020 硬直同款注入时钟；每 Tick 至多翻转一次状态，与时序化游戏循环一致），到点 `EndLandingRecovery()`。
   - `EndLandingRecovery()`：Recovering→Free + 清两截止时刻 + **第四清零点**——`Cast<ATrainingEnemy>(GetOwner())->ClearLauncherCycle()`（与 M1-025 读取侧同款 Cast 模式），保证恢复完成后下一次 launcher 从 700 起满速。
   - **恢复期拒绝伤害的落点（攻击侧主防线）**：`TryApplyActiveWindowHits` 内、目标去重/ aerial 门之前，经 `Target->FindComponentByClass<UCombatComponent>()`（与下方 NotifyHitReceived 复用同一次查找）查 `IsInLandingRecovery()`——命中即 `continue`：**不扣血、不加冲量、不记 InstanceHitKeys 去重键（M1-019 语义不受污染，恢复结束可再命中）、不广播 OnHitConfirmed**。
   - **受害者侧纵深防御**：`NotifyHitReceived` 在死亡/致命判定之后、硬直逻辑之前插入恢复期拒绝——恢复中的硬直请求不接管、不叠加、不重启过程（优先级见下）。
   - `SetDead(true)` 死亡转换收尾：清 Knockdown/Recovering（置 Free）并 `EndHitStun()`——死亡、倒地、恢复、硬直互斥（对 Attacking 的既有 SetDead 契约不变：不中断在飞攻击）。`ClearInstance` 同步清两截止时刻（ResetCombat 漏斗，房间重置不残留半个恢复过程）。
   - 优先级实现总结：**死亡 > 倒地/恢复 > 硬直**。Dead 拒绝 BeginLandingRecovery 与恢复期命中（NotifyHitReceived 头部已先行拒绝）；BeginLandingRecovery 覆盖 Attacking 与 HitStun（落地倒地接管硬直）；SetDead(true) 掐掉 Knockdown/Recovering/HitStun。`TryStartAttack`/`CanAcceptMovement`/`CanTurn` 依赖既有 `ActionState != Free` 守卫自然拒绝新状态，无需改动。

## 独立验收逐条对照

- **一次落地事件只建立一次 0.45+0.25s 恢复过程**：`LaunchedLandingBuildsOneKnockdownRecoveryProcess`（恰一次建立；0.45 翻 Recovering、0.70 总时长逐点断言）+ `DuplicateLandedNeverRestartsTheProcess`（重复 Landed 与直接 API 在 Knockdown/Recovering 两阶段均被拒，节拍仍钉在第一次落地的 0.45/0.70）。红灯阶段均失败（无过程/计时），绿灯通过。
- **恢复中命中被拒：不扣血、不产生 HitConfirmed、不加冲量**：`RecoveryRefusesHitsUntilFreeAgain`——HitCount 恒 1、HP 恒 82、速度矢量逐项不变、受害者保持 Knockdown；恢复结束后命中恢复正常（HP 72、击退叠加）。M1-019 去重键未记录（拒绝发生在记键之前），恢复后新实例可正常命中，符合"被拒命中不记键"约定。
- **Dead 不会被 Landed 恢复成 Alive**：`DeadEnemyLandingNeverRecovers`——击杀后落地不进 Knockdown/Recovering、直接 API 拒绝、HP 恒 0、时钟推进无复活；死亡清零点（M1-025）与第四清零点不冲突（计数恒 0）。
- **附加验收**：普通跳跃/重力落地不倒地（`PlainLandingNeverKnocksDown`，含硬直中的普通落地）；恢复完成才重置 AirComboPolicy（`RecoveryCompletionReopensLauncherAtFullSpeed` 的 700/490 判别 + 过程中计数保持 1）；硬直与倒地互斥且死亡>倒地>硬直（`HitStunAndKnockdownAreMutuallyExclusive` 双向）；M1-034 落地音效路径逐字保留（Landed 委托体内 epoch/派发逻辑未动，全量回归含 CombatAudioEventTests 全绿）。

## 已知限制

- **真实游戏侧的每帧推进接线不在本卡**：倒地/恢复与 M1-020 硬直同用"组件输入时钟显式注入 + 每帧 TickCombat"模式；当前游戏侧只有 PrototypeCharacter 每帧推进自己的组件，TrainingEnemy 的 EnemyCombat 尚无该接线（M1-020 起即如此）。因此真实试玩中敌人命中硬直/落地倒地的自动推进需待该接线任务收口；本卡按接口约定第 2 节以显式注入实现并全部验证。
- **测试落地经 `NotifyLanded` 显式时刻 seam**（Landed override 委托同一实现体）：引擎物理落地→`ACharacter::Landed` 的真实调用链共享同一代码，但自动化未覆盖引擎 notify 触发本身（与 M1-034 相同边界）。
- **状态机落在受害者自己的 UCombatComponent**：M2 的 `AMeleeEnemy`（复用 Health/Combat）天然继承倒地/恢复/拒绝行为；但第四清零点与 M1-025 同样按 `Cast<ATrainingEnemy>` 收口，非 TrainingEnemy 的 owner 无浮空周期可清（当前唯一可被浮空的目标就是 TrainingEnemy，M2 敌人采用同一计数面时统一处理）。
- **攻击者侧 `AerialFollowUpTargetIds`（M1-024）不因恢复期拒绝而清理**：恢复中的目标已落地（grounded），M1-024 的惰性判定会在下一次 aerial 尝试时自然丢弃该记录，行为不变。
- **`SetDead(true)` 语义增量**：死亡转换现同时结束 HitStun 与 Knockdown/Recovering（"死亡优先、状态互斥"）；对 Attacking 的既有契约不变。全量回归 192/192 证实对 M1-011/M1-020 用例零漂移。
- **0.45s / 0.25s 为试玩前初值**（接口约定第 6 节），手感（倒地时长、恢复期视觉表现、起身是否可被打断）归 H01 人工试玩；自动化不覆盖真实键盘事件与音画观感。
- 倒地/恢复目前为纯逻辑状态（无动画/表现层动作），表现接入归后续任务。
