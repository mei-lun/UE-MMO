## 目的

在 M2-006/008 的房间 Session 之上交付两个地图 Actor：`ARoomTrigger`（激活区，玩家进入 → `Session::StartRoom`，重复 Overlap 只启动一次）与 `ARoomExit`（出口，状态**由 Session 事件驱动**：Running 锁定、Cleared（OnRunEnded Cleared=true）解锁；解锁后玩家 Overlap → `Session::BeginExit` 恰一次，退出流程本体属 M2-011）。锁定/解锁用现成几何（引擎 Cube）红/绿颜色标记。刷怪地图副本 `L_CombatRoom01` 放置两 Actor，训练地图不动（渲染模式与刷怪模式显式区分）。

## 实际修改（提交 eef86c1ba917c322111f2126e9b07e4f92af2633）

### `Source/UEMMO/Room/RoomTrigger.h/.cpp`（新建，两 Actor 同文件——卡面文件范围仅此一对）

- **ARoomTrigger : AActor**：BoxComponent 激活区（QueryOnly、对 Pawn=Overlap、GenerateOverlapEvents，半长 150/150/90）。BeginPlay 经 World `GetSubsystem<URoomSessionSubsystem>()` 弱引用定位 Session（失效安全，GetSession() 供测试/关卡脚本）。玩家判定 `Cast<APrototypeCharacter>`（训练敌人等非玩家 Overlap 记 Verbose 忽略）。进入 → `StartRoom(Definition)`；**重复 Overlap 的幂等性完全依托 Session 既有语义**（非 Idle 时 StartRoom 拒绝且不重置 RunId），本地不加额外计数。房间定义：`RoomDefinitionAsset`（TSoftObjectPtr，可选）优先 LoadSynchronous；为空时用 `RoomId`（默认 `room_combat_01`）构造瞬态 URoomDefinition（StartRoom 只读 RoomId；目录资产属后续任务，届时地图直接赋资产即可）。
- **ARoomExit : AActor**：BoxComponent 出口区（QueryOnly，半长 80/80/110）+ UStaticMeshComponent 引擎 Cube（1.6 缩放）。状态**只由事件驱动**：`OnRunStarted`→锁定；`OnRunEnded` 仅 `Result.bCleared` → 解锁（Failed 保持锁定）；BeginPlay 一次性 `SyncFromSession`（对中途生成/已结束会话显示正确状态）+ 应用视觉。事件绑定用 `AddWeakLambda`（Session 事件是普通 C++ 委托、`FRoomResult` 非反射类型，UHT 拒绝 UFUNCTION 形参；弱绑定随 Actor 失效自清，EndPlay 再 `RemoveAll` 显式移除）。锁定门禁：`HandleExitBeginOverlap` → 仅当 `bUnlocked && Session->GetState()==Cleared` 才 `BeginExit`——Running 期间出口 Overlap 不产生任何胜利信号；接受后 Session 进入 Exiting（本 Actor 不再发信号）→ **BeginExit 恰一次**。视觉：MID `SetVectorParameterValue("Color", 红(0.85,0.12,0.12)/绿(0.16,0.75,0.22))`。
- **材质坑（红灯迭代发现）**：`/Engine/BasicShapes/Cube` 槽 0 实际是 `WorldGridMaterial`（无 Color 参数，首次截图两态同为灰色）；构造器显式 `SetMaterial(0, /Engine/BasicShapes/BasicShapeMaterial)`（其 vector 参数 `Color` 经编辑器脚本 `MaterialEditingLibrary.get_vector_parameter_names` 证实）后颜色生效。

### `Source/UEMMO/Tests/RoomTriggerTests.cpp`（新建，前缀 `UEMMO.Tasks.M2_009.*`，6 用例）

复用 M2-006/007/008 的 FTestWorldWrapper 临时游戏 World（真实 Session）+ **真实 Tick 模式**（`TickTestWorld`；传送玩家后对胶囊 `UpdateOverlaps()` 强制一次当前变换的重叠发现并派发事件——红跑证据显示手动 Tick 世界对传送不自动派发重叠，详见已知限制）。

1. `RepeatedTriggerOverlapsStartExactlyOneRun`：非玩家探针（训练敌人）入区不启动；玩家 1 进 + 3 次进出 → StartedCount=1、RunId 不变、始终 Running、无 end 事件；Session RoomId=触发器 RoomId（瞬态定义回退生效）。
2. `ExitLocksWhileRunningAndUnlocksOnCleared`：Idle 锁 → Running 锁 → MarkCleared 解锁（end 事件恰 1）→ ResetToIdle+StartRoom 后 RunStarted 重新锁 → FailRun 后 Failed 保持锁（两次 end 结果 Cleared/Failed 各半）。
3. `LockedExitOverlapYieldsNoVictoryAndNoExit`：Running 时玩家进出口区 → 仍 Running、无 end 事件、RunId 不变、仍锁定。
4. `ClearedExitOverlapSignalsBeginExitExactlyOnce`：Cleared 后首次 Overlap → Session 进入 Exiting；离开再进入仍 Exiting（不重复发信号）；end 事件恒为 1。
5. `CombatRoomMapCarriesTriggerAndExit`：`-game` 进程 `LoadObject<UWorld>` 加载 `/Game/UEMMO/Maps/L_CombatRoom01`，直读持久 Level 的 Actor 数组（未初始化的世界资产上 TActorIterator 取不到 Actor，改为 `World->PersistentLevel->Actors`）→ Trigger=1、Exit=1、PlayerStart≥1。
6. `ExitStateScreenshots`：采集伴随用例——在真实游戏世界（GWorld 有视口/玩家时）驱动一个真实 ARoomExit 走 Running/Cleared 两态，各请求一张截图（无渲染环境优雅跳过，保证 -nullrhi 回归不受影响）。

## 已知限制

- **测试世界的重叠派发**：FTestWorldWrapper 手动 Tick 的临时世界不会为传送自动派发 Overlap（红跑中桩的出口 Overlap 从未触发的直接证据），测试移动助手在传送+Tick 后对胶囊调一次 `UpdateOverlaps()` 模拟真实引擎每帧物理步的重叠发现；真实游戏循环无此问题。
- **触发器只做 StartRoom**：不含 BeginWaves（需要 UEnemyDefinition，目录资产属后续任务）；真实开战后波次自动推进的接线属后续房间流程任务。触发器携带的房间定义当前为瞬态回退（RoomId=room_combat_01），`Data/rooms.json` 本卡禁改，未新增 room_combat_01 条目。
- **出口为颜色标记而非物理阻挡**（卡面"红色/半透明方块阻挡**或**颜色标记"取后者）：胜利信号的拦截由锁定语义完成（Running 期间不发 BeginExit），玩家可穿过出口方块。
- 战斗副本继承训练地图的 1 个训练敌人（纯脚手架，按协调者指示"训练敌人照旧"原样保留，未删除）；地图上两 Actor 位置为常量约定，未写入任何 JSON。
