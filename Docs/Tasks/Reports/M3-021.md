## 独立验收逐条对照

- **所有故障后物品不凭空丢失或翻倍**：满足。每个测试槽在失败点前后调用统一不变量 `M3_021_ExpectXPAndItems`（背包 + 全部 pending 的 InstanceId 并集 + XP），XP 差值恰为 50 或 0；领取/重领路径另显式断言背包含原 InstanceId、draft 清空、无第二件。
- **坏档回退及两槽坏提示符合设计**：满足。单槽坏 → `RecoveredFallback`（回退另一槽、报告含原因与坏槽名、坏文件字节保留、保存路径仍可用）；两槽坏 → `RecoveryError`（问题列表点名两槽、写盘被守卫拒绝且写计数为 0、证据保留、绝不静默 NewProfile/伪装新档）。
- **重放 SettlementId 不会重复 XP/物品**：满足。活跃与重启后两条路径上，重放 Begin → `AlreadyApplied`（原草稿逐字段一致/已领取则无草稿），重放领取 → `AlreadyClaimed`（无 XP、无存盘、无第二件），总 XP 恰 50。

## 已知限制

- 快速点击的 Claim 半程未直接驱动 `APrototypeHUD::HandleRewardClaimRequested`：该路径内部 `EnsureRewardSaveService` 固定生产 `Profile_` 前缀且无存储注入缝，驱动它会触碰真实存档（卡面禁止）。改为按该调用点的生产接线形状（`FRoomResultActionGuard` + 真实 `URewardService::ClaimPendingAtomic` + 隔离 `M3_021Slot_` 前缀）验证守卫与数据不变量；Retry 半程则是真实 HUD 路径（不涉及存档）。
- M3-021 用例不产出场景证据 JSON（卡面未要求）；场景门禁继续拷贝 M3-020 的证据文件。
- 退出地图用例不创建任何存档（会话不落盘），无可清理槽路径；清理断言只在有存储的用例执行。
- 自动化不覆盖真实键盘事件，"快速点击"以请求级双击建模（M2-012 先例），不等价于人工试玩。
