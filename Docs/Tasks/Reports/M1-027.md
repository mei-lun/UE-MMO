## 目的

按接口约定第 6 节实现训练场统一复位入口 `UTrainingResetService::ResetTrainingSession`：一次调用清理玩家与全部已注册敌人的输入、动作、计时、命中集合、速度、HP、朝向和浮空计数，双方回出生点，不重载整张地图；连续复位幂等；玩家 M0 的 R 键 `ResetPosition` 包装进同一入口且单次按键恰好执行一次复位；复位后新攻击实例 ID 保持会话内单调唯一（不重置计数器，M1-011 决定）。

## 实际修改

全部 C++ 纯 ASCII；完整构建验证（未用 Live Coding）；`TrainingEnemy.cpp/.h` 零改动（既有 `ResetEnemy` 已完整覆盖敌方 HP/锚点/速度/浮空计数，无需新增）；`CombatComponent`、`HealthComponent` 等禁改文件零改动（全部通过既有公开 API 组装）。未改 TASKS.md、HANDOFF.md、Docs/Tasks/Handoffs/、Scripts/**、CombatHitTypes.h、CombatHitQuery.*、CombatGeometry.*、HealthComponent.*、CombatInputBuffer.h、AttackDefinition.h、AirComboPolicy.*、Data/*.json。其他任务测试零改动（全量回归 200/200 含 M1-018~M1-034 全部既有用例，零回归）。

### 1. `Source/UEMMO/Room/TrainingResetService.h` / `.cpp`（新建；Room/ 为新目录，无连字符）

- `UTrainingResetService : public UObject`，成员用 `TWeakObjectPtr` 持有参与者（玩家单槽 + 敌人数组），销毁的注册项懒清理（`PruneStaleEnemies`）。
- **敌人集合来源：注册制**（`RegisterPlayer` / `RegisterEnemy`），未用 `TActorIterator` 世界枚举。理由：任务卡明示"测试用注册制更可控"；注册制集合确定、不受同世界无关空间干扰，生产侧由房间归属方（未来房间/会话接线）注册自己的参与者。重复注册同一敌人被忽略（幂等），`GetRegisteredEnemyCount()` / `GetResetCount()` 供测试与诊断。
- **Reset 顺序（集中定义于 `ResetTrainingSession`，两阶段）**：
  - **阶段一 · 先停动作/计时（全体参与者，物理未动之前）**：玩家与每个敌人的 `UCombatComponent::ResetCombat()`——取消在飞攻击（不广播 Finished，复位是拆除不是打完）、脱离 HitStun/Knockdown/Recovering、清实例命中集合（InstanceHitKeys）、清战斗输入缓存（InputBuffer.Reset）、清硬直/倒地/恢复三组截止时刻与动作时钟、清攻击侧浮空追击记录（AerialFollowUpTargetIds）。故意不动 dead 标记与 InstanceId 计数器（后者属阶段二/永不回卷）。
  - **阶段二 · 再复位物理和数值**：玩家走 `ApplyTrainingRoomReset()`（位置回出生点、速度清零、`ClearAccumulatedForces` 清挂起冲量/launch、运动模式回 Walking、朝向回 BeginPlay 捕获的出生朝向）；敌人逐个走 `ResetEnemy()`（HP 满 + 新死亡生命周期、撤 dead 标记、combat 再拆一次幂等、回锚点变换、速度清零、AirComboCount/LauncherCycleCount/bWasLaunchedAirborne 浮空三项清零）。
  - 末尾 `++ResetCount`。全程无地图重载；每步都是拆除或赋值，天然幂等。
- **玩家 HP 处理**：玩家未挂 `UHealthComponent`（M1-016 只给敌人配血量），按任务指示跳过玩家 HP 项，敌人在阶段二统一 `ResetHealth`。

### 2. `Source/UEMMO/PrototypeCharacter.h` / `.cpp`（最小新增）

- `.h` 最小新增（报告声明）：前置声明 `UTrainingResetService`；`ResetPosition()` 从 private 移到 public（本就是 R 键绑定目标，测试直接驱动）；新增 `ApplyTrainingRoomReset()`（复位物理半段）与 `SetTrainingResetService()`（注入服务）；新增私有 `FRotator SpawnRotation` 与 `TWeakObjectPtr<UTrainingResetService> TrainingResetService`。
- `.cpp`：`BeginPlay` 捕获 `SpawnRotation`；`ResetPosition()` 改为**路由**——有注册服务则调 `Service->ResetTrainingSession()`（服务在阶段二转调 `ApplyTrainingRoomReset` 复位玩家物理），否则走 `ApplyTrainingRoomReset()` 保留 M0 本地复位。
- **绑定方式与无双重执行**：R 键仍保持原有唯一一条 `ResetAction Started -> ResetPosition` 绑定（`SetupPlayerInputComponent` 未动，且有 `ClearBindingsForObject` 幂等护栏）；`ResetPosition` 内两分支互斥先返回，服务路径只在此入口执行一次会话复位；`ApplyTrainingRoomReset` 自身不触发会话复位，两条入口不可能互递归。测试用 `GetResetCount()` 断言一次按键恰好计数 +1。`Tick` 的坠落自救（Z < -1000）同样经 `ResetPosition` 走统一入口。冒烟跑者（`PrototypeSmokeRunner.cpp`）不调用 `ResetPosition`/Reset 相关入口（grep 证实），M0 冒烟零影响。

- `PlayerResetRoutesThroughServiceExactlyOnceAndFallsBack`：带服务玩家 `ResetPosition()` → `GetResetCount` 恰 1（无双重执行）、双侧行为+物理全复位；再按一次幂等（计数恰 2）；无服务裸玩家 `ResetPosition()` 走 M0 本地复位（回出生点、速度清零）且不触碰服务。

## 已知限制

- **生产接线未含**：任务卡文件范围不含 GameMode/房间子系统，故当前 PIE 中没有常驻对象创建服务并注册玩家/敌人——真实游戏里 R 键（未注入服务时）走 M0 本地复位回退，行为与 M0 一致不回归。统一复位的生产接线（谁创建服务、注册参与者、注入 pawn）按服务契约留给房间/会话侧任务；接口（`RegisterPlayer/RegisterEnemy/SetTrainingResetService`）已就绪并有测试钉死。
- 玩家无 `UHealthComponent`，玩家侧复位不含 HP 项（M1-016 范围决定，如上）；玩家自身也无敌方浮空计数（AirComboCount/LauncherCycleCount 挂在 `ATrainingEnemy`），玩家侧对应的攻击者浮空记录（AerialFollowUpTargetIds）由 `ResetCombat` 清除。
- 服务按注册制收集敌人（未实现世界枚举备选）；若未来房间希望自动收集，需在房间侧显式遍历后逐个 `RegisterEnemy`，服务保持无 World 依赖。
- 自动化不覆盖真实键盘事件；R 键手感以代码路径与 `GetResetCount` 断言为准，未做人工试玩（不涉 H01）。
