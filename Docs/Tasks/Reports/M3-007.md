## 目的

按接口约定第 8 节落地结算奖励的掉落表与生成器：`FDropTable`/`FDropEntry`（starter 表三条权重 50/30/20，源数据 `Data/drops.json`）与 `FDropGenerator::GenerateReward`（独立 `FRandomStream` 种子流，一次加权选择产出 1 件装备实例）。同 RewardSeed 与 SettlementId 重试得到同一实例（InstanceId 由 SettlementId+槽位确定性派生）；权重总和 0、负权重、未知/重复 DefinitionId 均拒绝；战斗随机数不影响奖励序列。XP50 与满包保留属 M3-008/009，本卡不做。

## 实际修改

- `Source/UEMMO/Items/DropTable.h`（新建，纯值类型，无 UObject/UHT）：
  - `FDropEntry`：`DefinitionId`（FName，须能在目录解析）+ `Weight`（int32，>= 0）。
  - `FDropTable`：`TableId`（FName，如 "starter"）+ 有序 `Entries`。
  - `ValidateDropTable(const FDropTable&, FString& OutErrors)`：TableId 非空、Entries 非空、每条 DefinitionId 非空且表内唯一、每条 Weight >= 0；错误以 "; " 连接且每条含字段名（`TableId`/`Entries`/`Entries[i].DefinitionId`/`Entries[i].Weight`）。
  - `MakeStarterDropTable()`：内联镜像 `Data/drops.json` 的 starter 表（weapon_training:50 → armor_training:30 → charm_training:20），测试断言两者逐字段相等以防漂移。
- `Source/UEMMO/Items/DropGenerator.h/.cpp`（新建，纯逻辑，无 World）：
  - `FDropRewardResult`：`bSuccess`、`Instance`、`Error`（失败时信息含字段名）。
  - `FDropGenerator::GenerateReward(int64 RewardSeed, uint64 SettlementId, const FDropTable& Table, const FItemDefinitionCatalog& Catalog, int32 RewardIndex = 0)`：
    - 拒绝顺序（全部一次遍历，确定性）：空 Entries → 逐条（空 DefinitionId / 负 Weight / 重复 DefinitionId）→ 逐条目录查无 → 总权重 <= 0；不通过即返回失败，不产出实例。
    - **独立随机流**：`FRandomStream(DeriveSelectionStreamSeed(RewardSeed))`，种子仅由 RewardSeed 经 64 位 murmur3 finalizer（`DropMix64`）加盐折叠为 int32；不使用全局流、不与战斗流共享，战斗抽取次数/帧率差异不可能改变掉落。
    - **一次加权选择**：`Point = FRand() * TotalWeight`，单趟累计权重比较定位（无随机重试循环）；仅浮点在精确上边缘舍入时回退到最后一条正权重词条（确定性、有界）。
    - 实例：`MakeItemInstance(*Definition, DeriveRollSeed(RewardSeed))` 后覆写 `InstanceId = DeriveInstanceGuid(SettlementId, RewardIndex)`。`RollSeed` 由 RewardSeed 加独立盐派生（与选种流盐不同，未来属性 Roll 与选种流不相关）；`RolledStats` 按 M3-001 工厂行为原样复制 BaseStats；Level=1。
    - 每次调用固定产出 1 件装备（RewardIndex 默认 0）。
- `Data/drops.json`（新建）：schema_version=1、table_id="starter"、entries 三条 weapon_training:50 / armor_training:30 / charm_training:20，纯 ASCII。

### 确定性派生方案（供 M3-008/009 使用）

- 选种流种子：`DeriveSelectionStreamSeed(RewardSeed) = int32 折叠(DropMix64(uint64(RewardSeed) ^ 0x9E3779B97F4A7C15))`。
- 实例 RollSeed：`DropMix64(uint64(RewardSeed) ^ 0xC2B2AE3D27D4EB4F)`（盐异于选种流）。
- InstanceId：`FGuid(A,B,C,D)`，其中 `A = DropMix64(SettlementId ^ 0x243F6A8885A308D3 ^ (RewardIndex << 32))`、`B = DropMix64(SettlementId * 0x9E3779B97F4A7C15 ^ 0x13198A2E03707344 ^ RewardIndex)`，取 64 位折叠的两个 uint32 对；**只依赖 (SettlementId, RewardIndex)，不含 RewardSeed 与时钟**，并保证全零 GUID 不会出现（兜位置 A=1，确定性）。同 RewardSeed 同 SettlementId 重试得到逐字节相同的实例快照。

## 独立验收逐条对照

- **同 RewardSeed 与 SettlementId 重试得到同一实例**：`SameRewardSeedAndSettlementAreDeterministic` —— 同 (0x5DEECE66D, 42) 三次重试：DefinitionId、InstanceId、RollSeed、RolledStats 三项、Level 全等，`ToStringSnapshot()` 逐字节相同；另一 SettlementId（43）得到不同但同样确定的 InstanceId 且同种子选中同种 DefinitionId；选中项必为 starter 三条之一。通过。
- **未知 DefinitionId 或权重总和 0 失败**：`RejectsZeroTotalUnknownIdAndNegativeWeight` —— 全零总权重拒绝（报错含 `Weight`）；空 Entries 拒绝（含 `Entries`）；负权重（总权重仍为正）拒绝（含 `Weight`）；未知 ID（混入或唯一词条，报错含 `DefinitionId` 与缺失 id 文本）；表内重复 DefinitionId 与空 DefinitionId 拒绝；所有失败调用不产出合法 InstanceId；`ValidateDropTable` 对结构性用例结论与生成器一致。通过。
- **调用战斗随机数不改变奖励序列**：`BattleRandomDoesNotDisturbRewardSequence` —— 先取两基线，再让专用战斗流抽 1000 次并 `FMath::Rand()` 抽 200 次，两种子奖励快照与基线逐字节相同；反向顺序（先消耗后取基线）亦与原基线一致。通过。
- **不同 RewardSeed 序列独立**（实现步骤项）：`DifferentRewardSeedsFollowIndependentSequences` —— 种子 A/B 交错生成 A、B、A、B 各自结果不变；两种子派生 RollSeed 不同、快照不同；1..24 种子扫描全部成功、各自复现、24 个 RollSeed 互异且覆盖至少两种 DefinitionId（加权选择确实在变）。通过。
- **items/drops JSON 一致性**（本卡附加要求）：`DropsJsonMatchesItemsCatalogAndDrivesGeneration` —— drops.json schema_version=1、table_id="starter"、恰好 3 条且 id/权重与设计 50/30/20 逐项相等；三条 DefinitionId 全部存在于 items.json（items 恰好 3 条）；载入表过 `ValidateDropTable` 且与 `MakeStarterDropTable()` 逐字段相等；用载入表 + 目录真实生成成功。通过。

## 已知限制

- `RolledStats` 仍为 BaseStats 原样复制（M3-001 工厂行为），本卡未引入属性随机浮动；本卡验收只要求"同种子同属性"的确定性，`RollSeed` 已按独立盐记录，真正的属性 Roll 留给需要它的后续任务（届时用现成 RollSeed 驱动即可）。
- InstanceId 不含 RewardSeed：同一 SettlementId 若调用方违反重试契约换种子重掷，InstanceId 不变而内容可能变。随机结果生成一次、重试不重掷的持久化防护属 M3-008（`FPendingReward`）；本卡保证同 (RewardSeed, SettlementId) 完全幂等。
- 独立性是流隔离意义上的：选种流只由 RewardSeed 决定；RewardSeed 本身由调用方（M3-008）从结算数据派生，本卡不规定其来源。
- 生成器对非法表格只报告第一个命中的错误（结构 → 目录 → 总权重顺序）；聚合全部问题的能力在 `ValidateDropTable`。
- XP50、满包保留、奖励领取与存档同快照持久化均属 M3-008/009/013，本卡未涉及。
- 测试为纯逻辑自动化，无画面变更，未跑 `Test.ps1 -Render`；JSON 解析沿用手写解析器模式（Json 模块链接限制，见测试文件头注释）。
