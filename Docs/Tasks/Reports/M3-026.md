## 目的

用户试玩反馈：攻击刷怪房的敌人无任何反馈（无血条、无伤害感知）；已确认伤害事件正常广播（日志 18 次命中）、敌人血条从未绑定到生产刷怪的敌人。同时 L_CombatRoom01 从训练地图复制时继承了训练假人（TrainingEnemy），玩家攻击会同时命中假人与波次敌人（双重命中混乱）。本卡交付：HUD 对被命中敌人绘制跟随血条（死亡/失效移除，上限 3），并从战斗房地图幂等清理训练假人。

## 实际修改（提交 836838a330af0cc551d6a83bd0c9270faa54caf4）

### `Source/UEMMO/PrototypeHUD.h/.cpp`（血条最小增量）

- **数据结构**：`FEnemyBarEntry` = 敌人 Actor 弱引用 + 其 `UHealthComponent` 弱引用（M1-035 弱引用契约：被销毁读 null，读取前剪除，绝不悬垂解引用）。
- **数据源**：复用 M1-035 伤害数字的 `OnHitConfirmed` 订阅——`HandleHitConfirmed` 在既有伤害数字/连击之外追加 `TrackEnemyBarTarget(Hit)`（同一事件喂三类 HUD 反馈）。`RefreshDamageFeedBinding` 改为 public 且每绘制帧调用（血条是生产 HUD，不再挂在 debug 开关之后；overlay 关闭时经 `PlayerOwner->GetCharacter()` O(1) 解析，无世界扫描）。
- **建条规则**（`TrackEnemyBarTarget`）：取事件 Hit.Target（受击者）；无 HealthComponent 的目标忽略；已追踪的敌人重复命中只 upsert（刷新其血池引用，绝不重复建条）；上限 3 条（房间最多同时 3 敌），超限拒绝新条目而非驱逐旧条目。
- **移除规则**（`PruneEnemyBarEntries`，幂等）：弱引用失效、`!IsAlive()` 或 `GetHealth()<=0` → 移除条目。每次读取（计数接缝与绘制路径）先跑剪除，因此死亡移除无需绑定 OnDied 事件。
- **绘制**（`DrawEnemyHealthBars`）：世界锚点 = 敌人位置 + Z 120（胶囊半高 88 上方头顶）；`Canvas->Project` 投屏 + 后视相机保护（锚点在视点前方判定，与 M1-035 数字相同契约）；样式复用 M1-035 调色板（M2-012 敌人 HP 条样式）：深色底框 + 红色填充（填充比每帧读敌人真实 HealthComponent）+ `HP / Max` 文本。
- **测试接缝**：`GetTrackedEnemyCount()`（剪除后的活条目数）、`PeekTrackedEnemy(i)`、`PeekTrackedHealth(i)`（只读）。
- **HealthComponent.h/.cpp 零修改**：`GetHealth()/GetMaxHealth()/IsAlive()` 接口已存在（M1-016），无需按卡面预案新增最小 Get。

## 已知限制

- **血条数据源是 OnHitConfirmed（被命中的敌人才建条）而非 Session AliveIds/生成记录**：协调者边界划定——并行任务 M3-025 独占 Enemy/** 与 WaveSpawner 接线，`RoomSessionSubsystem` 本卡只读。效果：未被攻击过的敌人暂不显示血条，首次受击后出现并持续跟随至死亡/失效。此为卡面"最少：最近一个存活敌人的血条"下限之上的实现（最多 3 条，房间敌上限）。
- **只追踪玩家命中的敌人**：HUD 只订阅玩家 combat feed，敌人间互殴不建条（单机原型玩家视角语义正确）。
- **双重命中的体感确认**：自动化证据是地图枚举无 TrainingEnemy + 命中即建条用例；"玩家实际感知不再混乱"需用户试玩确认，本报告不代签。
- EnemyBarScreenshots 在 -nullrhi 回归中跳过采集（`FApp::CanEverRender()` 为假时日志声明并跳过），截图由独立 -RenderOffscreen 采集运行产出。
- `set_actor_location` TypeError 属 M2-009 既有幂等路径的潜在缺陷（此前从未重复运行到该路径），由本卡首次幂等重跑暴露并修复；该文件在本卡允许修改范围内。
