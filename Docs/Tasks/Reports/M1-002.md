## UE 5.8 真实导出格式（本次实测确认，非文档猜测）

来自引擎源码（AutomationControllerManager / JsonObjectConverter）与真实运行产物双重确认：

- 参数为 `-ReportExportPath=`（旧名 `-ReportOutputPath=` 会告警）；报告写在 `<目录>/index.json`（另有 index.html）。
- JSON 键为 **camelCase**（`tests`、`reportCreatedOn`、`fullTestPath`、`state` 等）；PowerShell 属性查找大小写不敏感，解析器按 PascalCase 访问即可命中。
- `state` 是枚举名字符串：`NotRun/InProcess/Fail/Success/Skipped`。
- `reportCreatedOn` 是 **UE 默认日期格式** `yyyy.MM.dd-HH.mm.ss`（UTC、无时区后缀，如 `2026.09.25-15.12.33`），不是 ISO-8601 也不是 Ticks 对象；解析器三种格式都支持，按 UTC 解释。
- 零匹配时 UE **不写 index.json**，日志输出 `...Automation Test Queue Empty 0 tests performed.`；入口脚本在该情形下解析此日志行归类为 `zero_tests`。

## 错误分类（全部返回非零）

| error_kind | 触发条件 |
|---|---|
| process | UE 进程非零退出或超时（Invoke-UEProcess 抛出） |
| no_report | 进程正常但 index.json 缺失且日志非零测试 |
| zero_tests | 匹配数为 0（解析器）或日志确认 0 tests performed |
| failures | 匹配测试中有 `Fail` 状态 |
| incomplete | 匹配测试中有 `NotRun/InProcess/Skipped` 状态 |
| stale | 报告生成时间早于 15 分钟上限或在未来 5 分钟以上 |
| structure | 非 JSON、缺 Tests、缺 State/FullTestPath、ReportCreatedOn 不可解析 |

## 过程中发现并修复的问题

1. Windows PowerShell 5.1 把无 BOM UTF-8 的 .ps1 按 ANSI/GBK 解析，脚本内中文字符串导致解析错误：脚本字符串全部改为 ASCII 英文，中文说明留在报告与文档。
2. `TimeSpan.ToString('zzz')` 不合法（zzz 是 DateTime 格式）：改用 `DateTimeOffset.ToString('yyyy-MM-ddTHH-mm-sszzz')` 去冒号生成目录时间戳。
3. 零匹配时 UE 不导出报告：曾误分类 no_report，改为解析日志 "N tests performed" 归类 zero_tests。
4. 真实导出日期为 UE 默认格式而非 ISO：解析器补 `yyyy.MM.dd-HH.mm.ss`（UTC）分支，并新增两个真实格式夹具用例。
