## 已知限制与偏离

1. **动画映射与协调者指令不一致（按设计文档第 7 节）**：指令写 launcher→MM_Attack_03、aerial_01→MM_ChargedAttack；设计文档第 7 节明确"launcher 暂用 MM_ChargedAttack 作为逻辑验证的表现占位……aerial_01 暂复用 MM_Attack_03 的片段"。按卡面"具体初值见接口约定与设计第 7 节"及协调者"以设计文档为准"的裁定原则，取设计文档映射：launcher=MM_ChargedAttack、aerial_01=MM_Attack_03。两者均为占位（placeholder_animation=true），不影响验收第 3 条。
2. **next_attack_ids 与协调者指令不一致（按设计文档第 7 节）**：指令给出 light_01.next=[light_02, launcher, aerial_01]、light_02.next=[light_01, launcher, aerial_01]、launcher.next=[]；设计第 7 节"下一动作"列为 light_01→light_02/launcher、light_02→launcher、launcher→aerial_01、aerial_01→落地或下一次追击（空）。指令版会把 launcher.next 置空，连招核心链"普攻→上挑→浮空追击"将无法经取消衔接成立，故取设计文档值。协调者版是设计值的超集/缺失混合，若后续想要更宽松的衔接，只需改 JSON 数组并重跑校验。
3. launcher 的 `hit_stun_seconds=1.0` 为占位值：设计写"硬直=浮空期间"，由浮空状态系统接管，文本字段仍需非负数值，先给 1.0 秒下限，待试玩调参。
4. `clip_end_seconds` 为库存里 float 序列化的全精度值（如 1.8333333730697632）；播放缩放公式已写入 `clip_policy` 字段，但 play_rate 的实际生效在 M1-009/M1-010 的资产/目录阶段，本卡不验证。
5. C++ 侧 JSON 解析为手写最小解析器（原因见上）；已覆盖本数据用到的全部 JSON 特性，不支持根顶数组外的更多糖（无影响）。\u 转义按单 TCHAR 解码（本文件纯 ASCII，未触发）。
6. 校验脚本允许未知顶层文档字段（clip_policy/cancel_window_policy），并按 M1-007 语义仅在 placeholder=false 时检查 clip 顺序；PS 5.1 的 ConvertFrom-Json 保留数组形状，脚本内用 `return , $Value` 防管道解包。
7. 本卡按协调者要求未登记/修改 TASKS.md、HANDOFF.md 与 Docs/Tasks/Handoffs/（由协调者统一维护）；Artifacts 证据目录为 `Artifacts/Tasks/M1-008/2026-09-26T00-26-39/`（脚本红绿+坏样本）、`.../2026-09-26T00-42-39+0800/`（C++ 红灯）、`.../2026-09-26T00-44-00+0800/`（C++ 绿灯）。
