## 目的

在调试 HUD（M1-028 的 F1 调试覆盖层）上增加三项命中反馈显示：双方 HP 条、实际伤害数字（0.6 s 生命周期、池上限 32、满淘汰最早）、连击计数。数据来源严格事件驱动：伤害数字/连击只来自 `UCombatComponent::OnHitConfirmed`（该事件只在 `ApplyDamage` 真实扣血 > 0 时广播），HP 条每帧从目标 `UHealthComponent` 真值读取，不做每 Tick 全场扫描。M1-028 调试覆盖层与 M0 输入提示不回归。

## 实际修改

### 新建 `Source/UEMMO/UI/DamageNumberModel.h/.cpp`（纯逻辑模型，无 World 可测）

- `FDamageNumberEntry`：{Damage（实际扣血值，来自 `FCombatHit::Damage`）、SpawnTimeSeconds（注入时钟生成时刻）、Location（`WorldHitLocation` 世界坐标，绘制时才投影）、AttackId（可选）}。
- `FDamageNumberPool`：`SetNowSeconds` 显式时钟注入（接口约定第 2 节，内部不自推进）；`Add` 先清过期再入池，池满（≥ **32**）淘汰最早（index 0），追加到尾部；`PruneExpired` 按 `Now - SpawnTime >= 0.6s`（边界含）清除；`Num()` 先清理再计数；`Clear()` 立即清空（reset 流程）。池只存数据拷贝、不存对象引用，淘汰/过期不可能产生失效引用访问。
- `FHealthBarData`：{CurrentHP, MaxHP, bAlive, bHasData}；`Set` 把 CurrentHP 钳制到 [0, MaxHP]（MaxHP>0 时），`GetRatio` 返回 [0,1] 填充率（无数据或 MaxHP<=0 返回 0，不除零）。
- `FComboCounter`：同一攻击者连续命中间隔 **< 1.5 s（可配，默认 1.5 s）** 内递增，`EvaluateCombo` 在距上次命中 ≥ 1.5 s 时读 0（边界含），下一次命中重新从 1 计；`Reset()` 清零。窗口边界语义（恰好 1.5 s 判超时）已写进头文件注释并由测试断言。

### `Source/UEMMO/PrototypeHUD.h/.cpp`（最小增量）

- 头文件新增（报告说明）：`BindDamageFeed`/`PeekDamageNumberCount`/`PeekDamageNumbers`/`PeekComboCount` 公共接口与测试接缝；私有 `RefreshDamageFeedBinding`/`UnbindDamageFeed`/`HandleHitConfirmed`/`DrawHealthBars`/`DrawDamageNumbers`/`DrawComboCounter`/`ResolveDisplayClockSeconds`/`StartDebugRepeatStrike`；成员 `DamageNumbers`、`ComboCounter`、`DamageFeedSource`（弱引用）、`DamageFeedHandle`、`DebugStrikeRepeatTimerHandle`、`LastObservedTargetHP`/`LastObservedHealth`。
- **订阅（事件驱动）**：`RefreshDamageFeedBinding` 每绘制帧（仅 F1 开启时）把 feed 绑定到**玩家**（攻击方）`GetCombat()` 的 `OnHitConfirmed`；绑定源经 M1-028 既有弱引用缓存复用（`DebugPlayer`），稳态零扫描，仅弱引用失效时重定位。`HandleHitConfirmed` 先判 `DamageFeedSource.IsValid()`（失效来源不崩不加数）再投递 `DamageNumbers.Add(Hit.Damage, ...)` 与 `ComboCounter.NotifyHit(Now)`。`UnbindDamageFeed` 只在弱引用仍有效时才 `Remove` 句柄，销毁对象永不被触碰。
- **HP 来源**：敌人（目标）条读 `DebugTarget->GetHealthComponent()` 真值（GetHealth/GetMaxHealth/IsAlive，每帧读取不算扫描——复用 M1-028 定位）；**玩家条按现状显示占位** "Player HP: n/a (no health component yet)"——M1-016 只给敌人 HealthComponent，不造假数。
- **投影方式**：伤害数字用 **World→Screen 投影**（`Canvas->Project(WorldHitLocation)`，与 M1-028 命中盒同一投影路径 + 同款背向相机点积剔除），数字随存活时间上飘（60 px/s）并淡出（alpha = 1 - age/0.6），0.6 s 后由池清除。选投影而非固定 HUD 区域：命中盒中心已有可靠投影先例且数字贴着受击点更可读。
- **绘制布局**：HP 条两行锚定**右上**（1280x720 下 x=1016，远离左上 M0 面板 y18..102 与 M1-028 面板 y108..212，任何分辨率都不遮主要角色）；连击计数锚定**左下**（"Combo x3"，combo=0 时不显示）；输入提示（左上 y18..102）完全不被遮挡。
- **reset 语义（卡面"reset清空连击/数字，HUD解绑旧目标事件"在本卡文件范围内的落地）**：模型层 `Clear()/Reset()` 已实现并被测试；HUD 层在 `DrawHealthBars` 读取目标 HP 时观测"血量回升"——伤害只能降 HP，回升只能是会话重置（ResetEnemy 恢复满血），此时清空连击与数字（`LastObservedTargetHP` 观测，目标切换时重置基线）。"HUD 解绑旧目标事件"：feed 绑定的是攻击方组件，其销毁由弱引用失效 + 下一帧重绑定覆盖，无悬挂绑定。
- **M1-028 不回归**：F1 覆盖层原逻辑一行未删，M1-035 绘制只在同一 `bCombatDebugOverlayEnabled` 分支内追加；exec 入口保留 mode 0/1/2 原语义，新增 **mode 3**（仅调试取证，永不玩法调用）：6.6 s 起每 0.6 s 一次**真实** light_01 打击（先把敌人吸附到玩家 +150 X 补偿击退，`TryStartAttack` 走真实路径），让 ~8 s 截图窗口内至少一个真实伤害数字存活——数据全部经 `OnHitConfirmed`，无任何合成数值。

### 新建 `Source/UEMMO/Tests/DamageNumberTests.cpp`（前缀 `UEMMO.Tasks.M1_035.*`，6 条，全部无 World）

1. `DamageNumbersAddExpireByInjectedClock`：3 条入池 → 3；注入时钟推进 0.59 s 存活、0.61 s 全清；清空后可复用；`Clear` 立即清空。计数不符时提前 return，不索引空池（不崩）。
2. `DamageNumbersCapThirtyTwoEvictsEarliest`：0.34 s 内投 35 条（无过期）→ 恰 32 条，最早 3 条被淘汰（断言剩余条目时刻 0.03/0.34），全池遍历求和可读（无失效访问）；再投 1 条仍 32 且次早（0.04）顶到队首。
3. `HealthBarDataTracksChangeReadable`：{100,100}→{90,100} 变化可读（ratio 1→0.9）；负值/超上限钳制；死亡标志；无数据态 ratio=0。
4. `ComboCounterIncrementsAndTimesOut`：0.5 s 间隔 3 次命中 → combo=3；距上次命中 1.49 s 仍 3、恰好 1.5 s 读 0；超时后命中重计 1；自定义 0.8 s 窗口同规则；`Reset` 清零。
5. `HitConfirmedFeedAddsExactlyOnePerAcceptedHit`（事件驱动）：HUD 绑定裸组件后广播 `OnHitConfirmed` → 池 +1，数值/位置/AttackId 为真实投递值；3 次广播 → 3 且 combo=3；无新广播 → 不新增。
6. `StaleSourceBindingReadsSafeNoCrash`：绑定 A → 命中 1；A `MarkAsGarbage` 后重绑 B（解绑陈旧源不触碰死对象）→ B 命中恰好 1 次（无陈旧双投递）；B 销毁后广播 → 弱引用判空跳过，计数不变不崩；`BindDamageFeed(nullptr)` 安全解绑陈旧源。
