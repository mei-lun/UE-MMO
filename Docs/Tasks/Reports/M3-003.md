## 目的

按接口约定第 8 节落地 `UProfileSubsystem : UGameInstanceSubsystem`：GameInstance 生命周期=跨地图保持，持有 CharacterId（NewProfile 生成唯一 FGuid）、Level 1..10、XP、基础属性公式（HP100+10×(L-1)、Attack 2×(L-1)、Defense L-1，下一级 XP=100×当前 Level、满级需求 0）、FInventoryModel 背包（M3-002 复用），以及 Equipment/PendingRewards/AppliedSettlementIds/AliveIds 占位状态。新游戏走显式 NewProfile/ResetNewGame API（本卡尚不存盘，ResetNewGame 绝不自动调用）；提供只读快照供 UI 与存档使用；不持有任何 World Actor，快照派生属性一律由公式重算，不抄 World 里临时 HP。

## 独立验收逐条对照

- **地图切换后 CharacterId 与背包不变**：`ProfileSurvivesMapSwitchAcrossSameGameInstance` —— GameInstance + WorldA 建 Profile（NewProfile→+150XP→装入 A1/A2 两件），只销毁 WorldA 并把同一 GameInstance 重绑到新建 WorldB；断言重绑后的 World 挂着同一 GameInstance、`GetSubsystem<UProfileSubsystem>()` 返回**同一实例指针**，CharacterId/Level2/XP50 不变，快照 Inventory 仍有 2 件、含 A1/A2 且插入序 A1、A2 保持。通过。
- **新游戏 ID 唯一、等级 XP 初值正确**：`NewProfileCreatesFreshInitialState` + `NewProfileMintsUniqueCharacterIdsAndResetsState` —— 初始化后无 Profile（HasProfile=false、快照默认、无代发身份、AddXP 被拒）；NewProfile 后 id 合法，Level1/XP0/派生 100/0/0/空背包；第二、三次 NewProfile 的 id 与之前全部互异且重置回 Level1/XP0/空背包。通过。
- **普通返回菜单不清空 Profile**：`MenuReturnWorldRebuildKeepsProfileAndFreshInstanceEmpty` —— 连续两次"只销毁重建 World、绝不调用 NewProfile/ResetNewGame"，每次重建后 HasProfile=true、CharacterId/Level2/XP50/1 件背包全部保持；同进程另开一个全新 GameInstance 则 HasProfile=false、无 id（数据按 GameInstance 隔离，非进程级全局静态）。通过。
- **AddXP 跨级精确断言**：`AddXPCrossesMultipleLevelsWithExactRemainder` —— +150 从 L1→L2 余 50（100×1 需求）；再 +450（余 50+450=500：付 L2 需求 200、付 L3 需求 300）单次连升两级到 L4 余 0；AddXP(0)/AddXP(-7) 拒绝且状态不变；+199 低于 L4→L5 需求 400 只入账。通过。
- **满级不再升级、XP 需求 0**：`MaxLevelStopsLevelUpsWithZeroXPRequirement` —— +4500（100+…+900）精确落位 L10 余 0；`GetNextLevelXP(10)==0`；L10 再加 1000 不升级；再加 `MAX_int32` 饱和不回绕；`GetNextLevelXP(11)/0/-5` 钳制为 0/100/100。通过。
- **派生属性公式（L1=100/0/0，L3=120/4/2）**：`DerivedStatsFollowLevelFormula` —— 静态公式逐档断言（含 L10=190/18/9、越界钳制）；快照在 NewProfile 与 +300XP（恰好 L3）两处均与公式行一致，且证明派生自公式而非任何 HealthComponent（整个子系统不接触 World Actor）；改写快照副本不影响活体状态。通过。
- **ResetNewGame 只作为显式 API**：`ResetNewGameExplicitCallResetsEverything` —— 显式调用后新唯一 CharacterId、Level1/XP0/空背包/派生 100/0/0、旧物品消失；配合地图切换/回菜单测试（其间无任何自动重置）证明它不在任何自动路径上。通过。
- **背包集成**：`InventoryTryAddVisibleThroughSnapshot` —— 经 Profile 的 `GetInventory().TryAdd` 返回 Added，同 ID 二次添加返回 Duplicate，快照 Count/Contains/槽 0 内容与 DefinitionId 全部可见；Remove 后快照归零。M3-002 语义在 Profile 表面下原样成立。通过。

## 已知限制

- **本卡尚不存盘**（接口约定第 8 节存档属 M3-013）：Profile 只活在本进程的 GameInstance 里，进程退出即丢失；因此"载入失败时 ResetNewGame 不得自动调用"目前只有 API 语义与测试背书，载入路径本身还不存在。
- **满级后 XP 仍继续累加（饱和封顶 `MAX_int32`，不回绕）**：这是对卡面"XP 只增不溢出"的字面取义；`GetNextLevelXP(10)==0` 才是"满级不再有需求"的权威信号。若 M3-008/M3-013 希望满级冻结 XP 计数，属显式语义调整，需改本卡测试。
- **公式输入越界取钳制语义**（按最近合法档 1..10 取值，非法输入造不出设计表外的属性），是本卡的设计选择；后续调参须按约定记录。
- **占位成员的诚实说明**：`PendingRewards` 暂为 `TArray<FGuid>`（M3-008 引入 FPendingReward 后会换元素类型）；`AliveIds` 在接口约定第 8 节无对应条目、卡面以"等"列出，本卡无法给它明确语义，仅按卡面保留私有占位（无消费者、随 NewProfile 清空），M3-008/M3-004 接手时可使用或删除。两者均为私有成员，不影响公共 API。
- **AddXP 返回值**：bool（本次是否发生升级），供未来 UI 钩子；若下游需要"升了几级"可扩展，不改变现有断言。
- **测试环境假设**：状态型测试经真实 `UGameInstance::Init()`（引擎 FTestWorldWrapper 同款接线）走生产子系统装配路径，`-game -nullrhi` 自动化环境验证可行；未覆盖真实 GameInstance 重建（PIE/standalone 完整启动）与手工试玩。
- 本卡无视觉变更，未跑 `Test.ps1 -Render`；测试为 `-nullrhi -game` 自动化，不涉及真实键鼠事件。
- 唯一性断言基于 `FGuid::NewGuid()` 的随机性（两次调用互异的概率为 1-2^-128），与工程既有身份生成方式一致。
