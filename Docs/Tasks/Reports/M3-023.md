## 实际修改

### 1. `Source/UEMMO/Logging/OperationLogSubsystem.h/.cpp`（新建）

`UOperationLogSubsystem : UGameInstanceSubsystem`（跨地图存活）：

- **文件与行格式**：`FPaths::ProjectSavedDir()/OperationLogs/OperationLog.log`；每行 `[HH:MM:SS.mmm][分类] 内容`（时间取可注入 now provider，默认本地 `FDateTime::Now()`）；逐条独立写盘（`FFileHelper::SaveStringToFile` + `FILEWRITE_Append | FILEWRITE_EvenIfReadOnly`，`ForceUTF8WithoutBOM`——引擎对 `ForceUTF8` 的 Append 每次都会再写 BOM，逐条追加会撒 BOM，故用无 BOM 变体），崩溃最多丢正在写的一行。
- **跨日清空**：子系统保存 `ActiveLogDate`（写入时刻的日期部分，本地时间语义与用户直觉一致）；每次写盘先比对 now provider 的日期，不同（或首写）→ `MakeDirectory` 建目录 → `IFileManager::Delete` 删旧文件 → 更新 `ActiveLogDate` → 写新头部 `=== Operation log started YYYY-MM-DD (build) ===`（build 取 `FApp::GetBuildVersion()`）。
- **可注入时钟**：`SetNowProvider(TFunction<FDateTime()>)` / `ResetNowProvider()`；测试注入假日期驱动跨日，不等待真实午夜。
- **统一 API**：`Log(FName Category, const FString&)` + 便捷 `LogInput` / `LogState` / `LogResponse`（分类固定 Input/State/Response）。
- **自动订阅**：`RegisterPlayer(APrototypeCharacter*)` 绑定玩家 `UCombatComponent` 的 `OnStarted`/`OnFinished`/`OnHitConfirmed` 与所属 World `URoomSessionSubsystem` 的 `OnRunStarted`/`OnRunEnded`；全部弱 lambda（捕获 `TWeakObjectPtr` 每次广播重判）+ 记忆 `FDelegateHandle`，`UnregisterPlayer` 摘绑；重复 Register 先摘旧绑再绑新（重持有/测试显式重注册安全）。`FindForContext`（静态）经 outer 链找 `UGameInstance`、再经 World 找，找不到返回 null——所有调用点无实例安全跳过。
- 全 ASCII；无 Player/无 World/无 Combat 时各入口优雅跳过不崩溃。

## 已知限制

1. X/Z/F1/F2/技能槽 8 键的输入绑定是 Started-only（沿用既有绑定形态），只记按下不记抬起；可区分按下/抬起的跳跃（Started/Completed）与移动轴（Triggered/Completed 的方向变化）已记两半。要补齐抬起需为每个动作新增 Completed 绑定，超出本卡最小增量，留待用户提出。
2. 移动轴只记方向变化（按下/松开/反向），幅度变化不产生日志（卡面性能规则）。
3. 无 Combat 组件时跳跃走 M0 直跳路径（`Jump()`），该次按键不产生输入行（该路径无意图缓冲，属 M1-023 既有设计；正常游戏内玩家恒有 Combat 组件）。
4. 每个新子系统实例的首写会开新"日志日"（删文件写头部）——同进程内多个 GameInstance（如自动化测试会话）各自清空后重开；生产单实例下该行为即跨日清空本身，不影响玩家使用。
5. 日志无滚动上限与多进程并发写保护：单机单进程使用符合卡面范围；若未来同日多实例并行写同一 Saved 目录会交错。
6. 本卡未包含 HUD/控制台查看日志的界面（用户未要求），日志仅供文件级查阅。
