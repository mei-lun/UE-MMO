## 实现说明

按任务卡与《UE-MMO固定视角角色接入方案》§3/§5 实现 DNFM 画面层（数据 + 帧播放 + §5.1 定位），全部为 C++ 代码层，不含真实图集资产（M6-022 负责），测试用程序内 mock manifest。

### 新增文件

1. `Source/UEMMO/Character/DNFMCharacterVisualSet.h/.cpp`
   - `UDNFMCharacterVisualSet : UPrimaryDataAsset`：页纹理软引用数组（`PageTextures`，源码不硬引资产）+ 页文件/sha256/尺寸追溯数组 + `FDNFMActionClip` 动作片段表（action_id、loop、source_ani、source_sha256、帧表）；`FDNFMVisualFrame` 逐帧携带冻结契约字段：duration_ms、page、uv_rect_px（位置+尺寸）、canvas_size_px、pivot_px（相对 uv_rect 左上、y 向下）、events（type/name）、可选逐帧 source_sha256。
   - `BuildFromManifestJson(ManifestJson, ResolvedPageTextures, OutSet, OutError)`：M6-020 manifest → DataAsset 字段的反序列化辅助（UE 5.8 Json 模块 `GetFieldUntyped/TryGetString` API）。验证优先：JSON 结构、页尺寸、uv_rect 越界、duration≤0、缺 loop、帧 index 不连续、重复 action_id、纹理数量不匹配——任一违规整体拒绝且 `OutSet` 全部清空，`OutError` 给出具体行级原因。空纹理数组构建纯数据集（测试/离线核对用）。
   - 纯采样函数（`namespace UE::UEMMO::Tasks::M6_021`，可单测、不依赖世界）：`ComputeClipTotalDurationMs`、`SampleFrameIndexByElapsedMs`（循环片按总时长取模、非循环片钳到末帧保持、空片 INDEX_NONE、全 0 时长片持末帧）、`ComputeCrossedFrameIndices`（低帧率跨帧按时间序走帧，循环回绕走 `[prev+1..末]∪[0..new]`，只回绕不空转）。
2. `Source/UEMMO/Character/DNFMCharacterVisualComponent.h/.cpp`
   - `UDNFMCharacterVisualComponent : UActorComponent`，只做画面/帧选择/定位，不建第二战斗时钟、不改任何 gameplay 状态。
   - 内部惰性创建单个 `UStaticMeshComponent`（引擎 Plane、无碰撞、不投影、绝对定位/旋转/缩放——不随 Actor yaw 转动）。
   - API：`SetVisualSet` / `SetAction(FName, EDNFMVisualLoopPolicy{UseClipDefault,ForceLoop,ForceOnce})` / `ResetVisual` / `TickVisual`（组件 PostPhysics 自 Tick，M6-023 可关组件 Tick 改为外部驱动）/ `ApplyPlacementNow` / `SetWorldScaleFromStandingHeight(头顶像素高, 目标身高cm)`（一次标定 s=目标身高cm/头顶像素，全动作共用，非法输入拒绝保持未标定；未标定不画）。
   - 事件：`OnVisualFrameEvent(ActorId, ActionName, FrameIndex, EventTag, EventName)`，帧成为当前帧时如实上报（跨帧逐帧上报、回绕重报），去重留给 M6-023；SetAction 立即置帧 0 并上报其事件。
   - 材质入口：`SetMaterialInterface`（运行时生成 MID），写参数 `PageTex`（页切换=换纹理参数）、`UVRectMin`、`UVRectSize`；无材质/无纹理时仅告警一次并继续逻辑（诚实降级，不崩）。Unlit+参数化透明模式（Masked 优先）、Nearest/Clamp/无 mip 由 M6-022 导入端设置；UV 线性映射 `pageUV = UVRectMin + quadUV * UVRectSize` 与 M6-015 已人工核验的翻页图集方向一致（图片上边朝 quad 局部 +Y=相机 Up，朝向翻转由 quad 基 X=R*Facing 一次完成）。
   - §5.1 定位（精确公式，纯函数实现于组件头文件命名空间）：脚底锚点 P = 胶囊中心 − 当前缩放后半高（跳跃随真实 Z）；平面世界朝向取相机 Right/Up（解析顺序：注入 provider → 侧视相机组件 → 玩家控制器相机 → 固定 (Pitch−18,Yaw−90) 常量）；Actor 0°/180° 只进 `Facing` 参与 `WorldPoint = P + R*Facing*(x−PivotX)*s + U*(PivotY−y)*s`；`ComputeFrameQuadTransform` 给出 quad 变换（基 X=R*Facing、Y=Up、尺寸=帧像素×s/引擎平面 100 局部单位），每 Tick 重算（脚底锚点跟随真实胶囊）。
   - 软阴影：按任务卡选项 Defer 到 M6-023（未实现，plane 不投影，见限制）。

## 给 M6-022 / M6-023 的对接说明

- M6-022（导入）：
  - 材质要求：Unlit + TwoSided + 参数化透明（Masked 优先评估），纹理 Nearest/Clamp/无 mip；材质内实现 `pageUV = UVRectMin + quadUV * UVRectSize`（quad 自带 UV [0,1]²），参数名 `PageTex`/`UVRectMin`/`UVRectSize`（常量 `UE::UEMMO::Tasks::M6_021::MaterialParam*`）。方向约定：图片上边渲染在 quad 局部 +Y（=相机 Up）一侧，与 M6-015 已人工核验截图方向一致；源素材左右朝向若需整体镜像，由 M6-020 合成端或材质一个翻转参数负责，组件不逐帧翻转。
  - 导入脚本调用 `UDNFMCharacterVisualSet::BuildFromManifestJson(manifestJson, 页纹理数组, *set, error)` 创建 DataAsset（纹理按页序传入即绑定软引用）；再把 DataAsset 软路径设到组件 `DefaultVisualSet`（或由 M6-023 presenter 显式 `SetVisualSet`）。
  - 标定数据：需要"站立帧脚底到头顶像素高 + 目标身高 cm"输入 `SetWorldScaleFromStandingHeight`（一次），或由 presenter 在 SetVisualSet 后调用。
- M6-023（战斗同步/presenter）：
  - 事件订阅：`UDNFMCharacterVisualComponent::OnVisualFrameEvent`（native 多播，参数 ActorId=Owner GetUniqueID、ActionName、FrameIndex、EventTag=manifest events[].type、EventName=events[].name）；组件只如实上报（含循环回绕重报），(ActorId, ActionId+InstanceId, EventId) 去重与 HitStop 冻结区间处理按方案 §6.2 在 presenter 做。
  - 播放驱动：默认组件自 Tick（PostPhysics）；presenter 可 `SetComponentTickEnabled(false)` 后按自己的顺序调 `TickVisual(DeltaSeconds)`；状态切换用 `SetAction(FName, LoopPolicy)`（未知 id 返回 false 不变状态），死亡等保持末帧用 `ForceOnce`（非循环片播完自动持末帧）。
  - 面向接定位不用管：`ResolveFacing` 默认读 Owner yaw（M1-029 约定），相机基读侧视相机组件；特殊需求可用 `SetFacingProvider/SetCameraBasisProvider/SetFootAnchorProvider` 注入。
  - 软阴影（接地椭圆）未实现，按卡面可选项留给 M6-023。

## 限制

- 无真实图集/材质资产：M6-022 导入前 `UEMMO.PlayerDNFMVisual=1` 时 pawn 激活画面模式但无可见平面（组件如实告警），视觉正确性（贴图方向、Masked 呈现、闪烁核对）须在 M6-022 导入后用 `Test.ps1 -Render` 实图确认。
- 组件事件走原生多播（项目惯例，同 `FOnPlayerDied`），未做 Blueprint 动态委托；M6-023 在 C++ 订阅即可。
- 单步推进超过整个循环时长（如极端低帧率一帧 >1 圈）时索引相同、不补发中间圈事件——方案 §6.2 的跨圈事件区间补发属 M6-023 去重/补帧职责。
- 软阴影 Defer 到 M6-023（见上）。
- 自动化测试未覆盖真实键盘输入；未做人工试玩（H01 类验收由用户执行）。
