## 目的

按卡面扩展近战敌人状态机：Approach → **Telegraph 0.35s** → **Attack** → **Recover 0.50s** → 回 Approach。前摇开始时锁定攻击方向、冻结位置判断，玩家走开则攻击打空；攻击实例通过敌人自身 CombatComponent 的 M1 管线发起（TryStartAttack → 有效窗 → 3D 查询 → 结算伤害），不新增任何直接扣血路径；被打断（M1-020 硬直）/死亡立即取消前摇计时，不发射延迟攻击。

## Telegraph 计时来源（卡面要求写明）

控制器注入（"Controller 注入"）：`AMeleeEnemyController::Tick` 每帧、在状态机读取之前，调用 `InjectTelegraphClockSeconds(World->GetTimeSeconds())` 把 World 游戏时钟注入为前摇/恢复倒计时的"now"（M1-020/M1-043 每帧注入时钟的同一语义；deadline 记为 `注入值 + TelegraphSeconds`，double 比较）。全程不读 wall clock / realtime timer；手动 tick 测试世界按注入 delta 精确推进，因此测试可用 0.01s 步进采样 0.34s/0.35s 边界。不依赖控制器与 Pawn 的 tick 先后（控制器自带注入，无跨 Actor 一帧滞后）。

## 独立验收逐条对照

- **0.34s 无攻击，0.35s 才启动攻击实例** → `WorldTelegraphDelaysAttackPast034s`：0.01s 步进采样，0.34s 样本（及之前全部样本）`Started==0` 且快照 Free；0.35s 截止后 Started 事件出现（实测首个 Started 落在 [0.35, 0.37] 窗口内）、AttackId=light_01、快照 Attacking、控制器处于 Attack 状态。
- **前摇时玩家 Y 移出命中范围会打空** → `WorldDodgeDuringTelegraphMisses`：前摇中把玩家 Y 平移 300cm（超出 light_01 命中盒 Y 半径 50cm），攻击实例照常启动（锁定在前摇开始，Started==1 且为 light_01），实例打完 Hits==0、玩家 HP 不变——打空由组件管线真实 3D 查询判定，无任何测试侧命中注入。
- **Recover 内重复请求无新攻击** → `WorldRecoverBlocksReattackUntil050s`：第一次攻击命中后把玩家钉在原地（攻击条件全程满足），0.01s 步进采样整个 0.50s 恢复窗：状态始终 Recover、`Started==1`；恢复结束后重新进入 Telegraph 并打出第二次攻击（`Started==2`）。
- **被打断（NotifyHitReceived→硬直，M1-020 路径）→ 前摇取消、不发射延迟攻击** → `WorldHitStunInterruptCancelsTelegraph`：前摇中按攻击管线同样的"先 ApplyDamage 后 NotifyHitReceived"顺序施加命中（StunSeconds=0.22），快照进入 HitStun；一帧内控制器退出 Telegraph、前摇表现还原；在原 0.35s 截止之后继续观察 0.36s，`Started==0`、`Hits==0`——延迟攻击不存在（0.22s 硬直也压制重攻，合法的重新前摇最早约 0.57s 后才开始，不在观察窗内）。
- **死亡 → 前摇取消、不发攻击** → `WorldDeathCancelsTelegraphWithoutAttack`：前摇中致命伤害（OnDied→SetDead，MeleeEnemy 自带接线），一帧内控制器回 Idle、快照死亡、表现还原；继续观察 0.60s，`Started==0` 且状态保持 Idle。
- （附加）**玩家不动 → 命中（HP -10，light_01）** → `WorldStationaryTargetTakesLight01Hit`：HP 100→90 恰为 light_01 基础伤害 10，HitConfirmed.AttackId=light_01，单实例恰好一次命中。
- （附加）纯函数表 `AttackConditionTableBoundaryInclusive`：攻击条件边界（160/35 恰好满足，161/36 不满足）与 Approach 驻留带一致。

## 已知限制

- SpawnGrace（M2-001 的 `SpawnGraceSeconds/CanAttack`）未接入攻击条件：本卡只交付前摇/恢复时序，出生宽限属于房间/生成任务，届时由调用方组合。
- Recover 0.50s 是控制器常量（`UEnemyDefinition` 无该字段）；Telegraph 时长来自定义数据（默认 0.35s）。
- 敌人定义没有 MeleeAttackId（或为空 id）时永不进入 Telegraph（保持 M2-002 行为）。
- Telegraph/Attack/Recover 期间敌人完全静止：不移动、不做分离推挤、不更新朝向（位置与方向按卡面冻结）。
- 攻击实例被硬直打断（无 Finished）不进入 Recover，直接回 Approach——被打断的连击后摇视为被命中本身取代。
- 打断路径重演使用合成 `FCombatHit`（Target 指向敌人、零冲量、零 hit stop、0.22s 硬直），与攻击管线在受害者侧执行的 ApplyDamage+NotifyHitReceived 序列一致；未在测试里再起一个真实玩家攻击者打敌人。
- 前摇表现为 Mesh 缩放 1.15 的最小表现（未做材质 tint/动画）；本卡无镜头/材质/模型资产变更，故未跑 Render 采集，验收以自动化为准。
- 测试通过 `SetActorLocation` 移动"玩家"来模拟走位/闪避（自动化无真实键盘事件），敌人侧零注入。
