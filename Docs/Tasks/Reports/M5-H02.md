## 根因（AI 诊断，代码实锤）

1. 初始发放（[PrototypeHUD.cpp:1775-1841](../../Source/UEMMO/PrototypeHUD.cpp)）：M3-011 staging 把
   `weapon_training`（Training Sword）发进背包并自动装备到武器槽。
2. 绑定拒绝：`Data/items.json` 无 `weapon_definition_id` 字段 →
   `EnsureWeaponCatalogsMounted` 生成的 FItemDefinition `WeaponDefinitionId = None`
   （[PrototypeCharacter.cpp:612-614](../../Source/UEMMO/PrototypeCharacter.cpp) 明确注释 "stays None"）→
   `UWeaponComponent::ApplyEquippedWeapon` 要求 `!WeaponDefinitionId.IsNone()`
   （WeaponComponent.cpp:96）→ 绑定拒绝（NoWeaponMapping），mount 保持 unbound。
3. Q 退化：`OnFireInputPressed` 的 `IsFireAuthorized()` 为 false → 走
   `SubmitSkillSlot(1)`（PrototypeCharacter.cpp:1035-1040，M1-040 技能槽语义），
   无开火无弹道。T 换弹同样静默拒（1061 行授权门）。
4. 包内自动化日志互证：M5-036 包内套件输出
   `weapon mount applied (bound=0, revision=bb1bb8e26ef73d20)`——bound=0 即
   真实游戏进程同样未绑定。包内 WeaponTrialCapture 三套件为绿是因为测试代码
   显式执行 mount+bind（生产构建器路径），与玩家实际路径（装备→绑定）不同。
