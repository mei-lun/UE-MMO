## 目的

在 M2-006/008 的房间 Session 之上补齐失败闭环：已注册玩家（`SetPlayer`）的 `PlayerDied`（M2-004 每死亡生命周期恰一次）在 **Running** 中使本局 **FailRun**（首终端胜出）并**取消生成**（当前波 CancelWave，PendingSpawns→0）+**停敌人**（本 run 登记的敌人：停追击/停攻击，不杀死不销毁）；非 Running（Idle/Cleared/Failed/Exiting）死亡一律忽略。新建 `URoomRetryService::RetryRoom`：一次调用完成"清理本 run 登记的敌人（只销毁 Session 登记表，绝不遍历世界 Character）→ Session 重置（旧 run 的 spawner 实例/死亡绑定/每 run 计数全部丢弃）→ 玩家复活（复用 M2-004 `ApplyTrainingRoomReset`：满 HP 新生命周期、去 dead 旗标、回出生点）→ `StartRoom` 新 run（新 RunId/SettlementId/Seed，旧奖励与旧计数零保留）→ `BeginWaves` 重启"；第 N 次重试与第 1 次完全一致（无委托叠加、每波恒为配置数量）。

## 实际修改（提交 65a32e74ba6d25804bfc80ca2a3f290f9fd4e8e9）

### `Source/UEMMO/Room/RoomSessionSubsystem.h/.cpp`（允许范围内的最小新增）

- **SetPlayer(APrototypeCharacter\*)**：登记死亡来源并以 `FDelegateHandle` 绑定 `PlayerDied`。同 pawn 重复登记（每次重试都会再调 SetPlayer）直接返回——**防重复绑定守卫**，无论重试多少次都只有一个死亡 handler；换 pawn 先解绑旧 handler；传 null 解绑。Deinitialize 显式解绑（世界清理不悬挂）。
- **HandlePlayerDied()**（私有）：仅 `State==Running` 生效；顺序为**先 CancelWave（仍在 Spawning 的波，未来出生清零）→ StopRunEnemies → FailRun**（OnRunEnded 最后广播，观察者读到失败后状态）；其余状态只记 Verbose 日志，不动任何状态。
- **StopRunEnemies()**（私有）：对本 run 登记的每个有效 `AMeleeEnemy`：有 Controller 则 `AController::StopMovement()`（AAIController 原生语义，M2-007 spawner 流程当前不 possess 控制器，此分支为接线预留）；`UCombatComponent::CancelCurrentAttack("RoomRunFailed")` 取消进行中的攻击实例（中断语义，无 Finished 事件）；`UCharacterMovementComponent::StopMovementImmediately()` 归零速度。**不 SetDead、不 Destroy**——停不是杀。
- **NotifyEnemyActorSpawned(FName, AActor\*)**：WaveSpawner 在 `NotifyEnemySpawned` 旁登记出生敌的本体弱引用（仅 Running 接受；随 StartRoom/ResetToIdle/Deinitialize 按 per-run 簿记清空）。
- **DestroyRunEnemyActors()**：销毁登记表中全部仍有效 Actor（含尸体，重试清场连尸体一起带走），返回销毁数；**Running 中拒绝**（不允许外部掏空进行中的 run）；`Destroy()` 不触发任何 OnDied，清理绝不产生击杀簿记或波次推进。
- **GetRunPendingSpawnCount()**：接口约定第 7 节把 PendingSpawns 列为 Session 可见状态，此处为各波 spawner PendingSpawns 之和的诊断面。
- ResetWaveOrchestration 增加 `CurrentRunEnemyActors.Empty()`（只清表不销毁——Session 本身从不销毁 Actor，销毁只经 DestroyRunEnemyActors）。

- `URoomRetryService : UObject` + 静态 `RetryRoom(World, Def, EnemyDef, Player)`：参数缺失/无 Session/Session 非 Failed/Player 为空 → 拒绝并原样不动；否则按上文顺序执行五步（DestroyRunEnemyActors → ResetToIdle → ApplyTrainingRoomReset + SetPlayer 再登记（幂等守卫）→ StartRoom → BeginWaves）。Timer 面：波次推进为注入时钟驱动、全程无 FTimerHandle，pending 归零由失败时 CancelWave 与 ResetToIdle 丢弃 spawner 双重覆盖。

### `Source/UEMMO/Tests/RoomRetryTests.cpp`（新建，前缀 `UEMMO.Tasks.M2_010.*`，6 用例）

复用 M2-006/007/008 的 FTestWorldWrapper 临时游戏 World（真实 Session）+ M2-004 世界rig（真实地板、真实 Tick、自带血池的 PrototypeCharacter）；房间定义为 room_training_01 形状（2+3 波）的手搓运行时 double（M2-007/008 先例）；推进由测试逐帧注入 Session 时钟（游戏帧驱动者的同款职责）。

1. `WaveSpawningPlayerDeathFailsRunAndStopsSpawns`：第 1 波生成中（已生 1、未生 1）玩家死亡 → Failed、end 事件恰 1（结果 Failed 且带 RunId）、PendingSpawns=0；注入推进真实 2s（120 帧真实 Tick）无新怪（SpawnedCount 恒 1、世界敌总数恒 1）；复活后再死亡（Failed 态）不产生第二个 end 事件。
2. `WaveTwoCombatPlayerDeathFailsRunAndStopsEnemies`：打完第 1 波进入第 2 波（2+3 全出生、3 活）后死亡 → Failed、PendingSpawns=0；给一个活敌推横向速度，死亡+1 帧后速度归零（停追击的可观测证据）、仍存活有效、combat 不在 Attacking；2s 内无新怪（恒 5）、无第二 end 事件。
3. `RetryDestroysRunEnemiesAndStartsFreshRun`：死亡后 RetryRoom → 旧 run 登记敌被销毁、**测试直生的未登记"外来敌"原样存活**（销毁范围只限本 run 登记表）、新 RunId/SettlementId/Seed 均更新、新波从 0 重新生成且每波恰为配置数量（2、3）、新 run 正常打穿 Cleared（结果带新 RunId、KilledCount=5）。
4. `FiveConsecutiveRetriesKeepWaveCountsExact`：初始 run + 连续 5 次 Retry 共 6 个生命周期；每次：RunId 恰 +1、SettlementId 严格递增、第 1 波恰生 2（世界总数恰 2——旧 run 5 个敌人含尸体全被清理）、第 2 波恰生 3、死亡后 Failed 且 PendingSpawns=0；全程 StartedCount/EndedCount/PlayerDiedCount 恒等于生命周期数（=6，**无任何委托叠加**）、最终 RunId=首局+5。
5. `OldRunEventsDoNotPolluteNewRun`：Retry 后新 run 中注入旧 run 的击杀通知（旧 run 第 2 波槽位 id）→ 按 M2-006 语义计数但不推进（wave 恒 0、Running、无 end 事件）；注入远未来时钟 5s（若旧 run 的等待泄漏会在此提前开第 2 波）→ 新 run 仍按自身节奏停在 wave 0；随后新 run 2+3 正常打穿 Cleared（end 事件共 2：旧失败+新清关，结果 KilledCount=6=1 旧计数+5 真击杀）。
6. `NonRunningPlayerDeathNeverFailsRun`：Idle 中死亡（状态不动、无 end 事件）+ 打穿一局 Cleared 后死亡（仍 Cleared、无第二 end 事件、结果不被覆盖、SpawnedCount 不被扰动）。

## 独立验收逐条对照

1. **失败后等待 2 秒没有新怪出现** — 用例 1（第 1 波生成中死亡：PendingSpawns 1→0，2s=120 真实帧后 SpawnedCount 恒 1、世界敌总数恒 1）与用例 2（第 2 波战斗中死亡：2s 后恒 5、总数恒 5，无第二 end 事件）。✔
2. **连重试 5 次每波仍只有配置数量** — 用例 4：6 个生命周期每轮第 1 波恰 2、第 2 波恰 3，世界总数恰 2（无上局残留），RunId 恰 +1/局、Started/Ended/PlayerDied 计数恒等生命周期数（无委托叠加）。✔
3. **旧 run 事件不导致新 run 清关或失败** — 用例 5：旧 run 击杀通知仅计数不推进、远未来注入不触发泄漏的波次推进、新 run 仍正常 2+3 Cleared；旧 run 登记敌人已被重试销毁，旧 spawner 死亡绑定随 ResetToIdle 丢弃且 RunId 过滤兜底（M2-008 用例 5 已锁）。✔
4. （卡面步骤）**Retry 只销毁本 run 登记的敌人，不遍历销毁所有 Character** — 用例 3：未登记的外来敌在 Retry 后 `IsValid` 为真，登记敌 `IsValid` 为假。✔
5. （卡面步骤）**非 Running 死亡不触发 FailRun** — 用例 6：Idle/Cleared 死亡均不动状态与事件。✔

## 已知限制

- **敌人停止的最小路径**：M2-007 spawner 流程当前不为出生敌 possess 控制器（AMeleeEnemyController 接线属后续任务），"停追击"的可观测面为速度归零（用例 2 以注入速度验证）+ 有 Controller 时的原生 `StopMovement`（预留）；"停攻击"为 `CancelCurrentAttack`（当前敌无目标本就不会主动攻击，取消为防御性中断）。未用 SetDead——停不是杀。
- **敌人 id 跨 run 复用**：spawner 的稳定 id 形如 `<EnemyId>_w<波>_s<槽>`，新 run 会再次生成同名 id（M2-008 设计即如此）。"旧 run 事件"在 Session 层的可测形态是"当前 AliveIds 之外的 id 通知"（用例 5 用旧 run 第 2 波槽位 id 避开与当前波的碰撞）；真正的旧 spawner 绑定死亡由 RunId 过滤（M2-008 已锁）+ 重试销毁来源双重覆盖。
- **游戏侧接线不在本卡**：`SetPlayer` 的初始注册与 `RetryRoom` 的真实调用方（如 M2-012 胜负 UI 的重试按钮）属后续任务；本卡交付的是 Session 侧失败语义与可测试的重试服务入口。Prototype\*/RoomTrigger\*（禁改）未动。
- **RetryRoom 仅接受 Failed 态**：Cleared 后的"再玩一局"与 Running 中的主动重开不在本卡验收范围，当前显式拒绝并留日志（如需可在后续卡扩展）。
- 测试世界为手动 Tick 临时世界：重叠派发等引擎每帧行为与本卡断言无关（无 Overlap 依赖）；玩家为无控制器 puppet，死亡经真实 HealthComponent `ApplyDamage` 触发（M2-004 同款路径）。
