## 目的

按接口约定第 2 节实现 `FCombatClock`：`Advance(DeltaSeconds, bFrozen)` 以 double 积累器把传入 Delta 折算成 60Hz 逻辑步（每步 1/60 秒）并返回本次步数；单次 Advance 最多执行 8 步，未消费积累保留到后续调用不丢失；`bFrozen==true` 返回 0 步且该 Delta 不进入积累，解冻后不补跑；负数与 NaN/Inf Delta 忽略（0 步、不积累、不崩溃）；`Reset()` 清零积累。只依赖 Core，时间全部来自显式 Delta，不读系统墙钟；仅用于战斗动作逻辑，不承诺物理确定性。

## 实际修改

- `Source/UEMMO/Combat/CombatClock.h`（新建）：`FCombatClock` 类声明，公开接口仅 `Advance`/`Reset`；私有 `AccumulatedSeconds`（double）、`StepSeconds = 1.0/60.0`、`MaxStepsPerAdvance = 8`，与接口约定签名一致。
- `Source/UEMMO/Combat/CombatClock.cpp`（新建）：实现顺序为 ①冻结分支（丢弃 Delta，返回 0，不排空积累）②无效分支（`!FMath::IsFinite || DeltaSeconds < 0.0` 忽略，返回 0，积累不动）③正常分支：累加后循环消费整数步（每步扣减 1/60），达到 8 步上限仍有剩余时经 `UE_LOG(LogTemp, Verbose, ...)` 记录限步诊断并保留剩余积累。零 Delta 是合法输入（累加 0），用于排空既有积累。
- `Source/UEMMO/Tests/CombatClockTests.cpp`（新建）：5 个纯逻辑自动化测试（`UEMMO.Tasks.M1_006.FrameRateTotals / CapAndDrain / FrozenDelta / InvalidDeltas / ResetClearsBacklog`），无 Actor/World 依赖；NaN/Inf 用 `std::numeric_limits<double>` 构造。

## 已知限制

- 冻结期间**不排空**既有积累（返回 0、积累原样保留），这是对"冻结返回 0 步"的严格读法；若后续任务希望冻结时继续消费积压，需要改约定并同步更新本测试。
- 负/NaN/Inf Delta 是完全 no-op（不积累也不排空积累）；零 Delta 是合法输入（累加 0 并排空积累）。两者语义差异在 FrozenDelta/InvalidDeltas/CapAndDrain 中均有断言锁定。
- 限步诊断走 `UE_LOG(LogTemp, Verbose, ...)`：默认详细度不可见，属长帧排障线索；模块内无现成日志类别，未为此新建类别。
- 本类只提供步数流，不维护"当前帧号"：`previous` 帧及 `FCombatWindow::Crosses` 的接线由消费方（M1-011）负责。
- 单次 Advance 因 double 舍入可能差 ±1 步，测试按"逐次加总"断言总量；30/60/120fps 三序列实测总量恰为 60，未出现偏差。
- 本卡不涉及资产与画面，无需 PrepareContent/`Test -Render`。
