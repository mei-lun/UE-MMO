## 目的

在 M3-011 只读背包列表的基础上实现装备操作界面：点击物品查看"当前 FinalStats vs 穿戴后 FinalStats"对比预览（纯函数模拟，绝不写真实 Profile），Equip/Unequip 按钮经 HUD 持有的 FEquipmentModel 执行真实穿脱并经 M3-010 的 TryEquipStatBonus 推送属性；失败显示可读原因；房间 Running 时按钮禁用（UI 层）且底层接口也拒绝（双层）；快速双击不产生重复状态。

## 接线形态（卡面允许自定，报告写明）

- `APrototypeHUD` 持有 `FEquipmentModel InventoryEquipment`（值成员）+ `FRoomResultActionGuard InventoryActionGuard`（复用 M2-012 导出的单次守卫类型，同一模式零重复）。
- 定义源：模型 `SetDefinitionCatalog(InventoryDisplayCatalog)`（当前为调试 staging 目录；正式目录资产属后续任务）。`AttachToInventory(Profile->GetInventory())` 在每次接线时重挂（NewProfile 重新赋值背包会丢弃守卫）。
- 按钮回调：widget 只广播 `EquipRequested`/`UnequipRequested`/`SelectionChanged`（弱 lambda 接 HUD，M2-012 HandleRetryRequested 模式）；HUD 持有模型、守卫与 Running 查询（`RoomSessionPtr.GetState()==Running`）。
- 行选择：行控件从纯文本块改为 `UInventoryRowButton`（UButton 子类，携带 InstanceId，动态 OnClicked 桥接到原生 `OnRowSelected` 委托——动态委托无法绑定带载荷 lambda）。
- 属性推送：操作成功后 HUD 以 `ComputeEquippedBonusFromModel()`（逐条硬化的装备求和）调 `Player->TryEquipStatBonus(...)`（唯一生产入口，含 Running 拒绝与无回血钳制），然后 `RebuildEquippedInventoryIds()` + `RefreshInventoryScreen()`（M3-011 刷新入口）+ `UpdateInventoryEquipContext()`。
- 预览数据全部来自 widget 内绑定快照副本（`BoundInstances/BoundCatalog/BoundEquippedIds/BaseStats`），widget 从不接触 Profile。
