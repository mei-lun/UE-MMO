## 目的

按接口约定第 5 节实现 `UHealthComponent : UActorComponent`：`ApplyDamage(float)` 返回实际扣血量，负数/零/非有限数（NaN/Inf）拒绝且不触发任何事件，HP 始终夹取在 [0, MaxHP]（MaxHP 默认 100），死亡事件 `OnDied` 每条死亡生命周期至多广播一次，`ResetHealth()` 恢复满血并开启新生命周期，`IsAlive()` 查询。不另建第二套血量类型。

## 实际修改

- `Source/UEMMO/Combat/HealthComponent.h`（新建）：`UCLASS` 组件，字段 `MaxHealth=100.0f`、`Health=100.0f`（UPROPERTY）与 `bDied`；API 为 `ApplyDamage` / `ResetHealth` / `IsAlive` / `GetHealth` / `GetMaxHealth` / `OnDied`。
- `Source/UEMMO/Combat/HealthComponent.cpp`（新建）：ApplyDamage 先拒绝非有限（`FMath::IsFinite`）与非正值（返回 0、无事件），再拒绝已死亡状态；接受命中时 `Health = Clamp(Health - Damage, 0, MaxHealth)`，返回实际扣血量（前值减后值，过杀只计剩余血）；HP 到 0 且未死过时置 `bDied` 并 `OnDied.Broadcast()`，保证每条生命周期至多一次。ResetHealth 置 `Health=MaxHealth`、`bDied=false`。IsAlive 为 `!bDied && Health > 0`。
- **委托形式选择**：原生 `DECLARE_MULTICAST_DELEGATE(FOnDied)`。理由：纯 C++ 测试可直接 `AddLambda` 绑定，无需 World/Actor 注册与反射开销；单参数 void 事件不需要动态多播的序列化/Blueprint 绑定能力；接口约定第 4 节允许首次实现自选委托形式。
- `Source/UEMMO/Tests/HealthTests.cpp`（新建）：6 个自动化测试（见下），`NewObject<UHealthComponent>()` 创建组件，无 World/Actor 依赖，lambda 计数器绑定 OnDied。
