## 根因（用户包日志 + 回归测试双重实证）

用户包日志唯一战斗警告：`the consumed Light chain input could not start 'light_02'; the component stays Free.`

核心机制：M8-031 把相位推导注入放在 TickCombat 的 Attacking 路径末尾，而 `ActionState != Attacking` 分支无条件提前 return——攻击一结束（Finish/跳取消/受击中断全归非 Attacking 态）推导永远不再执行，**相位冻结在最后一次攻击相位**。冻结在 CancelWindow 时 `CanStartAttack` 侥幸为真（短测试漏网原因）；冻结在 Active/Recovery 时永久为假，之后所有攻击/技能门控静默拒绝。技能"消失"同源（M5 技能是给下一击上增益，攻击起不来增益永不到账）。

次级缺陷同轮修复：teardown（Frame<0）走表撞 Active→Idle 非法；链式实时帧与滞后相位一帧差吃掉窗口首帧按键；直启拒绝无 Warning 日志、验收测试杀怪走 `ApplyDamage` 直调未走玩家攻击链。

## 交付（e707f84）

- **门控回退**：`TryStartAttack`/`TryCast` 的 `CanStartAttack()` 门控注释停用；Free 状态检查保持唯一门禁。状态机保留纯观察层（`OnPhaseChanged` 无生产监听者已核实）。
- **推导全覆盖**：注入抽为 `UCombatComponent::UpdatePhaseMachine()`，TickCombat 顶部（一切早退之前）+ Attacking 尾部双调用——非 Attacking 态每 tick 也推进相位。
- **teardown 强制归位**：`UCombatStateMachine::ForcePhase(Idle)` 绕表归位（销毁是事实不是转换）、清 `bCancelWindowOpen`；Windup 分支清残留旗标。
- **回归测试**（`Scripts/TestCombatAttackLifecycle.ps1`，filter `UEMMO.Tasks.M8_031`）：
  - `TeardownNeverLocksThePhaseMachine`：mid-Active teardown 后相位回 Idle、CanStartAttack 恢复、新攻击可起——修复前精确复现用户包症状。
  - `ChainWindowStartAcceptsTheFollowUp`：真实 QueueInput 路径，取消窗口首帧链式消费按键并起 light_02（Started==2）。
