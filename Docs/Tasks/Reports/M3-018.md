## 目的

在 M2-012 结果界面之上扩展结算奖励区（M3-008/016 的草稿与原子领取的 UI 面）：
胜利界面展示 XP50 与固定草稿物品，领取按钮走 `URewardService::ClaimPendingAtomic`
原子提交，UI 只反映返回结果；保存失败/满包保持原奖励可重试、无假完成提示；
新建待领取列表界面与菜单待领取角标。

## 独立验收逐条对照

- 同一结算反复打开界面物品不变：
  `SameSettlementReopenShowsIdenticalDraftItems`——同一 SettlementId 三次 `BeginReward`
  返回 Applied/AlreadyApplied/AlreadyApplied，二三次草稿与首次逐字段相等
  （InstanceId/RollSeed/RolledStats 不变，无重掷、无多余草稿）；三个视图模型
  RewardText/物品名/物品统计一致；Widget 三次 BindReward 渲染同一行。
  数据源是 PendingRewards 草稿快照，UI 不重 Roll。
- 满包回菜单后仍可领取：
  `InventoryFullKeepsPendingAndClaimableAcrossMenuReturn`——满包领取回答
  InventoryFull（存 0 留 1，XP 首次即授予并持久化）；奖励区显示共享满包提示；
  待领列表 1 行 + 角标 "Pending rewards: 1"；GameInstance 级 profile（菜单返回
  按构造不清理）仍持有原 InstanceId 草稿；腾出一格后重领 Claimed、XP 总增量恰为
  设计 50、角标清空、列表空。
- 保存失败有明确反馈且没有假完成提示：
  `SaveFailureShowsReadableErrorAndStaysRetryable`——注入第 3 次写失败（领取快照槽写）
  → SaveFailed、bSaveCommitted=false、存 0；纯派生与 Widget 均显示
  "Claim failed - the reward stays pending for retry. Reason: …"，不含
  "entered the inventory"；Saving 态禁用按钮、失败态重新武装 Claim 按钮可重试；
  健康存储重试领到同一预生成物品，失败+重试 XP 总增量恰为 50。

其余卡面要求：五态齐全（Unclaimed 测试 1、Saving 测试 4、Claimed 测试 1/2/4、
InventoryFull 测试 5、Failed 测试 1/4）；失败结果无奖励区（测试 3：服务拒绝 +
M2 契约 + Widget 整区折叠）；防双击复用（测试 6：Widget 首击广播一次并禁用 +
HUD 侧 FRoomResultActionGuard 首 acceptance/重复拒绝/重新武装）；待领取列表
占位与空态（测试 7：`<unknown item>`、`(no items)`、空态文案、满包提示）。

## 接线形态（报告要求说明）

- 领取链路：ResultWidget Claim 按钮（广播 `RewardClaimRequested`，可见防双击半）
  → HUD `HandleRewardClaimRequested`（`FRoomResultActionGuard` 机器防双击半，
  EnsureResultWidget 中以弱 HUD lambda 绑定）→ `URewardService::ClaimPendingAtomic(
  SettlementId, Profile, SaveService)`。Profile 经 HUD 既有 `ResolveProfileSubsystem`
  （World→GameInstance）解析；SaveService 由 HUD 惰性创建并持有
  （`UPROPERTY(Transient) TObjectPtr<UProfileSaveService>`，生产前缀 `Profile_`），
  即"经 HUD 持有引用注入"；无 SaveService 时原子领取自拒绝（RejectedNoSaveService），
  UI 显示可读失败并保持可重试（-nullrhi 等场景优雅降级）。
- 菜单角标挂接点：`APrototypeHUD::DrawHUD` 画布文本——GameFlowSubsystem 状态为
  Menu 且 PendingRewards 数 > 0 时绘制 `MakePendingRewardsBadgeText(N)`。
  纯文本函数与数量读取均可无头测试；HUD 绘制本身未做自动化断言。
