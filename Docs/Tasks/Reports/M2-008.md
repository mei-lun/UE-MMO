## 目的

在 M2-006（房间状态机/RunId）与 M2-007（单波可取消生成器）之上，实现死亡驱动的多波推进编排：当前波 `PendingSpawns=0` 且 `AliveIds=0` 才推进，下一波开始前按注入时钟等待 1.0 s；最后一波同条件达成才 Cleared（RoomCleared 恰好一次）；重复、未知、旧 RunId 的死亡事件全部幂等；任一波 StartWave 失败进入 FailRun 终态。房间数据取自 `Data/rooms.json` 的 `room_training_01`（2+3 波）。

## 实际修改（提交 ac7c70d63644668ba9c907218b1dfdee938c830a）

### 编排结构（最小侵入，全部在 Session 内驱动）

- `URoomSessionSubsystem::BeginWaves(const URoomDefinition* Definition, UEnemyDefinition* EnemyDef)`：仅在 Running 且本局尚未编排时接受；弱引用房间/敌人定义并立即启动第 0 波。卡片原文写 `BeginWaves(Def)`，实际多一个 `UEnemyDefinition*` 参数——因为 M2-007 的 `StartWave` 需要敌人定义做 EnemyId 匹配校验与 `SetEnemyDefinition`，而敌人目录（JSON→资产）属于后续任务，Session 无法自行解析。
- Session 内部持有 `UPROPERTY(Transient) TArray<TObjectPtr<UWaveSpawner>> RunWaveSpawners`：**每波一个全新 UWaveSpawner 实例**（M2-007 单波生成器天然拒绝二次 StartWave）。因此第 2 波的 PendingSpawns/AliveEnemyIds 簿记按实例从零开始，第 1 波残留计数不可能带入（M2-007 已按实例隔离，此处跨波确认）。
- 死亡驱动：`WaveSpawner` 每个出生敌人的一次性死亡绑定移除 AliveId 后调用既有 `NotifyEnemyKilled`；Session 在该路径内做推进检查 `CheckWaveProgressionAfterKill()`。
- 注入时钟：`SetSessionClockSeconds`（M2-006 既有注入时钟，无墙钟）在每次有效注入后调用私有泵 `PumpWaveProgression()`：驱动当前波 `UpdateWave`（按 0.3 s 槽位出怪）、观察 `EWaveState::Failed` 转 FailRun、等待期满（`SessionClockSeconds >= 完成时刻 + 1.0 s`）启动下一波。无编排时泵为 no-op，M2-006 既有注入行为完全不变。
- 推进判定（`CheckWaveProgressionAfterKill`）：仅当编排激活、State=Running、当前波非 Failed 且 `GetPendingSpawnCount()==0 && GetAliveEnemyIds().Num()==0` 才推进；最后一波 → `bWaveOrchestrationActive=false; MarkCleared()`（first-terminal-wins，OnRunEnded 只广播一次）；非最后一波 → 置等待标记 `NextWaveStartClockSeconds = SessionClockSeconds + 1.0`。
- 失败路径：`StartNextWave()` 内任何 `StartWave` 非 Started 结果（含 FailedNoWorld/FailedRegistration）→ `FailRun()`；泵中观察到当前波 `EWaveState::Failed`（出怪中途失败，M2-007 已清零 pending）→ `FailRun()`，杜绝失败波伪装成完成波后错误 Cleared。`BeginWaves(null/null/空 Waves)` 是请求拒绝，不制造失败终态（尚未有波失败发生）。
- 幂等三层：
  1. WaveSpawner 一次性死亡绑定（M2-007 既有，`AliveEnemyIds.RemoveSingle` 权威判定）；
  2. **新增旧 RunId 过滤**：`WaveSpawner` 在 StartWave 时捕获 `SpawnRunId`，`HandleEnemyDied` 发现 `Session->GetRunId() != SpawnRunId` 时整体吞掉死亡（旧 run 残敌在局间死亡不会计数、不会推进、不会结算新 run）；
  3. Session 侧 `TSet<FName> CurrentRunAliveEnemyIds`（由 `NotifyEnemySpawned` 记录、`NotifyEnemyKilled` 移除）：只有本 run 真正出生过的 id 才允许触发推进检查；未知/重复/陈旧 id 保持 M2-006 的计数语义（照常返回 true 并计数，见已知限制）但绝不推进波次。
- 每局重置：`StartRoom`（接受后）、`ResetToIdle`、`Deinitialize` 统一调用私有 `ResetWaveOrchestration()` 清空集合、生成器序列、计数与等待标记。
- 新增公开诊断 `GetStartedWaveCount()`。

## 独立验收逐条对照

1. **2+3 波次顺序准确，无提前结算** — 用例 `TwoWavesProgressInOrderAndClearExactlyOnce`（+`SecondWaveStartsWithFreshCounters`）：room_training_01 两波按 0→1 推进（CurrentWaveIndex 0→1，StartedWaveCount 1→2）；存活 1 只时注入时钟远超 1.0 s 仍停留在波 0；两杀后波间 0.5 s 注入不启动、恰满 1.0 s 才启动波 1；期间每个中间点 State=Running、OnRunEnded 计数 0；最后一只波 1 敌人死亡才 Cleared，OnRunEnded 恰一次、KilledCount=5、RunId 不变，重复 MarkCleared 被拒且不再广播。
2. **重复同 EnemyId 死亡不会跳过下一波** — 用例 `DuplicateEnemyDeathDoesNotSkipTheWave`：ResetHealth 触发同一敌人第二次 OnDied（绑定层吞掉，KilledCount 不变、不提前武装等待），第二只真实死亡与完整 1.0 s 等待仍不可省略，最终按 2+3 精确 Cleared。用例 `ForeignKillNotificationDoesNotAdvanceWaves` 另证从未出生的未知 id 直接调用 NotifyEnemyKilled 不推进任何波。
3. **旧 run 敌人死亡不影响新 run** — 用例 `OldRunEnemyDeathDoesNotAffectNewRun`：run 1 故意 FailRun 后留一只活敌；run 2（新 RunId）推进期间旧敌死亡 → 新 run KilledCount 保持 0、波次状态不变、无新终态事件；随后 run 2 按自身 2+3 正常 Cleared（run 2 结果 KilledCount=5、bCleared、RunId 为新值；会话共两次 end 事件：run1 失败 + run2 通过）。
4. **第 2 波不复用第 1 波残留计数** — 每波独立 UWaveSpawner 实例（结构保证）+ 用例 `SecondWaveStartsWithFreshCounters`：波 1 启动时 StartedWaveCount=2 且未结算，出生总数精确 2→3→4→5，波 1 需要自身全部 3 死才 Cleared。
5. **存活 1 只/未出生 1 只时不推进（中间态断言）** — 用例 `AliveOrUnbornEnemyBlocksProgression`：存活 1 只时注入至 +5.0 s 仍在波 0；未出生 1 只（alive=0 但 pending=1）时若实现错误会于 +1.0 s 启动下一波，测试在 11.0 s 注入断言波次仍为 0，逾期出生并击杀后才按等待推进。
6. **失败路径** — 用例 `WaveStartFailureFailsTheRun`：非法波数据（Count=2 vs 1 个出生点）被 StartWave 拒绝 → Session FailRun 终态、单次失败 end 事件、零出生零击杀；null 定义的 BeginWaves 是请求拒绝，不制造终态。

## 已知限制

- **M2-006 锁定的计数语义**：`RoomSessionTests.cpp`（不可修改）锁定"Running 期间任意 id 的 NotifyEnemyKilled 均接受并计数（含同一 id 重复调用）"。因此对从未出生的未知 id，Session 仍照常计数，M2-008 幂等保护只隔离"推进"而不改变"计数"；旧 run 残敌的死亡则经 WaveSpawner 旧 RunId 过滤彻底吞掉（连计数也不进新 run，用例 5 已断言 KilledCount=0）。两条边界在用例 3 的说明注释中明确。
- `BeginWaves` 比卡面 `BeginWaves(Def)` 多 `UEnemyDefinition*` 参数（无敌人目录任务前的最小解法）；后续目录任务落地后可由 Session 内部解析并收窄签名。
- 推进泵挂接在 `SetSessionClockSeconds`（战斗输入时钟同风格）；真实游戏帧的逐帧注入属于后续房间流程任务的接线。
- 等待从"当前波最后一只敌人死亡的时刻"起算 1.0 s（注入时钟）；两杀同帧完成时下一波于死亡时刻+1.0 s 启动。
