## 目的

落受击硬直：战斗组件新增**受害者视角**命中入口 `NotifyHitReceived(const FCombatHit&)`——接受命中后（攻击者侧成功扣血并回调）`ActionState=HitStun`，并立即 `CancelCurrentAttack("HitStun")` 停止进行中的攻击、清该实例 HitSet/待触发伤害（旧实例不再命中）；硬直计时 = 命中携带的 `Hit.StunSeconds`（0.22s 等设计值），期间拒绝 `TryStartAttack`，计时结束回 `Free`；**死亡最高优先级**：已死组件收命中无效果，致死命中直接 Dead 不进硬直（不会在硬直计时结束后复活）；新硬直取 `max(剩余, 新时长)`，不叠加；硬直期间输入缓存照常接收（M1-004 语义不变）。不做浮空倒地（M1-026）、不做死亡后的统一复位（M1-027）、不做 HitStop 执行（M1-033）。

   - **为什么必须改**：硬直时长来源是命中所对应攻击定义的 `HitStunSeconds`（接口约定第 3 节，light_01=0.22 等，`UAttackDefinition` 已有该字段）。受害者组件在收到命中时**不能也不应该**反查攻击者的目录（受害者可能没有目录，训练敌人的组件就不挂），所以时长必须随命中载荷携带——与 `HitStopSeconds` 同型同位。备选方案（受害者按收到的伤害反查攻击定义）需要伤害→定义的反向映射，复杂且不可靠，放弃。

3. `Source/UEMMO/Combat/CombatComponent.cpp`
   - **NotifyHitReceived**（受害者入口，判定顺序）：命中 Target 与 Owner 不符 → 忽略（纵深防御）；`bDead` → 直接返回（已死不硬直）；Owner 挂有 HealthComponent 且已不存活 → **致死命中**：`SetDead(true)` + `CancelCurrentAttack("Death")` + 退出可能存在的旧硬直，返回；否则 `CancelCurrentAttack("HitStun")` 打断进行中攻击（`ClearInstance` 清实例、清 HitSet、清时钟），再以 `max(剩余, 新时长)` 进硬直（新时长非有限值按 0 处理；总和 ≤ 0 不进硬直态）。计时终点 = `InputClockSeconds + StunSeconds`。
   - **CancelCurrentAttack(Reason)**：仅 Attacking 态生效（幂等）；走 `ClearInstance()`（状态回 Free、HitSet 清空、动作时钟复位），**不广播 OnFinished**——该委托的契约是"实例到达最后一帧"，打断不是自然结束（报告写明该语义选择）；Verbose 日志带 Reason。
   - **EndHitStun**：仅 HitStun 态生效，回 Free 并清计时成员。
   - **TickCombat**：新增 HitStun 分支——`InputClockSeconds >= HitStunEndTimeSeconds` 时 `EndHitStun()`，之后返回（硬直期不推进动作帧）。**硬直时钟 = 组件已有的输入游戏时钟（`SetInputClockSeconds` 显式注入）**，与 M1-014 缓冲输入寿命同一时钟源；Pause/自身 HitStop 不推进该时钟的语义由注入方负责（契约第 2 节），故硬直与输入寿命天然同节奏。动作时钟 delta 在硬直期不起作用；`bClockFrozen` 也不参与判定（冻结是动作时钟概念）。恰好 0.22s 时 `>=` 判定成立，状态即回 Free。
   - **ClearInstance**：追加清 `HitStunEndTimeSeconds`（受击路径是先 Cancel（清）后设新值，顺序安全）。
   - **攻击者侧接线**（本组件作为攻击者的 `TryApplyActiveWindowHits`）：`ApplyDamage` 成功（>0）→ 组装 `FCombatHit` 时填充 `Hit.StunSeconds = Definition->HitStunSeconds` → 对 `Target->FindComponentByClass<UCombatComponent>()` 调 `NotifyHitReceived(Hit)` → 再广播 `OnHitConfirmed`。回调在广播**之前**，保证 OnHitConfirmed 的观察者看到受害者已是硬直/死亡状态。
   - **完整接线链**：攻击者组件 TickCombat→TryApplyActiveWindowHits→QueryTargets 选目标→`UHealthComponent::ApplyDamage`（致死时 OnDied 同步广播）→成功后攻击者调 `Target` 的 `UCombatComponent::NotifyHitReceived(Hit)`（受害者状态机在此判定 死亡/硬直）→攻击者广播 OnHitConfirmed。受害者入口是唯一状态改写点；训练敌人（及任何挂 CombatComponent 的 Actor）无需自己的伤害钩子即被覆盖。HealthComponent 无受击事件（只有 OnDied）且不在本卡文件范围，故未给它加委托——致死路径由"ApplyDamage 后受害者健康池已不存活"的检查 + 训练敌人的 OnDied→SetDead 接线双保险覆盖。

## 已知限制

- **硬直时钟依赖显式注入**：计时走 `SetInputClockSeconds` 注入的输入游戏时钟，组件从不自行推进。生产侧（角色/敌人每帧注入该时钟）的接线属后续任务（M1-033/敌人 AI）；未注入时钟的 Owner 受击后不会自动恢复（自动化测试全部显式注入，已验证语义）。这与卡面"用组件输入时钟（显式注入）"的决定一致。
- `CancelCurrentAttack` 不广播 `OnFinished`（打断 ≠ 自然结束）；目前无 OnCancelled 委托——原因参数现仅进 Verbose 日志，若下游任务需要可观察的打断事件再按契约扩展（.h 改动保持克制）。
- 致死判定的来源是"NotifyHitReceived 时 Owner 的 HealthComponent 已不存活"，即依赖攻击者先 ApplyDamage 再回调的次序（现唯一伤害路径即此次序）；若未来出现绕过该次序的伤害入口，死亡接线仍由 HealthComponent.OnDied（训练敌人已绑）兜底，其他 Owner 类型需各自绑定（M1-027 统一复位/清理时再收口）。
- 训练敌人的 `Combat` 组件未挂目录、不参与攻击（本卡只用于受击状态）；`ResetEnemy` 里的 `SetDead(false)+ResetCombat` 是为保持可重玩契约的最小补充，统一复位仍归 M1-027。
- 受击硬直目前**无表现层**（无受击动画/闪烁/位移），仅状态机与拒绝规则；可见手感属后续表现任务与 H01 人工验收。
- 硬直期间 `CanAcceptMovement/CanTurn` 返回 false（沿用"Free 且存活才接受"规则，未新增逻辑），移动组件对 HitStun 的实际表现接线属移动任务。
- 测试用互殴场景对两体间 95cm 间距和加高测试体（半高 Z 95cm）有几何依赖，已用真实 QueryTargets 做前置断言；不会对生产几何产生假设。
- 环境事件：D 盘曾 100% 满；已清理 20 个 DONE worktree 的未跟踪构建产物（约 52 GB）并如实报备，未来任务重跑这些 worktree 需一次完整重建。
