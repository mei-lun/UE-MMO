## 目的

launcher 成功命中（ApplyDamage>0）后把目标打上真实物理浮空：Z 速度置为定义值 700cm/s（`Data/combat-attacks.json` launcher `launch_cm_per_s=700`）、X 击退 70cm/s×Facing（`knockback_cm_per_s=70`），Z 覆盖而非无限叠加（连续上挑 Z 恒为 700，不累加到 1400）；目标 Grounded/Rising/Falling 随实际速度更新；训练敌人保存 AirComboCount 与地面接触记录。通过 CharacterMovement/LaunchCharacter 施加，不 Teleport、不开布娃娃，墙边走碰撞。次数上限（落地前最多两次）与 Z 系数衰减（1.0/0.7）按接口约定第 6 节归 M1-025，本卡只做记录；空中受击落地→Knockdown 归 M1-026；敌人打玩家浮空归 M2。

## 实际修改

全部 C++ 纯 ASCII；完整构建（未用 Live Coding）；未改 TASKS.md、HANDOFF.md、Docs/Tasks/Handoffs/、Scripts/**、CombatHitTypes.h、CombatHitQuery.*、CombatGeometry.*、HealthComponent.*、CombatInputBuffer.h、AttackDefinition.h、Data/*.json、PrototypeCharacter.*。M1-034 的 Landed 音效接线（epoch 去重、SubmitLandingAudio、播放链路）零改动——Landed 内只在音效 epoch 逻辑之前插入一行地面接触记录（见下），M1-034 全部既有测试在回归中保持全绿。

1. `Source/UEMMO/Combat/CombatComponent.cpp`（命中施加路径增量）
   - **ApplyHitImpulse 增加浮空发射路径**：携带发射分量的命中（`Impulse.Z > 0`，即定义 `LaunchSpeed > 0`：launcher 700、aerial_01 60）对 Character 目标改走 `ACharacter::LaunchCharacter(FVector(Impulse.X, Impulse.Y, Impulse.Z), /*bXYOverride*/ false, /*bZOverride*/ true)`；其余命中（light：Z==0）保持 M1-019 的 `Movement->AddImpulse(Impulse, true)` 加法路径不变。非 Character 的模拟刚体路径不变。
   - **Z 覆盖方式（卡面要点）**：UE 5.8 的 `ACharacter::LaunchCharacter` → `UCharacterMovementComponent::Launch` 把速度存为 **PendingLaunchVelocity**（不叠加），真实运动更新经 `HandlePendingLaunch` 绝对置 `Velocity = PendingLaunchVelocity` 并切 MOVE_Falling；后一次上挑覆盖前一次的待发射值，Z 永远等于定义值 700，不可能叠成 1400。`bXYOverride=false` 保留引擎语义：X/Y 在当前速度上**加成**（地面静止目标命中后 X=70×Facing；空中连续两次上挑 X=70→140，加法；Z 严格覆盖）。`bZOverride=true` 的语义即"Z 覆盖、XY 加成"，与任务简报指定一致。
   - 浮空受击不被归零：light 的加法路径 `Velocity += (X,0,0)` 不触碰 Z，浮空目标被 light 命中后 Z 速度保持 700（测试 `LightHitOnAirborneTargetPreservesZ` 回归护栏）；CharacterMovement 自身保证地面走位输入不作用于空中目标。
   - 无 Teleport：发射路径只有速度注入与 MOVE_Falling 模式切换，无任何 SetActorLocation；飞行位移完全由带碰撞扫掠的物理积分解析，墙边自然碰撞滑动。
2. `Source/UEMMO/Combat/CombatComponent.h`（最小新增，仅注释）
   - `ApplyHitImpulse` 的文档注释更新为 M1-022 双路径语义（无任何声明/成员变化）。
3. `Source/UEMMO/Enemy/TrainingEnemy.cpp`（增量）
   - **构造函数：`GetCharacterMovement()->bRunPhysicsWithNoController = true;`**（本卡关键使能修复，见"红→绿证据"：无控制器的训练假人此前移动模式停留在 MOVE_None、AddImpulse/Launch 被引擎守卫静默丢弃——M1-019 的击退与任何上挑在真实训练 World 都不会生效；开启后假人有真实物理存在：出生受重力落稳到地面、上挑后走正常下落物理、每次落地经 ACharacter::Landed 进入 M1-034 音效与本卡地面接触记录）。
   - **LaunchCharacter override（UE 5.8 该函数为 virtual）**：先 `Super::LaunchCharacter(...)`，当 `LaunchVelocity.Z > 0` 时按 `bGroundedSinceLastLaunch` 标志计数：true（自上次地面接触以来未上挑过）→ `AirComboCount = 1`；false → `++AirComboCount`，并把标志置 false。**AirComboCount 语义**：自最近一次地面接触以来被 launcher 打上的连续次数（地面首次上挑=1、落地前空中再被上挑+1）；落地（Landed）关闭当前连段，下次上挑重新从 1 计。分类用命中时刻的记录标志而非移动模式，避免与延迟应用的发射抢时序；计数上限与 Z 系数衰减归 M1-025，本卡只记录不衰减。
   - **GetAirState()**：按需从实际速度推导（无 Tick 依赖）：`IsMovingOnGround()` → Grounded；否则 `Velocity.Z > 0` → Rising，否则 Falling（空中 Z==0 的顶点归为 Falling）。`enum class ECombatAirState : uint8 { Grounded, Rising, Falling }` 声明在 TrainingEnemy.h（接口约定第 4 节三态）。
   - **RecordGroundContact(double NowSeconds)**：公开可测入口，记录 `LastGroundedTimeSeconds`（地面接触时间）并置 `bGroundedSinceLastLaunch = true`；真实 Landed 覆写以世界时间调用它，测试以显式时间直接调用（接口约定第 2 节）。
   - **ResetEnemy 增量**：`ClearAccumulatedForces()`（丢弃残留的待发射/待冲量，可重玩房间不会复活出已重置的上挑）+ `SetMovementMode(MOVE_Walking)`（复位后记录回到 Grounded）+ `AirComboCount = 0`、`bGroundedSinceLastLaunch = true`。`LastGroundedTimeSeconds` 是真实落地事件的时间记录，复位不伪造落地、不改动。
4. `Source/UEMMO/Enemy/TrainingEnemy.h`（最小新增）
   - `ECombatAirState` 枚举；`GetAirComboCount()` / `GetLastGroundedTimeSeconds()` / `GetAirState()` / `RecordGroundContact(double)` 公开方法；`LaunchCharacter` 覆写声明（protected，经基类虚派发）；私有成员 `AirComboCount` / `bGroundedSinceLastLaunch` / `LastGroundedTimeSeconds`。
5. `Source/UEMMO/Tests/LaunchPhysicsTests.cpp`（新建，前缀 `UEMMO.Tasks.M1_022.*`，临时 World + 真 M1-020 敌人接线模式）
   - 场景：真实目录（DefaultGame.ini）+ 盒体攻击者（CombatComponent）+ 场中生成的 ATrainingEnemy（DispatchBeginPlay 一次）；断言 launcher 定义初值（duration 40、窗 [12,17)、伤害 18、击退 70、发射 700）。临时 World 永不 BeginPlay（`AreActorsInitialized` 为 false，引擎跳过 InitializeComponents/PostInitializeComponents），场景按引擎在已开局 World 的真实行为**镜像两步**：CMC `Activate()` + `SetDefaultMovementMode()`（测试内注释写明缘由）。
   - 速度断言的驱动方式：UE 5.8 中 `Launch`/`AddImpulse` 都延迟到下一次运动更新，临时 World 不积分，故用引擎自身公开应用步 `ApplyAccumulatedForces(1/60)` + `HandlePendingLaunch()`（即 PerformMovement 的实际执行顺序）驱动一次"运动更新"后再断言 Velocity——非自写物理模拟。
   - `LauncherHitLaunchesTargetAtDefinitionSpeeds`：launcher 命中（HP 100→82）后 Velocity=(70,0,700)、MOVE_Falling、GetAirState=Rising、位置逐位未变（无 Teleport）。
   - `LeftFacingLaunchMirrorsXOnly`：Facing -1 → X=-70、Z=700 不变、Y 恒 0、位置未变。
   - `RepeatedLauncherHitsOverrideZInsteadOfStacking`：两次 launcher 命中（空中第二次）→ Z 仍 700（非 1400）、X 加成 140（记录语义）。
   - `AirComboCountTracksLauncherComboUntilGroundContact`：新敌 0；地面命中→1；手动置 Z=-300（顶点模拟）→ Falling；空中命中→2；RecordGroundContact(12.5) → LastGroundedTime=12.5；再命中→1（新连段）；ResetEnemy → 0、Grounded、速度清零。
   - `LightHitOnAirborneTargetPreservesZ`：浮空目标收 light → Z 保持 700 不清零、X 加成 160（70+90）、仍非 Grounded。
   - `LauncherLaunchSpeedExceedsMinimumAirHeight`：**高度运动学证明**——发射后竖直上抛（CharacterMovement 下落物理无阻力），用目录定义的 LaunchSpeed=700 与敌人移动组件实际重力 `GetGravityZ()`=980（断言为前置条件）计算最大上升高度 h = v²/(2g) = 700²/1960 = 250cm，断言 >60cm 且等于 250±1。数值全部来自真实定义与实际重力，不硬编码结论。

## 已知限制

1. **高度为运动学证明，未做真实 World 逐帧积分与人工目击**：临时 World 不积分物理（自动化 World Tick 不可靠），采用"速度断言 + 引擎自身应用步（HandlePendingLaunch/ApplyAccumulatedForces）+ 运动学 h=v²/2g=250cm"的组合证明；真实起飞/落点的手感与目视高度留给用户试玩确认（卡面步骤"先在实际训练World验证起飞与高度"由此组合替代，属如实记录的方案取舍）。
2. **X 击退为加法（bXYOverride=false，按简报指定）**：连续上挑 X 累加（70→140），卡面未规定 X 是否覆盖，报告记录该选择；Z 严格覆盖。
3. **aerial_01（LaunchSpeed=60）同走 Z 覆盖发射路径**：规则按定义驱动（Impulse.Z>0），aerial 命中把 Z 覆盖为 60；本卡仅规约 launcher 行为，aerial 行为如实记录供后续任务校准。
4. **AirComboCount 为记录性计数**：以"自最近地面接触以来的 launcher 发射次数"为语义（标志判定，不依赖移动模式时序）；非 launcher 造成的下落（如走落台缘）不算进行中连段，其后首次上挑记 1；同帧内"先落地后命中"的极端时序由标志按命中时刻分类。上限/衰减归 M1-025。
5. **行为变化（修复）**：`bRunPhysicsWithNoController` 使假人在真实训练 World 中开始拥有活动物理——出生会受重力落稳（锚点在地面则静止）、M1-019 的 X 击退与落地 Landed（M1-034 音效）从此真实生效（此前被 MOVE_None 守卫丢弃，落地音效从未有机会触发）；全量回归确认 M1-016/M1-019/M1-020/M1-034 既有测试不受影响。
6. **同帧多源速度覆盖的引擎语义**：launcher 命中与 light 命中落在同一运动更新窗口内时，待发射速度（绝对值）会覆盖该窗口内已加的待冲量 X 分量（引擎 HandlePendingLaunch 绝对置值的固有语义）；不同攻击对同一目标的同帧连击在当前时序下罕见，如实记录。
7. **测试侧镜像引擎开局步骤**：临时 World 测试需显式 `Activate()` + `SetDefaultMovementMode()`（真实 World 由引擎原生完成）；该差异已在测试注释与本报告中说明。
