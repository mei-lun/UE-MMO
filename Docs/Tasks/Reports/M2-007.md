## 目的

交付 M2-007：`UWaveSpawner` 可取消的单波刷怪器。按 `URoomDefinition::Waves[WaveIndex]` 的 Count/SpawnLocations 生成 `AMeleeEnemy`，SpawnInterval=0.3s；AliveEnemyIds 只计本轮成功生成且注册到 Session 的敌人；生成失败明确返回失败状态；CancelWave 只停未来出生、不误杀已生成或其他场景 Actor；每个敌人死亡只结算一次并幂等。

### 实现要点

- **驱动方式**：注入时钟 + 显式 `UpdateWave(double Now)`，全程无 `FTimerHandle`/World Timer（卡面步骤原文"World Timer+Session弱引用"按协调者实现要求改为注入时钟，测试可控）。`StartWave` 只校验与登记，不出生；第一次 `UpdateWave` 锚定波开始时间，第 i 只在 anchor + i*0.3s 到期（含 1e-9 容差），一次调用可补生多只逾期敌人；非有限时间被忽略。
- **登记/计数**：`PendingSpawns` 计未出生数量（出生 -1，Cancel/失败归 0）；`AliveEnemyIds` 只计成功 `SpawnActor` 且 `Session->NotifyEnemySpawned` 接受的敌人。出生 id 形如 `melee_grunt_w0_s1`（敌种+波号+槽位，会话内稳定）。
- **死亡绑定**：出生后立即对 `UHealthComponent::OnDied` 绑定一次 lambda（仅捕获弱引用），死亡 → 从 `AliveEnemyIds` 移除 → `Session->NotifyEnemyKilled`；幂等性由 AliveIds 成员关系保证（同一敌人 ResetHealth 后第二次死亡通知被忽略，不重复计数）。
- **失败路径**：StartWave 前置校验——null 房间/敌方定义、WaveIndex 越界、Count<=0 或 Count!=SpawnLocations.Num()、非有限出生点、波 EnemyId 与传入定义不一致、无 Session、Session 非 Running、Session 无 World、Session 拒绝波登记——各自返回独立枚举，不改任何簿记。已接受波的中途失败（SpawnActor 返回 null / World 丢失 / 登记被拒）→ `EWaveState::Failed` + `PendingSpawns` 归 0 + `GetLastFailure()` 诊断；登记被拒时销毁刚出生未登记的敌人，保证"无半登记"。
- **Cancel 语义**：`CancelWave()` 把 Spawning 置为 Cancelled 并将 PendingSpawns 归 0；已生成敌人和世界中其他 Actor 一律不碰。
- **生成方式**：`World->SpawnActor<AMeleeEnemy>`，`AlwaysSpawn` 固定在配置位置（房间定义已保证出生点合法且分离），`FRotator::ZeroRotator`（面向 +X），并 `SetEnemyDefinition(EnemyDef)` 应用移动/战斗参数。
- **定义来源**：测试用 `NewObject<UEnemyDefinition>` 直接构造（数值对齐 Data/enemies.json 的 melee_grunt 源数据）传入刷怪器；刷怪器接受定义参数、不读 JSON——JSON→资产的运行时加载属后续目录任务。

## 已知限制

- 测试无法从外部强制 `World->SpawnActor` 返回 null：中途 SpawnActor-null 失败分支按防御性实现（Failed 状态 + Pending 归 0 + 诊断），红→绿证据中的失败注入覆盖为定义/会话/世界级失败，未对 SpawnActor-null 设专项用例。
- 刷怪器只出生与登记，不 Possess/不控制敌人（AMeleeEnemyController 属后续接线），也不判定 Cleared/Failed（单局结算语义留在 URoomSessionSubsystem，后续房间流程任务消费 `GetPendingSpawnCount`/`GetAliveEnemyIds` 决定"最后一波 pending=0 且 alive=0 才 Cleared"）。
- 单波器：同一实例 StartWave 恒只接受一次（之后一律 `RejectedAlreadyStarted`），多波房间需每波新建实例（UObject 开销可忽略）。
- SpawnInterval 固定 0.3s 常量，未暴露为可配置参数（卡面规定值）。
- 接口约定第 7 节把 WaveIndex/AliveIds/PendingSpawns 列在 Session 名下；按协调者实现要求，AliveIds/PendingSpawns 簿记落在 `UWaveSpawner`（避免 Session 持有 Actor 侧状态），Session 仅最小新增 WaveIndex 记录与出生登记计数，已在"实际修改"说明。
