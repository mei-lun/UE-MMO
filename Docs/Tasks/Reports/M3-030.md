## 目的

把 M3-017 建好的 GameFlowSubsystem（Menu/Loading/Room/Result/Menu 状态机）与
MapSelectWidget（单图选择菜单）挂载到生产 HUD 与启动流程，让游戏具备完整的
"菜单 → 游戏 → 结算 → 菜单"结构：开机进菜单；点进入加载刷怪房；死亡/胜利出
结算（Defeat/Victory），Retry 重开、Return 经 GameFlow ReturnToMenu 回菜单
（Profile 存活不清空，M3-017 语义）；菜单态 HUD 保留 M3-018 待领取角标与进入
按钮。

## 开机方案选择（卡面二选一，报告写明）

**选择"保留 L_CombatRoom01 + 开机显示菜单覆盖层"方案，`Config/DefaultEngine.ini`
零改动**。理由（实现成本最低）：

- GameFlowSubsystem 是 GameInstance 级子系统，`Initialize` 在任何 World 之前
  运行且初始态即 Menu——开机世界（GameDefaultMap=L_CombatRoom01）的 HUD
  BeginPlay 只要"按当前流程态呈现"就自动得到"开机进菜单"，无需新建菜单地图
  资产、无需编辑器脚本改 umap。
- 该地图本身就是刷怪房（M2-016 RoomTrigger 链所在），挂载后进入按钮的真实
  语义（EnterRoom → 绝对 travel 重载本图 → 全新房间）与既有玩法链（走位进
  触发区 → 波次 → 结算）零冲突；`Scripts/Test.ps1` smoke 与既有渲染链不受
  影响（已验证，见下）。
- 若改为"空/菜单专用小地图"需经 UE 编辑器 API 新建 umap 并重新验证 smoke 的
  移动/跳跃断言，成本显著更高且与本卡文件范围不符。

菜单专用地图切换仍不是本实现的一部分（M3-017 已知限制的原语义保留）：
ReturnToMenu 不切地图，菜单以覆盖层在当前世界重新呈现；下一次"进入"经
EnterRoom 的绝对 travel 重载出全新房间。

## 已知限制

- 生产开图（`OpenLevelBySoftObjectPtr` 绝对 travel）仍是"发起即成功"语义：
  travel 异步完成与流送期失败不可在调用点观测（M3-017 已知限制原样保留），
  真实开图效果属用户 H01 验证；自动化经注入开图器覆盖机器行为，渲染伴生套件
  在真实进程里走了一次真实 travel。
- Return 不切地图（M3-017 语义）：菜单覆盖层在当前（战后）世界重新呈现，背后
  可见残留敌人/尸体，纯外观；下一次"进入"经 travel 重载出全新房间（实测截图
  menu-again 即战后世界上的菜单）。
- Retry（败局重开）沿用 M2-012 同世界重开：M3-017 状态机无 Result→Room 转移，
  重试期间流程态停留在 Result（与重开后的会话态短暂不同步）；重试局结束仍会
  呈现结算画面、Return 仍正常落 Menu（状态机拒绝重复 NotifyRunEnded 仅记录），
  循环闭合不受影响。已在测试 4 覆盖"回菜单后立即可再进入"。
- 挂载进入目标为 room_combat_01（L_CombatRoom01）而非 M3-017 可选条目的
  TrainingArena 身份：后者无 RoomTrigger、无波次链（渲染专用图），进入它无法
  形成可玩循环。M3-017 的单图菜单列表规则、套件断言与 Widget 默认行为全部
  保留（不设覆盖时 Widget 仍请求 TrainingArena 条目）。
- 覆盖层进入按钮标签保持 M3-017 套件钉住的 "Enter"（未改中文"进入刷怪房"）；
  卡面"进入刷怪房按钮"由该按钮 + 覆盖层呈现承载，截图可证。
- 开机菜单以 UIOnly 捕获输入并显示光标：`Scripts/Test.ps1` smoke 的移动断言以
  C++ 直调驱动不受影响（已验证 success=true）；真实键盘输入与菜单交互属用户
  H01 试玩。
- 截图伴生套件在 nullrhi 全量回归下整体跳过（渲染专用证据，且其在共享开机世界
  执行真实 travel）；headless 行为由其余 4 个套件覆盖。
