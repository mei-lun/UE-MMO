## 验收对照

- **一ShotN弹丸要么全部提交要么无消耗，无半串Actor**：`CommitAllOrNothingNoHalfVolley`——3 pellet 一 reservation、一枚 ProjectileInstanceId，逐 pellet context 同源（Epoch/Source/ShotId/PelletIndex/实例 id）；SpawnFailAfter=1 的失败 commit 销毁已准备 actor（DestroyCalls≥1、无存活）、live 回提交基线 3、reservation 落 Failed 且 detail 非空。`CancelReservationLeavesNothing`——reserve+cancel 零 actor 零占位、二次 cancel 幂等、cancelled 永不能 commit、槽位可复用（fresh 2-pellet 正常 commit）、已 commit 不可 late-cancel。
- **超时/离场/旧Epoch销毁，注销数量回基线**：`TimeoutAndEpochCleanup`——commit 盖 `SetLifeSpan(LifetimeS)`（断言 2.0s，引擎 Pause 冻结世界钟）与 Movement 初速；`BeginNextWorldEpoch` 销毁全部 live actor、live=0、epoch 前进；跨代持有的 reservation commit 拒绝；旧代 shot 新代 reserve 命名拒绝 StaleEpoch；新代 shot 正常 reserve。"离场"（地图卸载/房间退出/重试）与旧 Epoch 同走 BeginNextWorldEpoch 面（接口约定 §0.5 World/Session 生命周期）。
- **Actor没有第二运动Tick叠加，生命周期不依赖源JSON**：`SingleMotionSourceNoSecondTick`——`PrimaryActorTick.bCanEverTick=false`、全 actor 恰 1 个 UProjectileMovementComponent、恰 1 个 UMovementComponent（任意种类）、Movement->UpdatedComponent==Body、Body QueryAndProbe。`ProvenanceWithoutSourceJson`——任意 revision 串逐字透传至 reservation 与每 pellet context（weapon/volley 实例 id、projectile id、launch speed）；全夹具纯值构造，服务与测试不引用任何 Data/ConfigParser/catalog 头。

## 集成决策（卡面授权范围内）

1. **预留/提交两段事务**：ReserveProjectiles 只做校验 + 铸身份（零 spawn），CommitSpawn 才经 `IProjectileSpawner` 逐 pellet 生成——失败注入面即该 seam（FTestSpawner.SpawnFailAfter）；生产 spawner 实现归 028+ 接线。
2. **StaleEpoch 双面**：reserve 面拒绝旧代 shot（旧代 volley 从不铸造 reservation）；commit 面拒绝跨代持有的 reservation（Reservation.Epoch != CurrentEpoch）。两面对应卡面"房间退出/重试清理"与"旧Epoch销毁"。
3. **生命周期归引擎**：超时 = 引擎 LifeSpan（Pause 冻结世界钟），commit 时 SetLifeSpan(LifetimeS)；服务不持自有时钟/Timer；销毁统一 BeginNextWorldEpoch。
4. **FProjectileSpawnContext 为普通 C++ 值结构**：非 USTRUCT——UHT 不接受含非反射 typedef 的 USTRUCT 字段（首版编译踩坑，见下）；上下文快照无反射需求。
5. **运动参数挂点预留但不定义策略**：ACombatProjectile 携带 LaunchSpeedCmS/MotionGravityScale 并在 spawn 时盖 Movement 初速/重力；027 不定义运动/命中策略接口（028 LinearProjectilePolicy 才冻结 029..032 的策略接口）。
