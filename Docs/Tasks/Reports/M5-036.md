### 5. 包内 FName 显示大小写缺陷修复（本卡发现并收口）

包内首跑三套件全挂：`target_reactions.json: row 1 ('normal'): PolicyId 'Normal' must be a-z 0-9 and _`，而同一份表（SHA256 与包内副本一致）在编辑器全绿。根因：**打包游戏构建不带 case-preserving FName**，`FName(*IdText)` 在名字池已有其他大小写的同词条目（引擎早期注册 'Normal'）时采用池内显示串，基于 `PolicyId.ToString()` 的语法检查把合法小写 'normal' 误拒。编辑器构建（case-preserving）不受影响，故全量回归此前无法暴露。

修复（把字符集契约移到 raw JSON 字符串层，presentation parser 已有先例）：
- `CombatDataTableParser.cpp`：`ParseDamageProfile` / `ParseAttackReaction` / `ParseTargetReaction` 在 FName 构造前对 raw `IdText` 做 `IsValidDefinitionIdSyntax` 检查，错误文本与 validator 原文一致。
- `DamageTypes.h` / `ReactionTypes.h`：三个 validator 的 FName 语法检查改为仅 `== NAME_None` 非空检查（NAME_None 显示为合法样子的 "None"，必须单独拒）。
- 测试对齐：`M5ReactionDefinitionTests`（M5_003）validator 层 uppercase/hyphen/space/65-char 断言移至 parser 层；`M5DataTableParserTests`（M5_005）补 raw 层 uppercase（damage profile + target policy）与 hyphen/space/65-char 断言；`damage_profiles holds 4 rows` 类行数断言更新为 6（含补行）。weapon/ammo/projectile validator 使用独立的 `IsValidDefinitionIdText`，不受影响。

## 限制

1. **H02 保持待用户（AI 不代签）**。任务卡验收「用户无需控制台造武器」在当前基线的可达范围：包内 WeaponTrialCapture 证明了包携带配置下的生产挂载、真输入 bind/fire 与 UI 开启；但**真键鼠试玩（H02 操作清单）必须由用户执行**，本报告不宣称已完成人工试玩。
2. **items.json 无武器映射（诚实限制）**：FTestRoomItemRow 无 weapon_definition_id 字段（M5-019 lineage，Data/items.json 三行均为 armor/charm/sword 通用定义，无 weapon→item 关联）。因此 H02 清单第 1 条「通过 UI 选装备六武器」在当前基线不可达——玩家只能经 `ApplyEquippedWeapon` 代码路径/默认绑定使用武器。映射字段接线属后续卡，H02 验收时按此口径执行。
3. **会话弹药与 D 段持久化边界**：弹药是 UWeaponComponent 会话状态（Mount 后播种），本次未接入也不声称接入任何存档；H02 试玩时武器/弹药状态不跨进程持久。
4. **FName 大小写修复的通用风险残留**：weapon/ammo/projectile validator 仍用独立 `IsValidDefinitionIdText`（FName 显示路径），其 id 词形特殊（weapon_hitscan_sample 等）撞池概率极低，本次未改动；若未来包内出现同类大小写误拒，按本卡 raw-string 模式收口。
5. **弹丸视觉尺寸**：16cm 无碰撞引擎 Cube 载体在 1280x720 截图中偏小（035 同类限制），不影响断言与亲验结论。
6. **v1 包为 FName 修复前产物**：保留在 Artifacts/Package/M5B-2026-10-09-v1 作为首包证据（其包内三套件失败记录是本次缺陷的原始证据）；交付包为 v2。
