2. `Source/UEMMO/Enemy/MeleeEnemyController.h/.cpp`（新建）
   - `AMeleeEnemyController : AAIController`，无行为树、无寻路调用：Tick 驱动最小状态机 `EMeleeEnemyState { Idle, Approach }`。
   - 目标：`TWeakObjectPtr<AActor>`，`SetTarget(AActor*)` 注入；每 Tick 经 `ResolveTarget` 解析——`TargetWeak.Get()` 为空（销毁/置灰）即失败，**不解引用失效对象**；目标带 `UCombatComponent` 且 `IsDead()` 视为失效（无组件的普通 actor 视为存活）。失效 → 回 Idle，不产生移动输入（CharacterMovement 刹车停住，不走向最后已知位置）。
   - 移动选择：**AddMovementInput**（非 MoveToLocation）——临时测试世界无导航网格，且本卡追击是直线转向；走 CharacterMovement 正常加速度/刹车/碰撞。报告写明。
   - 纯函数（声明在 Controller 头文件，供测试无世界直测）：
     - `ComputeMeleeApproachIntent(Location, Target, AttackRangeX, AlignYTolerance)`：|ΔY|>容差 → 纯 ±Y 单位向量（无论 ΔX 多大都不斜冲）；对齐后 |ΔX|>AttackRangeX → 纯 ±X；对齐且在射程内 → 零向量（停住）。边界值含容差/射程本身（≤ 语义）。
     - `ComputeMeleeSeparationAdjustment(Self, Others, MinSeparation)`：水平 XY 逐邻居累加"差额推离"（每个 <80cm 邻居贡献 (MinSeparation−距离) 大小的远离向量）；恰好重合用确定性 +X 兜底。
     - `FilterMeleeIntentByRoomBounds(Location, Intent, FBox)`：未设置（非法 FBox）→ 原样放行；在界外 → 全停；界内 → 会越界的分量清零（1cm 前瞻，另一分量保留可沿墙滑动）。
     - `ComputeMeleeFacingYaw(Intent, CurrentYaw)`：仅 X 分量转向（+X→0，−X→180），纯 Y/零保持现值——永不面向镜头或斜向目标。
   - Tick 流程：无 pawn → Idle；目标失效 → Idle（零意图返回）；Approach 中计算意图→边界过滤→`AddMovementInput`（单位意图，scale 1）；分离修正→边界过滤→`AddMovementInput(方向, clamp(量/80,0,1))`；最后 `Enemy->ApplyFacingIntent(过滤后意图)`。分离对象 = 世界内除自身外全部 `AMeleeEnemy`（TActorIterator，量级个位数，逐 Tick 查询可忽略）。
   - 参数：AttackRangeX/AlignYTolerance/MinSeparation 默认契约值 160/35/80，`SetCombatParameters`/`SetMinSeparation` 可覆盖，pawn 挂有定义时定义优先；`SetRoomBounds(FBox)` 配置矩形场地；`GetState()`/`GetLastMoveIntent()` 供测试诊断。

## 独立验收逐条对照

- **目标 Y 差 150cm 时先对齐深度，再进入 X 距离** → `ApproachIntentTableDepthFirstThenX`（ΔY=150/ΔX=500 与 ΔX=100 行均为纯 ±Y；对齐后为纯 ±X）+ `WorldDepthAlignsBeforeClosingX`：敌人出生 (ΔX=-500, ΔY=+150)，真实 Tick 下**首次进入 |ΔY|≤35 的时刻 X 距离 ≥440**（X 从未被实质性拉近，起点 500），随后才把 X 收进 160 且保持对齐。
- **已在 X 距离内且 Y 对齐 → 停止接近** → `WorldInRangeAlignedStopsApproach`：敌人出生 (ΔX=-100, ΔY=+10)，追击 3 秒位移 <5cm，且仍在射程/对齐带内（卡面允许"Idle/停住"，本实现取"保持 Approach 状态 + 零移动意图"）。
- **玩家销毁 → 回 Idle 不崩溃；玩家死亡（SetDead）→ 停止追击，不解引用失效对象** → `WorldDestroyedTargetReturnsToIdle`：先确认 Approach，`Destroy()` 后继续真实 Tick 60 帧无崩溃且状态回 Idle；`WorldDeadTargetStopsChase`：先确认 Approach，`Player->GetCombat()->SetDead(true)` 后回 Idle，且死亡后 60 帧内位移 <30cm（刹车停住，不走向最后已知位置）。解析路径只在 `TargetWeak.Get()` 非空后解引用，失效对象永不触碰。
- **3 敌同追不重叠、不穿墙** → `WorldThreeEnemiesChaseWithoutOverlapOrWallClip`：3 怪 (ΔX=-600, ΔY=+250/0/-250) 同追，真实物理房间（四面 BlockAll 墙）+ 逻辑 RoomBounds；末 120 帧（2 秒稳定窗）逐帧采样：两两水平距离最小值 ≥70cm（80cm 契约值带 10cm 容差）、全部时刻在逻辑界内（物理墙+边界过滤双保险）、全部收进玩家攻击带（X 距离 ≤260cm）。
- **朝向只反映 ±X 运动，不面对镜头** → `FacingYawOnlyReflectsXMovement`（纯函数表）+ `WorldFacingStaysOnXAxisWhileApproaching`：两怪从左右两侧夹击，全程每帧 forward 向量的 |Y|、|Z| ≤0.01（从未斜向/朝向镜头）；对齐深度阶段保持出生朝向；X 接近阶段左侧怪 forward.X>0.5、右侧怪 forward.X<−0.5。
- **超出场地边界停止** → 纯函数 `RoomBoundsFilterStopsOutsideAndBlocksWallCrossing` + `WorldOutOfBoundsEnemyDoesNotChase`：界外出生的敌人追击 2 秒位移 <5cm。

## 已知限制

- **完全重合出生的对称敌人无法靠纯位置规则分离**（分离规则是位置的函数，两怪坐标相同时收到相同兜底 +X 推力，对称性破缺需额外信息）；本卡测试与未来刷怪器保证出生点不同，兜底仅防 NaN/零除。
- "已在射程且对齐"时状态保持 Approach、移动意图为零（未回到 Idle）；卡面验收允许"Idle/停住"两种表达，攻击启动（M2-003）在此状态上挂接更自然。
- 分离对象目前包含全部其他 AMeleeEnemy（含未来阵亡者）；M2-003+ 若要求尸体不参与推挤可加死亡过滤（当前无测试需求，未扩范围）。
- 分离修正是运动输入（加速度）而非位置硬改：追击会合瞬间两两距离可能短暂低于 80cm（实测稳定窗最小值 ≥70cm，断言带 10cm 容差）；稳态在"≥80 且射程/对齐带内"附近小幅震荡。
- MeleeEnemy 未设置 CombatComponent 的 facing provider（TrainingEnemy 的 provider 服务于输入驱动的攻击起手；本卡敌人不攻击，M2-003 接攻击时再接线）。
- RoomBounds 的越界分量清零用 1cm 前瞻（单位意图）；实际防穿墙主要依赖物理墙碰撞，逻辑边界是追加保险。
- Artifacts/ 不入库（.gitignore），本轮全部时间戳证据目录保留在 worktree `Artifacts/Tasks/M2-002/` 下。
