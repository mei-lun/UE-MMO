## 步骤与结果

### 目的

把 M3-005/M3-006 建立的 Profile 最终属性（等级基数 + 装备加成行）接入本地战斗属性：进副本从 Profile 加载 FinalStats（MaxHP → HealthComponent 上限，Attack/Defense → M1-019 伤害公式入口），新 run 恢复 HP 至当前 MaxHP，普通装备变化不隐式治疗（降 MaxHP 夹取 CurrentHP、升不回血），第一版 Running 房间内穿脱装备一律拒绝。

### 实际修改

1. **伤害公式参数化**（`Source/UEMMO/Combat/CombatComponent.cpp`）：
   - 匿名命名空间的 `M1_019_ComputeHitDamage(const UAttackDefinition&)` 原用两个具名常量 `AttackPower = 0` / `Defense = 0` 占位；本卡改为显式参数 `(const UAttackDefinition& Definition, float AttackPower, float Defense)`，公式本体不变：`damage = max(1, round((baseDamage + AttackPower × coefficient) × 100 / (100 + max(0, Defense))))`。
   - 唯一调用点（命中应用管线）改为传入：攻击方 AttackPower 取 `this->CombatAttackPower`（本组件即攻击者）；防御方 Defense 取受击者身上的 `UCombatComponent::GetDefense()`。该查找原本就为 M1-026 落地恢复门存在，本卡把查找提升到循环作用域顶部、M1-020 受击者通知复用同一变量（消除 C4456 变量遮蔽）。目标没有战斗组件时 Defense 按 0，保持 M3-010 前的既有结果逐字不变（未接线的战斗体默认 0/0）。
2. **战斗属性注入入口**（`Source/UEMMO/Combat/CombatComponent.h/.cpp`，.h 新增见下）：新增 `SetCombatStats(float AttackPower, float Defense)` 与只读 `GetAttackPower()/GetDefense()`；成员 `CombatAttackPower/CombatDefense` 默认 0/0。硬化规则与 FStatCalculator 装备行一致：非有限值记 0、负值夹 0。**注意签名偏离**：卡面草拟为 `int32`，实现用 `float`——FItemStats 三字段均为 float，公式全程浮点运算，float 是无精度损失的最小形态。
3. **Health 上限变更语义**（`Source/UEMMO/Combat/HealthComponent.h/.cpp`）：新增 `SetMaxHealth(float NewMaxHealth)`——复用 M3-005 纯函数 `FStatCalculator::ClampHealthOnMaxChange`（降上限夹 CurrentHP 下探、升上限不回血），非有限/非正值拒绝。此前 HealthComponent 没有 MaxHealth 写入口，接线必须补该最小接口；死亡生命周期不动（复活仍归 `ResetHealth`）。该文件不在卡面四文件清单内，作为最小增量补充并在本报告说明。
4. **角色侧接线**（`Source/UEMMO/PrototypeCharacter.h/.cpp`，.h 新增见下）：
   - BeginPlay：经 `World->GetGameInstance()->GetSubsystem<UProfileSubsystem>()` 解析并弱持有 ProfileSubsystem（无 GameInstance 的裸测试 World 优雅降级：保持组件默认、装备入口拒绝）；随后 `ApplyProfileFinalStats()`（快照 MaxHP → `Health->SetMaxHealth`，快照 Attack/Defense → `Combat->SetCombatStats`）+ `Health->ResetHealth()`——pawn 首次装载（出生/进副本）血池以新上限满格开启。
   - **Running 拒绝接线点**：装备操作唯一入口 `TryEquipStatBonus(const FItemStats&)`——先查 Profile 存在（无 Profile 拒绝），再在调用 `Profile->SetEquippedStatBonus` **之前**检查 `RoomSessionPtr->GetState() == ERoomSessionState::Running`，Running 中拒绝并 `UE_LOG` 提示"离开房间后再操作"，拒绝时连装备行都不写入；接受则整行替换（M3-005 语义，零行即卸下）并立即重放快照（只夹取、不治疗）。
   - **新 run HP 恢复钩子**：BeginPlay 绑定 `RoomSessionSubsystem::OnRunStarted()` → `HandleRoomRunStarted()`——重放最新快照（吸收两次 run 之间的装备变化）+ `ResetHealth()` 恢复至当前 MaxHP；无 Profile 时装载为 no-op、按未变上限回满。选择 Character 侧绑定而非 RoomSessionSubsystem 内新增钩子：子系统已有 `OnRunStarted()` 委托（M2 既有 API），Character 侧绑定零改动公共接口，为最小路径。
   - Tick 未改动（沿用 M2-016 时钟注入与 Session 惰性解析）。
5. **新测试**（`Source/UEMMO/Tests/ProfileCombatStatsTests.cpp`，前缀 `UEMMO.Tasks.M3_010.*`，8 条）：复用引擎 `FTestWorldWrapper` 脚手架（GameCombatWiringTests/EnemyTelegraphTests 先例：临时 World + 真实 Tick + 真实行走物理）+ ProfileTests 的 GameInstance 装配模式——Profile 在 BeginPlay 之前经生产入口 `NewProfile()/SetEquippedStatBonus()` 配置，测试只按生产入口 `SubmitCombatInput` 攻击、`TryEquipStatBonus` 穿脱。

### 公式与 round 语义（按卡面要求实测记录）

M1-019 实现取整用 `FMath::RoundToFloat`（= `Floor(x + 0.5)`，对正数即四舍五入 half away from zero）。light_01 `baseDamage=10, AttackCoefficient=1.0`（Data/combat-attacks.json，M1-010 资产路径）：

| 场景 | 公式原始值 | 实扣 | 测试断言 |
| --- | --- | --- | --- |
| Attack 0 / Defense 0（空装） | 10 | 10 | 通过 |
| Attack 5 / Defense 0（装备 +5） | 15 | 15 | 通过（同攻击两场景差值 = 装备加成全额） |
| Attack 0 / Defense 100 | 5.0 | 5 | 通过 |
| Attack 5 / Defense 100 | 7.5 | round→8 | 通过（7.5 向上取整到 8） |

### 已知限制

1. 第一版范围：装备行整体替换入口 `TryEquipStatBonus`，尚未接 UI/物品实例到装备槽的完整流程（M3-004 装备模型到行的汇总仍属下游）；Defense 对游戏内敌人默认 0/0，敌方成长数据源未引入。
2. `SetCombatStats` 参数类型为 `float`（卡面草拟 `int32`），理由见"实际修改"第 2 条。
3. `HealthComponent::SetMaxHealth` 为卡面文件范围外的最小增量（HealthComponent 此前无上限写入口），已在上面单独说明。
4. 测试文件为本次新建，其中 `RoomEntryMatchesSnapshotAndNewRunRestoresHealth` 初稿装备行 {MaxHP:30} 与断言 150 不自洽（整行替换语义下应为 130），已修正为 {MaxHP:50}（100+50=150），断言数值未改。
5. 自动化测试不覆盖真实键盘事件与人工试玩手感；Running 拒绝的门只在 `TryEquipStatBonus` 单一入口生效（当前不存在其他装备写入口）。
