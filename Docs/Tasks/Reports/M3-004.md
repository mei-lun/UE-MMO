## 目的

按接口约定第 8 节落地纯逻辑装备模型 `FEquipmentModel`（无 World、无 UObject）：三个封闭槽位（Weapon/Armor/Accessory）到背包实例 `InstanceId` 的映射，仅引用 `FInventoryModel` 中已存储的实例。`Equip` 要求实例在传入背包且其 Definition（经 `FItemDefinitionCatalog` 解析）的槽位与目标槽一致；同槽替换只改 ID 映射、不增删任何物品；重复 Equip 同件为幂等无操作；`Unequip` 仅清映射，物品原地保留可再穿；`FInventoryModel::Remove` 对已装备实例返回新枚举 `ItemEquipped` 拒绝删除。属性求和属 M3-005 `FStatCalculator`，本卡不做加减属性。

### 循环 include 方案（本卡关键设计）

`EquipmentModel.h` → `InventoryModel.h`（传递含 `ItemDefinition.h`）单向包含；`InventoryModel` **不** include `EquipmentModel`，改为持有不透明装备谓词 `TFunction<bool(const FGuid&)>`。`FEquipmentModel::AttachToInventory` 调用 `FInventoryModel::SetEquippedPredicate` 注册 `[this](const FGuid& Id){ return IsInstanceEquipped(Id); }`——背包从此对装备类型零编译耦合，Remove 的 ItemEquipped 判定经谓词回询装备模型。注册是组合点行为：本卡测试经 `AttachToInventory` 显式接线；谓词捕获 `this`（非拥有），装备模型必须活过注册期，不得复制已 Attach 的模型；背包副本（拷贝/赋值）一律不带谓词，因此快照类分离副本永远不会回询到失效对象。

## 独立验收逐条对照

- **同 Weapon 槽替换后仍只有 1 件生效**：`SameSlotReplacementKeepsSingleActiveItem` —— Equip W1→`Equipped`，槽映射指向 W1；再 Equip W2→`Equipped`（替换成功），`GetEquippedId(Weapon)==W2`、`IsInstanceEquipped(W1)==false`、`NumEquippedSlots()==1`；背包 `Count()==2`、W1/W2 都在（替换只改映射，不删除物品）。通过。
- **重复 Equip 不叠加属性也不重复扣物品**：`DuplicateEquipIsIdempotentWithoutDoubleDeduction` —— 同槽同件第二次返回 `AlreadyEquipped`；映射仍 1 条（`NumEquippedSlots()==1`、Armor/Accessory 槽为空，无第二映射即无属性叠加载体）；背包 `Count()==2` 不变（装备本就不扣物品，重复穿不产生任何第二次扣减）；插入另一槽装备后再重复穿同件仍 `AlreadyEquipped`。`ReplacementLeavesInstancePayloadsUntouched` 进一步锁定：被替换件与新装备件的 DefinitionId/RollSeed/Level/Attack/Defense/MaxHP 逐字段全等——任何叠加或复制都会破坏全等断言。通过。
- **背包外 ID 和已装备删除都返回明确失败**：`EquipUnknownInstanceFailsWithoutMapping` —— 从未加入的 ID 与全零 guid 的 Equip 均返回 `NotInInventory`，映射 0 条、背包不变；`InventoryRemoveRejectsEquippedInstance` —— 已装备武器 `Remove` 返回 `ItemEquipped` 纯无操作（count=2、插入序不变、装备映射完好），未知 ID 仍 `NotFound`，未装备的饰品仍正常 `Removed`；Unequip 后武器可 `Removed`→重新 `TryAdd`→重新 `Equipped`，证明守卫释放后无陈旧状态。通过。
- **卡面实现步骤逐项**：不存在 ID、槽不匹配（Weapon 实例→Armor/Accessory 槽、Armor→Weapon、Charm→Weapon、目录外 ghost_item→Accessory 均返回 `SlotMismatch`）、同件重复穿戴全部先行成测（红→绿）；越界枚举槽 `InvalidSlot`、未绑目录 `MissingDefinitions` 为补充的明确失败面（`EquipRejectsInvalidSlotAndMissingCatalog`）；Unequip 清槽/物品仍在/可再穿（`UnequipClearsSlotAndAllowsReEquip`，含 NotEquipped、InvalidSlot、三槽全清）。

## 已知限制

- `Equip` 签名按卡面保持三参，定义目录经 `SetDefinitionCatalog` 绑定（非拥有指针）；未绑定返回 `MissingDefinitions` 而非跳过检查。下游装配（M3-005/M3-010/M3-012）须先 `SetDefinitionCatalog` + `AttachToInventory` 再使用。
- 未知 DefinitionId 折叠为 `SlotMismatch`（未单列枚举）：槽位约束视角下与"槽不符"同为"匹配无法确认"；若下游需要区分，扩枚举即可，不改既有语义。
- 装备守卫是按对象接线：`FInventoryModel` 拷贝/赋值刻意丢弃谓词（防快照悬垂回调）。`ApplyFreshProfileState` 的 `Inventory = FInventoryModel()` 会清守卫，未来 Profile 装配在 NewProfile/ResetNewGame 后需重新 `AttachToInventory`（与 `Equipment.Reset()` 同一生命周期时点）。
- `FEquipmentModel` 持有非拥有目录指针、`AttachToInventory` 捕获 `this`：两者都要求被引用对象活过使用期；不得复制已 Attach 的模型（本卡测试均为栈上局部对象，天然满足）。
- 不做属性求和（M3-005 `FStatCalculator` 从基础与装备完整求和）；不接线 `UProfileSubsystem`（其 `Equipment` 占位 `TMap` 保持原样，装配属后续任务）；无 UI（M3-012）、无序列化（M3-013）。
- 纯逻辑 `-nullrhi` 自动化测试，本卡无视觉变更，未跑 `Test.ps1 -Render`；不涉及真实键鼠事件。
