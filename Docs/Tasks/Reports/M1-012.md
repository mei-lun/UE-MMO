## 目的

把 J/K 按键转成战斗意图并进入 M1-011 的组件输入缓存：Character 持有 `UCombatComponent` 默认子对象，公开入口 `SubmitCombatInput(ECombatInput)` 用输入游戏时钟打 `PressedAt`、Character 级计数器从 1 递增 `Sequence`，压入组件输入缓存；Enhanced Input 映射 J=Light、K=Launcher，**只用 Started 事件**（一次按下只入 1 条，按住不重复，释放不入队）；Character Tick 驱动 `TickCombat`（M1-011 的 60Hz 推进从此在游戏里运行）；原移动/跳跃/复位不受影响。本卡不连接缓存消费与出招（K 只入队，不触发上挑；消费属 M1-014/后续）。

## 实际修改

全部 C++/注释纯 ASCII；未改 TASKS.md/HANDOFF.md/Docs/Tasks/Handoffs/Scripts 既有脚本（按协调者要求由协调者统一维护）。**未新增任何 uasset 或 .py 脚本**（见"输入映射采用方式"）。

2. `Source/UEMMO/PrototypeCharacter.cpp`
   - 构造：`Combat = CreateDefaultSubobject<UCombatComponent>(TEXT("Combat"))`（默认子对象，紧随既有 CameraRig 之后）。既有 M0/M1-029/030/031 代码（PlanarMovement、SideViewCamera、AnimBP、移动参数）未动。
   - **Catalog 接线点 = `APrototypeCharacter::BeginPlay`**：`NewObject<UAttackCatalog>(this)` 后调 `InitializeFromConfig(FText&)`（与 M1-010/M1-011 相同的 DefaultGame.ini 四引用加载路径），成功即 `Combat->InitializeFromCatalog(...)`；失败记 Warning 并继续运行（意图仍可入缓存，`TryStartAttack` 之后按其自身诊断拒绝）。BeginPlay 每实例只跑一次，无重复注入问题。
   - **输入映射采用方式：沿用 M0 现状——代码内运行时创建 IA/IMC，不引入 uasset**。检查确认现有输入本就来自 `SetupPlayerInputComponent` 里 `NewObject<UInputMappingContext>/NewObject<UInputAction>` + `Mapping->MapKey`（Content 下无 IMC/IA 资产），因此本卡在同一 IMC 上补两个 IA：`CombatLightAction`→`EKeys::J`、`CombatLauncherAction`→`EKeys::K`；既有的 AddMappingContext 调用点仍是唯一一处，无重复注册。不需要 `Scripts/Editor/create_combat_inputs.py`。
   - **绑定防重机制（三层，均在 `SetupPlayerInputComponent`/`EnsureCombatInputActions` 内）**：
     1) `Input->ClearBindingsForObject(this)` 在绑定前清掉本 pawn 已有绑定，使整个绑定块幂等（EnhancedInput 的 BindAction 重复调用会叠加委托、双触发）；
     2) `EnsureCombatInputActions()` 用 `Mapping != nullptr` 守卫，动作/映射上下文每 pawn 只构建一次，re-possess 复用同一组 IA 对象；
     3) `AddMappingContext` 前用 `Subsystem->HasMappingContext(Mapping)` 判断，绝不重复注册上下文。
   - 事件路由：仅 `BindAction(CombatLightAction, ETriggerEvent::Started, ...)` 与 Launcher 同理；Started 每次按下只触发一次 → 一次事件恰好一条意图；Triggered/Completed 不绑（按住不重复、释放不入队）。
   - `SubmitCombatInput(Action)`：`GetWorld()` 存在时取 `GetWorld()->GetTimeSeconds()`（**输入游戏时钟**：随正常游戏推进，Pause 与整段时间膨胀（HitStop）不推进；无 World 的早期测试环境回退 0.0），转调显式时钟重载。显式重载：`Sequence = NextCombatInputSequence++`（Character 级、只增），组装 `FBufferedCombatInput` 后 `Combat->QueueInput(Intent)`；Push 被拒（重复/回退 Sequence、非有限时间）只忽略。
   - **TickCombat 接线点 = `APrototypeCharacter::Tick`**：`Combat->TickCombat(DeltaSeconds)`（组件自身 60Hz 时钟从此在游戏内推进）。**不连接缓存消费**：`TryStartAttack` 仍无游戏侧调用方，K 按下只入队。
3. `Source/UEMMO/Combat/CombatComponent.h/.cpp`（**最小新增，允许范围内**）
   - `void QueueInput(FBufferedCombatInput Input)`：透传 `InputBuffer.Push(...)`；被拒（重复/回退 Sequence、非有限时间）静默忽略（接口约定 §4 本就列出 QueueInput）。
   - `bool PeekInputBuffer(FBufferedCombatInput& Out, int32 Index = 0) const`：只读窥视第 Index 条（0=最早），不消费不改序；供诊断与测试观察缓存内容。消费接线仍归 M1-014。
4. `Source/UEMMO/Combat/CombatInputBuffer.h/.cpp`（**偏离说明：禁止清单上的最小只读新增**）
   - 新增 `bool PeekAt(int32 Index, FBufferedCombatInput& Out) const`（约 10 行，纯追加、const、不改任何既有行为）。原因：协调者简报要求组件提供 `PeekInputBuffer` 且测试须断言每条的 Sequence/Action/PressedAt，但 `FCombatInputBuffer` 原本只有破坏性 `ConsumeFirst/Consume`，不读缓存条目就无法实现窥视——两处要求冲突，选择了影响面最小的只读追加并在本报告声明。回归证据：全量 86 条 UEMMO.Tasks 自动化（含 M1-004 缓存、M1-011 生命周期）全部通过。
5. `Source/UEMMO/Tests/CombatInputRoutingTests.cpp`（新建；前缀 `UEMMO.Tasks.M1_012.*`；无 World：`NewObject<APrototypeCharacter>`（同 M1-016 TrainingEnemy 的 Hermetic 模式，默认子对象齐全、无 BeginPlay）+ `NewObject<UEnhancedInputComponent>`；时间一律显式传参）
   - `SubmitLightOnceBuffersSingleIntent`：一次 `SubmitCombatInput(Light, 1.25)` → `GetSnapshot().BufferSize==1`，`PeekInputBuffer(0)` 读到 Sequence=1、Action=Light、PressedAt=1.25（>0 且精确相等）。
   - `ConsecutivePressesIncrementSequenceAndAlternateAction`：J/K/J 三次 → 缓存 3 条，逐条断言 Sequence=1/2/3、Action=Light/Launcher/Light、各自 PressedAt（10.0/10.1/10.2）。
   - `QueueInputRejectsDuplicateAndRegressingSequences`（组件公开接口）：同 Sequence 重复 Queue → 仍 1 条；回退 Sequence=0 → 仍 1 条；NaN PressedAt → 仍 1 条；新 Sequence=2 → 2 条且第 2 条为 Launcher。即"同一次输入事件不重复"的缓存会话规则在组件层可断言。
   - `RepeatedSetupDoesNotDuplicateBindingsOrIntents`：对同一 `UEnhancedInputComponent` 连续两次 `SetupPlayerInputComponent`，用 `GetActionEventBindings()` 统计 Started 绑定——数量不变且引用的是同一组 IA 对象（守卫 1/2 生效）；随后 `SubmitCombatInput(Light, 2.0)` 一次仍只 1 条且 Sequence=1（重复初始化不预入队、不抬计数器）。
   - `CombatTickKeepsBufferedIntentsConsistent`（TickCombat 接线冒烟）：入队 2 条后组件 `TickCombat(1/60)`×5，BufferSize 仍 2、最早条目原样（Free 状态推进不碰缓存，不崩溃）。
   - `GameClockOverloadRoutesSingleIntent`：无参时钟重载（无 World 回退 0.0，有限值被接受）仍恰好入队 1 条。

## 已知限制

1. 缓存消费未接线：J/K 意图只入队，`TryStartAttack` 仍仅测试/后续任务调用（出招与 150ms 寿命消费属 M1-014/后续）；本卡 K 不触发上挑，符合卡面。
2. HUD 操作提示未更新（不含 J/K 字样）：`PrototypeHUD` 不在本卡文件范围，留给后续 HUD/UX 任务。
3. PressedAt 在无 World 环境（早期测试）回退 0.0；真实游戏路径用 `GetWorld()->GetTimeSeconds()`。M1-033 接入 Pause/HitStop 停顿行为时再统一冻结语义。
4. Character 级 `NextCombatInputSequence` 在 `ResetCombat()`（清缓存会话）后不回卷：新会话的首条 Sequence 延续递增而非从 1 重来，仍满足"同会话严格递增"；跨"会话"从 1 重计的统一复位语义归 M1-027。
5. `SetupPlayerInputComponent` 移为 public（测试需驱动二次 setup）；`CombatInputBuffer::PeekAt` 为禁止清单上的最小只读偏离（见上）；两者均已声明，如需回收由协调者裁定。
6. 自动化不覆盖真实键盘事件；J/K 实际手感待 H01 用户试玩，本报告不代签。
