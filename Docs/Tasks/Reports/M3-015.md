## 已知限制

- 游戏启动流程的实际接线（GameInstance/游戏循环在启动时调用 StartupLoad 并按结果 RestoreFromSave / 显式 NewProfile）不在本卡范围：本卡交付服务入口 + 子系统恢复 API + 行为测试，生产前缀 "Profile_" 的真实启动调用点由后续接线任务落地；当前只有自动化测试在 TestSlot_ 前缀上调用。
- 写守卫是服务实例的内存状态，只约束 `UProfileSaveService` 自己的保存路径（绕过服务直接调 GameplayStatics 写同名槽不在约束内）；同一进程内守卫持续到下一次 StartupLoad 重新武装，进程重启后由下次 StartupLoad 重新评估。
- RecoveryError 的证据守卫只武装"存在但不可用"的槽文件，不含索引文件本身：索引可在下一次成功事务提交时被全新索引覆盖（M3-014"索引=唯一提交点"的既定行为）；验收要求针对的是坏槽原文件。
- 未来 schema 识别依赖旧版能从存档读出 `SchemaVersion` 字段（属性布局未变的假设）；若未来版本改变封套布局导致旧版连字段都读不出，该槽按"存在但不可加载"分类，仅在 RecoveryError 路径获得证据守卫。该边界已在实现注释声明。
- 恢复报告当前是结构化字段 + 一行 Summary 文本，未接 UE_LOG/UI 呈现（呈现方式属接线任务）；`StartupLoad` 在正常回退成功时对坏槽不武装守卫（M3-014 事务既定行为：失败槽下次保存覆盖），仅全不可用（RecoveryError）时武装证据守卫。
- 沿袭 M3-014/M3-013 限制：PayloadDigest 为 32 位 CRC（完整性校验非防篡改）；schema_version=1、MasterVolume 占位；`UProfileSaveGame`/`ProfileSerializer` 本体未改动。
