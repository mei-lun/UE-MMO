## 目的

按接口约定第 8 节落地装备栈的定义层与实例层：`FItemDefinition`（DefinitionId、DisplayName、Slot、BaseStats、IconPath、Rarity）与 `FItemInstance`（InstanceId=FGuid 持久化业务 ID、DefinitionId、RollSeed、RolledStats、Level）分离；同一定义可产生不同实例 ID；已序列化实例恢复后 ID 不变；非法槽、负属性、重复 DefinitionId 均被拒绝；提供 `Data/items.json` 三条初始物品源数据。

## 实际修改

- `Source/UEMMO/Items/ItemDefinition.h`（新建，纯值类型，无 UObject/UHT）：
  - `enum class EItemSlot : uint8 { Weapon=0, Armor=1, Accessory=2 }`（封闭枚举）。
  - `enum class EItemRarity : uint8 { Normal=1, Rare=2, Legendary=3 }`（1 普通/2 稀有/3 传说）。
  - `FItemStats`：Attack/Defense/MaxHP（float）。属性映射已在头文件注释写明：Attack → M1 伤害公式 `M1_019_ComputeHitDamage`（CombatComponent.cpp）的攻击方 `AttackPower` 入口；Defense → 同公式防守方 `Defense` 入口；MaxHP → `UHealthComponent::MaxHealth`（HealthComponent.h）上限。
  - `FItemDefinition`：DefinitionId（FName）、DisplayName（**选型 FString**，理由见"已知限制"）、Slot（EItemSlot）、BaseStats（FItemStats）、IconPath（FString 软路径，本卡为空串）、Rarity（EItemRarity）。
  - `ValidateItemDefinition(const FItemDefinition&, FString& OutErrors)`：DefinitionId 非空、Slot 属封闭枚举、三项 BaseStats 有限且 >= 0（负值/NaN 拒绝）、Rarity 属 1/2/3；错误以 "; " 连接且每条含字段名（如 `BaseStats.Attack`、`Slot`、`Rarity`）。
  - `ParseItemSlot`（大小写不敏感；空串/未知串返回 false 且不改写输出）、`IsValidItemSlot`/`IsValidItemRarity`。
  - **目录形态**：最小实现 `FItemDefinitionCatalog`（TMap<FName, FItemDefinition>），`AddDefinition(const FItemDefinition&, FString* OutError=nullptr) -> bool` 拒绝重复 DefinitionId 与空 ID（拒绝时不修改集合），`Find(FName) -> const FItemDefinition*`（未知返回 nullptr，不静默回退），`Num()`。单条字段校验职责仍在 `ValidateItemDefinition`，目录本身只管 ID 唯一性。
- `Source/UEMMO/Items/ItemInstance.h`（新建，纯值类型）：
  - `FItemInstance`：InstanceId（FGuid）、DefinitionId（FName）、RollSeed（int64=0）、RolledStats（FItemStats）、Level（int32=1）。**业务 ID 用 FGuid，不用 UE 资源路径**。
  - `MakeItemInstance(const FItemDefinition&, int64 RollSeed)` 工厂：`FGuid::NewGuid()` 新实例 ID；同一定义两次调用得到不同 InstanceId、相同 DefinitionId；RolledStats 本卡原样复制 BaseStats（种子 Roll 属 M3-007），Level=1。
  - 序列化往返（最小实现，手写键值，不走存档系统——存档属 M3-013）：`ToStringSnapshot()` 输出 `UEMMO_ITEM_INSTANCE_V1|instance_id=…|definition_id=…|roll_seed=…|level=…|attack=…|defense=…|max_hp=…`；`FromStringSnapshot(const FString&, FString* OutError=nullptr)` 严格解析：版本标签必须匹配、七个字段必须各出现一次、未知键拒绝、instance_id 必须是合法 FGuid（全零拒绝）、roll_seed/level/attack/defense/max_hp 严格数值解析（level 必须 >= 1）、解析失败不改写目标实例且错误信息含字段名。重复序列化字节一致（规范形）。
- `Data/items.json`（新建）：schema_version=1，恰好 3 条 —— weapon_training（Weapon，Attack=5）、armor_training（Armor，Defense=3）、charm_training（Accessory，MaxHP=20）；rarity 均为 1，icon_path 均为空串。属性值为设计占位，数值可在后续调参任务复验。
- `Source/UEMMO/Tests/ItemDefinitionTests.cpp`（新建）：前缀 `UEMMO.Tasks.M3_001.*`，6 个纯逻辑测试（无 World）；JSON 读取沿用 M1-008/M2-001 手写递归下降解析器模式（Json 模块未链接进 UEMMO，见文件头注释），解析器类重命名为 `FItemJsonValue`/`FItemJsonParser` 置于本任务命名空间。

## 独立验收逐条对照

- **同定义可产生不同实例 ID 但 DefinitionId 相同**：`SameDefinitionYieldsDistinctInstanceIds` —— 两次 `MakeItemInstance(weapon_training, 11)` 得到两个有效且互不相同的 FGuid，DefinitionId 均为 weapon_training；RollSeed 直传、RolledStats==BaseStats、Level=1。通过。
- **已序列化实例恢复 ID 不变**：`SnapshotRoundTripPreservesInstanceId` —— 实例（含 RollSeed=0x5DEECE66D、Level=3、非默认 RolledStats）→ 字符串 → 恢复，InstanceId/DefinitionId/RollSeed/Level/attack/defense/max_hp 全等，且恢复后再序列化字节一致；负 RollSeed 往返亦通过。通过。
- **非法槽/重复定义拒绝**：`RejectsInvalidSlotsAndNegativeStats`（枚举外 Slot=200、空槽串、未知槽串、Attack/Defense/MaxHP 负值与 NaN、Rarity=9、默认构造空 ID 均拒绝且报错含字段名，多条错误 "; " 连接）与 `CatalogRejectsDuplicateDefinitionIds`（重复 weapon_training 拒绝、集合大小不变、保留首条数据、空 ID 拒绝、不同 ID 共存）覆盖。通过。
- **items.json 三条载入校验**：`ItemsJsonLoadsThreeDefinitions` —— schema_version=1；恰好 3 条；逐条经 `MakeDefinitionFromJson` → `ValidateItemDefinition` 全过；目录 `Num()==3`（无重复）；设计值逐项核对（weapon_training Attack=5/Weapon、armor_training Defense=3/Armor、charm_training MaxHP=20/Accessory，rarity=1）；由载入定义生成的实例携带正确 DefinitionId。通过。
- **非法实例 ID**（卡面实现步骤项）：`SnapshotRejectsMalformedPayload` —— 空串/垃圾串/缺 instance_id/损坏 GUID/全零 GUID/未知键/非数值 roll_seed、level 与 level=0/外来版本标签均拒绝，错误含字段名；失败恢复不改写目标实例。通过。

## 已知限制

- **DisplayName 选型为 FString 而非 FText**：本卡手写解析与数据文件保持纯 ASCII，FString 使往返与数据填充最小化；本地化需求出现时改为 FText 是单字段改动（数据文件编码策略也需同步决定，`LoadFileToString` 对无 BOM 的 UTF-8 中文文本在 Windows 上按 ANSI 解释有乱码风险）。display_name 当前为英文占位（Training Sword/Armor/Charm），非设计定稿文案。
- `IconPath` 为纯 FString 软路径字符串且三条数据均为空；未做路径存在性校验（图标资产属后续任务）。
- `FItemDefinitionCatalog` 是最小内存集合形态（TMap 键唯一），不是 M1 `UAttackCatalog` 那样的只读资产目录；运行时目录资产、Cook 规则属后续任务。目录只负责 ID 唯一性，字段校验在 `ValidateItemDefinition`。
- 本卡 RolledStats 恒等于 BaseStats；固定种子 Roll 逻辑属 M3-007（RollSeed 仅记录）。属性到战斗公式的实际接线（把装备 Attack/Defense/MaxHP 汇入 M1_019 公式入口与 HealthComponent）属 M3 后续任务，本卡只提供映射注释。
- Snapshot 是最小键值格式，不含 DisplayName/IconPath/Rarity（实例按 DefinitionId 引用定义，实例自身不携带展示字段）；完整存档 schema（A/B 槽、Generation、校验）属 M3-013。
- 测试为纯逻辑自动化（`-nullrhi -game`），未涉及画面；本卡无视觉变更，未跑 `Test.ps1 -Render`。
- 自动化运行期间对 `UI/RoomResultWidget.cpp` 出现一条既有 C4996 弃用警告（bIsFocusable），非本任务引入，未处理。
