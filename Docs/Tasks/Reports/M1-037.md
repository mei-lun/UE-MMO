- Build 阶段即断言四招设计值（light_01=(26,[7,11),[12,24),10)、light_02=(32,[9,14),[16,29),14)、launcher=(40,[12,17),[18,32),18,launch 700)、aerial_01=(28,[6,10),[12,23),12,launch 60)）与两条链路许可（light_01 允许 light_02、light_02 允许 launcher）——排程帧全部运行时读自定义，不写死。

- 相位机（正例）：Free 起手按 Light → light_01 取消窗首帧排 Light（下一帧消费，仍在窗内）→ 确认 light_02 → 其取消窗首帧排 Launcher → 确认 launcher → 其取消窗首帧排 Jump → 观察 Free 且跳请求 ≥1 后置空中标志并排 Light → 确认 aerial_01。
- 事件记录：`OnStarted/OnFinished/OnHitConfirmed` 三个委托与每次排程/发射/落地/倒地/恢复各记一行（UE_LOG Display + 报告字符串），`AddInfo` 把完整事件顺序写进自动化报告 index.json。

三条测试：

- `FullComboScenarioTraversesAllFourAttacks`（正例）：断言恰好 5 次排程（序号 1..5）、Started = [light_01, light_02, launcher, aerial_01]、实例 ID = 1..4、Finished = [light_01, light_02, aerial_01]（launcher 被 Jump 取消，永不 Finished）、命中键去重下每实例恰一跳、伤害 = 10/14/18/12、HP 轨迹 = 90/76/58/46（终值 46）、跳请求恰 1 次、launch Z 速度 = 700、aerial 命中时目标 Z 速度 > 60（浮空追击从未被 60 下限降速）、aerial 命中时浮空周期计数 = 1、飞行峰值 ≈ 250 cm（实测 244.2）、滞空 ≈ 1.43 s（实测 1.400）、Knockdown→Recovering→Free 各一次、恢复完成清浮空周期（第 4 清零点）、AirComboCount = 2（launcher + aerial 追击）、终态双方 Free 且缓存空。
- `MissedWindowNegativeDoesNotAutoChain`（负例）：同一相位机走到 light_02 后，在其取消窗 [16,29) 关闭后的第一帧（EndFrame=29）故意按 Light，并用一次 +0.2 s 时钟步把该按键陈化（M1-023 Frame32 过期测试同款手法）——light_02 自然打完（Finished），陈化按键在首个 Free 帧被剪除（非消费）。断言 Started/Finished 只有 light_01/light_02、伤害 10/14、HP 停在 76、跳请求 0、敌人从未离地、无倒地、攻击方终态 Free 且缓存空。窗外输入没有自动连上任何后续招式。
- `TenRoundsNoStateLeak`（10 轮）：每轮先组件级复位（`UCombatComponent::ResetCombat()` + `ATrainingEnemy::ResetEnemy()`），断言轮初新鲜（HP 100、双方 Free、双方缓存 0、敌人 Grounded、AirComboCount/LauncherCycleCount=0）与 Actor 集合不变（总数与敌人数逐轮持平、敌人恒 1）；跑完整正例连招并断言与第 0 轮流完全一致（Started/Finished 流、命中与伤害轨迹、HP 轨迹、排程序号）；实例 ID 逐轮严格递增且全会话唯一（10 轮 40 个，复位不回卷计数器）。

## 已知限制

1. **攻击方不是玩家 pawn**：按任务指示复用 LaunchPhysicsTests 的命中管线模式（盒根 Actor + 真实 CombatComponent），feet 来源钉在场景基线、空中标志与跳请求为注入桩。因此场景不含 M1-033 命中停顿（双方均无演示组件，时间线是纯净 60 Hz 帧栅格）；缓存起手按 M1-021 既有语义携带存储朝向 0（几何等价 +1，冲击 X 为 0）。
2. **复位用组件级组合**：`UTrainingResetService::RegisterPlayer` 只接受 `APrototypeCharacter`，本场景不生成玩家 pawn，故采用任务卡明确允许的组件级 `ResetCombat + ResetEnemy`。这两个调用正是 `ResetTrainingSession` 对每个参与者执行的全部条目（TrainingResetService.cpp 阶段一/二），复位语义等价；服务自身的幂等/注册表行为已由 M1-027 套件覆盖。
3. **敌人飞行是运动学积分**：临时 World 从不运行物理，pending-velocity 两步是真实引擎入口，之后的竖直积分为测试侧半隐式欧拉（实测峰值 244.2 cm 对连续解 250 cm、滞空 1.400 s 对 1.429 s，离散误差在断言容差内）；落地经真实 `NotifyLanded` 走 M1-026 全流程。
4. **负例的陈化手法**：窗外按键若不陈化，会在攻击自然结束后被 M1-021 的 Free 起手当作新 light_01 消费（这是 Free 起手语义，不是取消窗链）；为干净证明"不自动衔接"，负例按 M1-023 Frame32 过期测试同款用一次 +0.2 s 时钟步使按键过期后被剪除。
5. 自动化不覆盖真实键盘事件；本卡未触碰画面资源，无需 Render 采集。
