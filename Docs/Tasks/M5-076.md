# M5-076 · 包内既有测试失败的根治

- 前置：M5-074；预计 30–60 分钟。M5-074 固定包全量门禁暴露的两个**链外既有**问题在本卡根治，删除 TestPackage.ps1 中对应的临时豁免条目。
- 背景：2026-10-25 包内全量套件（自 2026-10-06 后首次运行）发现：
  1. `UEMMO.Tasks.M5_004.AmmoTypeValidation` / `ProjectileDefinitionValidation` 的大写 ID 拒绝断言依赖 FName 回显大小写。FName 大小写不敏感且共享显示名池：包内 cooked 内容预先注入小写生产 ID（如 `ammo_cell`），`FName("AMMO_CELL").ToString()` 回显小写，被测拒绝不再发生。属测试断言对 FName 池状态的隐式依赖，非游戏缺陷（生产数据全小写）。
  2. `UEMMO.Tasks.M5_009.SavedAssetsLoadFromDiskInFreshProcess` 校验仓库工作树 `Content/UEMMO/Combat/Data/*.uasset` 的磁盘文件存在性；包内 Content 在 pak 中，必然失败。属 dev-only 校验器类别。
- 实现：1) 把 M5_004 的大写/小写往返断言改为不依赖名称池状态的写法（如直接校验 `IsValidDefinitionIdText` 对显式字符串的行为，或在断言前显式构造全新未池化名称并记录限制）；编辑器与包内行为一致后，从 `ExpectedInPackageFailures` 删除两个条目。2) 为 M5_009 增加与 M5-074 相同的包内显式跳过守卫（FileExists 检测 + AddInfo 说明），从 `DevOnlySourceJsonFilter` 删除 `M5_009.` 条目。两项均在编辑器与包内双环境验证。
- 验收：包内全量套件这两个家族不再出现在任何豁免清单，`TestPackage.ps1 -IncludeRoomScenario` 通过且失败名单不含它们；编辑器定向套件保持全绿。
- 命令：Build；`TestAutomation.ps1 -Filter "UEMMO.Tasks.M5_004" -TaskId M5-076`；`TestAutomation.ps1 -Filter "UEMMO.Tasks.M5_009" -TaskId M5-076`；`Package.ps1`；`TestPackage.ps1 -IncludeRoomScenario -TaskId M5-076`。
- 报告 `Docs/Tasks/Reports/M5-076.md`；证据 `Artifacts/Tasks/M5-076/<时间戳>`。
