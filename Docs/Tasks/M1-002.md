# M1-002 · 建立按任务筛选的自动化测试入口

> 任务卡；进度以根目录 TASKS.md 对应行为准。

## 边界

- 前置任务：M1-001。
- 粒度：一次只交付本卡描述的行为；通常以 20–60 分钟实现工作为目标，不承诺运行耗时。
- 必留报告：`Docs/Tasks/Reports/M1-002.md`。
- 原始证据目录：`Artifacts/Tasks/M1-002/<本次时间戳>`（时间戳使用本机当前时间，不字面创建尖括号）。

## 文件范围

- `Scripts/TestAutomation.ps1`。
- `Scripts/Common.ps1`。
- `Source/UEMMO/Tests/AutomationHarnessTests.cpp`。

## 输入、输出与约定

新增 TestAutomation.ps1 -Filter <测试前缀> -TaskId <ID>，使用 Common.ps1 的 UE 进程封装；每次输出到 Artifacts/Tasks/<ID>/<timestamp>，不修改现有运动测试。

## 实现步骤

- [ ] 先用一个不存在的测试前缀验证必须失败，不能把零测试记为成功
- [ ] 建立 UE Automation 测试 UEMMO.Tasks.M1_002.Harness，断言加载的 UEMMO 游戏模块存在
- [ ] 读取 UE 当前导出报告结构，实现匹配数>0、通过数=匹配数、失败数=0、未完成数=0和报告新鲜度检查
- [ ] 保留 600 秒超时；导出失败、进程失败、没有报告都返回非零；测试夹具中的假报告只测试解析器不能代替 UE 执行

## 独立验收

- [ ] 真实 Harness 运行成功且测试数至少 1
- [ ] 不存在的前缀运行返回非零，报告明确 zero_tests
- [ ] 对解析器输入失败、未完成、过期三种报告样本全部拒绝；报告结构差异有明确错误

## 验证入口

Build.ps1 后运行新 TestAutomation.ps1 -Filter UEMMO.Tasks.M1_002 -TaskId M1-002；再运行一个不存在的过滤器并检查非零退出码。仅本卡在创建此入口。

- 先读仓库根目录 `TASKS.md`、`AGENTS.md`、`Docs/Tasks/执行与交接规则.md`，确认本项依赖全部 `DONE`。
- 在总表登记本人和领取时间为 `IN_PROGRESS`；同一工作目录同时只能有一项进行中。
- 以下复选框是验收清单模板，**任务状态只写总表**，实际执行结果写 `Docs/Tasks/Reports/M1-002.md`。
- 不扩大为整个子系统。预计超过 90 分钟实现工作（不含首次编译/下载等待）时，先按规则拆分新子任务，保留旧 ID 为 `SUPERSEDED` 并更新下游依赖。
- 新行为有先失败后通过的证据；不要为简单文案机械补测试。不能执行验证时用 `BLOCKED`，不能用 `DONE`。
