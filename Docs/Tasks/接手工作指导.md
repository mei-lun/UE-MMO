### 4.1 开工前（尚未领取）

在仓库根目录用 Windows PowerShell，命令前加 `rtk proxy`：


实现先作独立 Git 提交；用 `git show --stat` 和 `git diff --cached --name-only` 核对提交仅包含本项。不要顺手提交其他人修改；`git commit --only -- <本卡文件>` 可避免已暂存的不相关文件被带入。**不自动推送**。

### 4.4 完成报告、任务板与交接：文档填写顺序

以下顺序是项目硬约定，不能先标 DONE 再补测试：

1. **实现提交后**取得真实 `git rev-parse HEAD`，把该 SHA 写进 `Docs/Tasks/Reports/<ID>.md` 的 `Implementation-Revision`。报告同时列实际修改、每条验收命令/退出码、JSON 的 matched/failed/incomplete/success、日志和截图观察、未通过项。全部通过才写精确字段 `Verification: PASS`。
2. **报告已写完**后运行 `Scripts/UpdateTaskStatus.ps1 -Id <ID> -Status DONE -Owner ... -Report ...`，使 `TASKS.md` 该行变 DONE；再运行 `Scripts/CheckTaskBoard.ps1 -Json` 确认 valid=true 和 0 个未知错误。
3. **提交任务报告和总表**，避免报告引用尚未存在的未来提交 SHA。每完成 1 项立即做这一步，不能等三项一起补。
4. 累计完成 **3 项**，或未满 3 项但准备退出时，更新 `HANDOFF.md`，另保存 `Docs/Tasks/Handoffs/<日期>-<Owner>.md`；写清本轮新增 DONE 数与 ID、起止提交、分支/工作区、验证证据、限制、下一任务。里程碑验收实际通过时再更新 `Docs/05-验证记录.md`。
5. 最后再次运行 CheckTaskBoard；若卡只做了一部分或验证失败，标 `PAUSED`/`BLOCKED` 并在报告写清已做和剩余步骤，不得为好看标 DONE。人工 `M5-H02` 只等用户真实试玩认可。

上述过程是“任务卡定义工作 → 任务报告记录事实 → TASKS.md 标状态 → HANDOFF 总结批次”；设计和计划文档只提供目标/方法，不能代替任何实际报告。
