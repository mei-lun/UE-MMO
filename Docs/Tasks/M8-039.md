  回退项，前置=门控读实时事实而非滞后相位）。

## 背景根因（M8-034 注记的重启用前置）

M8-031 门控读**存储相位**（上一 tick 末推导），而链式判定用**实时 CurrentFrame**——窗口首帧
实时帧已入窗、相位仍是 Active → 门拒且按键已被消费；Active 段 teardown 后存储相位冻结
（M8-034 已修推导覆盖，但存储相位仍是"上一 tick"语义）。修法：门控在**判定现场**用当前
快照重推导相位（与存储相位解耦），滞后不复存在。

## 实现要求

1. **`UCombatStateMachine::DerivePhase(Facts)` 抽纯静态函数**：UpdateFromFacts 的相位级联
   原样抽出；UpdateFromFacts = ApplyTransition(DerivePhase) + `bCancelWindowOpen = (派生
   相位==CancelWindow)`（语义与现分支写入逐字一致）。
2. **`CanStartAttackLive(Facts)`**：`TransitionAllowed(DerivePhase(Facts), Windup)` 纯评估，
   不改存储状态。
3. **`UCombatComponent`**：抽私有 `BuildPhaseFacts()`（UpdatePhaseMachine 复用）；公开
   `CanStartAttackLive()`（无状态机=true 保持裸组件旧行为）。
4. **双门重启用**：`TryStartAttack` 与 `USkillAbilityComponent::TryCast` 的注释门控改为
   `CanStartAttackLive()` 实时门。
5. **验收自动化**：
   - `CombatStateMachineTests` 增 CanStartAttackLive facts 级断言（Idle/CancelWindow 真、
     Active/Recovery 尾段/HitStun/Dead 假）。
   - `AttackLifecycleTests` 增**无 tick 间隔**断言：mid-Active 起手→ResetCombat→**立即**
     TryStartAttack 必须成功（存储相位门必红、实时门绿——滞后修复的直接证词）。
   - 既有护航全链：M8-034 两守卫（teardown 不锁死+窗口首帧链式吃键）、M8_031 三件套、
     M1_009、连招时序（M1_038/M3_031 族）、全量冒烟。
