## 1. 最终目标与明确范围

保持 UE 5.8.3 单机 3D 横版原型：X 横向、Y 地面纵深、Z 高度；固定镜头、现有四招、八武器、两波 2+3 敌人、1 秒波间隔、失败重试、出口、结算、存档语义均不因架构适配而改玩法。真正要增加的是**可校验的房间源数据和有限规则层**：房间事件驱动开波与清关，但 HP、动作、命中、奖励仍归现有所有者。

完成标准：生产战斗房从唯一房间源数据生成 Cook 资产，区域进入启动第 0 波，波次完全清空后按注入时钟延时启动下一波，最终只结算一次；资源缺失、重复/旧事件、死亡、离房和重试都有明确行为。训练场和系统测试房原行为不变。没有新增在线账号、服务端、多人、AOI、Buff/吸血/反伤、服务端数值表或新角色素材。

### 2.3 当前需要修正的事实与基线差异

1. `WaveSpawner::HandleEnemyDied` 已拒绝同一 spawner 的重复死亡和旧 RunId（`WaveSpawner.cpp:402-430`）；但 `URoomSessionSubsystem::NotifyEnemyKilled` 在 Running 中对未知/重复 ID 仍 `++KilledCount`（`RoomSessionSubsystem.cpp:381-417`）。M5-067 修**公共入口**，不称生产正常路径完全没有去重。
2. `ARoomTrigger::StartProductionSession` 在 `StartRoom` 后才解析敌人资产，失败时只记日志并返回（`RoomTrigger.cpp:186-208`）。M5-068 必须使“缺资源”不会卡在无怪的 Running。
3. `Data/rooms.json` 是 schema 1、只含 `room_training_01`；`GameFlowSubsystem`/触发器用 `room_combat_01` 硬编码和 transient 房间定义。这是数据统一工作，不可只改 JSON 而不接运行时。
4. `RoomSessionSubsystem` 的旧测试 `UEMMO.Tasks.M2_006.NotifyEnemyKilledCountsOnlyDuringRunning` 允许任意 Running ID 计数；M5-067 将更严格地要求已登记出生实例，需更新测试与接口约定，不能把旧测试悄悄删除。
5. 上一版设计把 `PlayerEnteredRegion` 当唯一首波触发来源。重试路径不会自动产生第二次物理 Overlap；本计划允许**可信重试服务在新 Run 启动后发布同一 activation_region_id 的逻辑激活事件**，并在事件中标记 retry 来源。此事件只表示玩家已重新进入本房间流程，不能由任意外部请求伪造。它使重试维持“立即开波”的现有体验。

## 3. 目标数据与运行时契约

### 3.1 房间源数据与资产

M5-069 将 `Data/rooms.json` 先保持 schema 1 并补 `room_combat_01` 行；M5-070 用 UE 编辑器 API 生成 `Content/UEMMO/Rooms/DA_room_combat_01`，在地图 `L_CombatRoom01` 的唯一 `ARoomTrigger` 上绑定。运行时使用 Cook 资产，不解析仓库源 JSON。`GameFlowSubsystem` 的战斗房入口身份必须与资产一致；训练房/系统测试房不被重定向。M5-071 再把该数据升级到 schema 2，显式提供 schema 1→默认两波规则的迁移与测试。这个顺序先证明数据闭环，再增加规则语义，便于定位回归。

配置字段建议：`rule_id`、`event`、对应 `region_id` 或 `wave_index`、`effect`、需要时的 `next_wave_index`、`delay_s`、`once`。事件白名单：`PlayerEnteredRegion`、`WaveCleared`、`PlayerDied`；效果白名单：`StartWave`、`MarkCleared`、`FailRun`。`StartWave` 的索引必须单调递增且不越界；同一波在同 Run 不可重启。输入不允许任意 Lua/表达式、概率或不认识的字段。未知 schema 拒绝；旧 schema 1 的迁移是明确规则，不是缺字段时悄悄回退。

默认战斗房规则的语义表：

| rule_id 示例 | 事件 | 效果 | 必须成立的边界 |
|---|---|---|---|
| `enter_start_wave_0` | `PlayerEnteredRegion(activation)` | `StartWave(0,0s)` | 新 Run 首次进入；重试可信逻辑激活；重复 Overlap 无效 |
| `wave_0_start_wave_1` | `WaveCleared(0)` | `StartWave(1,1s)` | 该波 `PendingSpawns=0` 且 Alive=0；暂停不推进延时 |
| `wave_1_clear` | `WaveCleared(1)` | `MarkCleared` | 单次结算；出口继续读 Session 状态 |
| `player_dead_fail` | `PlayerDied` | `FailRun` | 停出生/AI，清 pending；迟到事件不覆盖 Cleared |

规则加载校验除类型/引用外，应验证 `room_id` 唯一、触发区域存在、每个有入口的规则图有终态、没有自循环或越界 StartWave、延时有限且非负。区域在地图物理上是否可抵达由地图场景验收验证，静态数据无法仅凭 ID 保证。

### 3.2 事件、时间、幂等与效果失败

事件为值快照：`RunId`、`RoomId`、`EventSequence`、事件枚举、可选 `RegionId/WaveIndex`、`SessionClockSeconds`、可信来源标签。产生方在自身状态提交后发布；评估器只读当前 Run。死亡不是直接玩家输入，必须先由 `HealthComponent` 确认，波清空只有 `PendingSpawns==0 && AliveIds==0` 才发；规则层不接受外部指定的最终伤害。

建议接口边界（具体 UE 反射形式由 M5-071/072 编译确认，不并列创造另一个 Session）：

```cpp
struct FSceneRuleEvent {
    uint64 RunId;
    FName RoomId;
    uint64 EventSequence;
    ESceneRuleEventType Type;
    FName RegionId;
    int32 WaveIndex;
    double SessionClockSeconds;
};

// 评估器只返回/提交有限命令，Session 是最终准入者。
FSceneRuleDecision SubmitEvent(const FSceneRuleEvent& Event);
void AdvanceClock(double SessionClockSeconds);
void ResetForRun(uint64 RunId, FName RoomId);
void CancelRun(uint64 RunId);
```

`RunId` 只在所属 World 的 Session 内有意义；跨 World 隔离依赖对象生命周期和弱引用，不能把单独的 RunId 当全球唯一键。命令结果需包含 `Accepted/Rejected/AlreadyApplied` 和原因，日志记录 `room/run/rule/event/effect`，不只返回 bool。生产模式下 `BeginWaves` 的首波直接调用与规则 `StartWave(0)` 必须互斥；在非规则测试夹具里仍保留旧直接路径。这样 M2 既有用例不需要为证明新规则而全部改写。

规则评估器在运行内用 `EventSequence` 与 once 状态防重。同步效果先保留该规则，交给 Session 执行，成功才标完成；失败记录具体原因且不能留下“已完成但没效果”。会导致无法通关的效果拒绝，应使本 Run 进入 Failed 并可重试。`MarkCleared/FailRun` 仍由 Session 的先到终态规则裁决。延时任务使用 `SetSessionClockSeconds` 的注入时钟，实际时间推进须单调；暂停不推进，离房/重试/World teardown 按 RunId 取消，旧到期回调再次验证新 Run 不可触发。

区域是 UE 世界空间 3D Volume，X 横向、Y 纵深都参与判定，Z 只用于高度范围。Facing ±1 仅镜像 X；不可锁住 Y。M5-073 可复用 `ARoomTrigger` 的 Box 作为 `activation` 区域，若未来增多个区域再抽独立 actor，避免首版无需求的区域框架。

### 3.3 模块所有权与不可破坏的不变量

`CombatComponent` 保持动作/计时所有者；`WeaponComponent` 保持开火事务；`UnifiedHitApplier`/Ledger 保持命中准入与去重；`HealthComponent` 保持生命；`URoomSessionSubsystem` 保持 Run/波次/结算；规则评估器只持规则进度和延时请求，不能自己生成敌人、扣血、发奖励或开出口。Profile 的业务存档不能持 World Actor/规则瞬态；保留现有 SettlementId 奖励幂等。

初版规则**只消费已确认死亡引出的 WaveCleared**，不把每次武器命中变成关卡事件。M5-074 必须证明近战/枪械/投射物造成的敌人死亡都能经原生命链清波；不新增服务端复杂技能系统。将来真要做技能分段/充能/Buff，应另开任务并仍接现有 CombatComponent 与统一命中，不夹在 M5-067～074 中。
