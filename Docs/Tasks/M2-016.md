- 必留报告：`Docs/Tasks/Reports/M2-016.md`。

## 背景（协调者审计确认的生产缺口）

Session 的生产调用只存在于 PrototypeHUD 的调试 exec 代码：游戏主循环不注入 Session 时钟（波次泵不转）、RoomTrigger 只 StartRoom 不 BeginWaves（进房不出怪）、敌人定义无运行时资产（BeginWaves 需要）、RetryRoom/SetPlayer 无生产调用方（重试按钮缺上下文）。

## 实现要求

- `Scripts/Editor/create_enemy_assets.py`：从 Data/enemies.json 生成 `DA_melee_grunt`（/Game/UEMMO/Enemy/Definitions，UEnemyDefinition 资产；M1-009 先例），幂等，保存+报告。
- `ARoomTrigger`：StartRoom 成功后（有定义资产时）调 `BeginWaves(Def, EnemyDef)`；敌人定义软引用属性可配（默认 DA_melee_grunt 路径）；StartRoom/BeginWaves/Session 注册与 `SetPlayer` 由 Trigger 在 Overlap 时对玩家注册。
- `APrototypeCharacter::Tick`：每帧 `Session->SetSessionClockSeconds(World->GetTimeSeconds())`（World 空跳过；Session 从 GetSubsystem 获取，弱引用安全）——会话泵随游戏帧推进。
- HUD Retry 上下文：`SetRoomRetryContext(Def, EnemyDef)` 由 Trigger/资产路径注入（HUD 持有或经 Session 传递——最小侵入，报告写明）。
- 在环验证：临时 World + 真实 Tick，玩家进 Trigger → 敌人自动出生（波 1 的 2 只）→ 击杀 → 波 2 → Cleared——**不注入测试时钟**（会话时钟来自角色 Tick 接线）。

## 文件范围

- `Scripts/Editor/create_enemy_assets.py`、`Content/UEMMO/Enemy/Definitions`、`Source/UEMMO/Room/RoomTrigger.h/.cpp`、`Source/UEMMO/PrototypeCharacter.h/.cpp`（最小增量）、`Source/UEMMO/UI/RoomResultWidget.cpp` 或 PrototypeHUD（Retry 上下文最小接线）、`Source/UEMMO/Tests/SessionWiringTests.cpp`（新建）。

## 独立验收

- 包内/在环：进激活区后敌人自动出生（不再依赖调试 exec）
- 玩家死亡 → Failed → HUD Retry 按钮 → 重试成功（生产链路）
- 会话时钟随游戏帧推进（无测试注入）
