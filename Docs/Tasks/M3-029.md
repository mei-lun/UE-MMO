# M3-029 · 新游戏首启建档与完整战斗循环生产验证

> 任务卡；进度以根目录 TASKS.md 对应行扇。

## 背景（协调者审计发现的 P0 缺口）

GameFlow 的 NoSaveFound 分支**不创建 Profile**（注释："never automatic"），生产代码唯一 NewProfile 调用在 HUD 调试路径——**新玩家首次启动（无存档）没有 Profile**：领奖 RejectedNoProfile、成长链断裂。用户能打能跳是因为 M2-004 的 Health 独立于 Profile。另：敌人攻击玩家的完整链路（Telegraph→Attack→玩家受伤→死亡→重试）在生产中未经真实循环验证。

## 实现要求

1. **NoSaveFound → NewProfile（新游戏语义）**：GameFlow StartupLoad 返回 NoSaveFound 时调用 `Profile->NewProfile()`（这是"新游戏"的合法语义，区别于 M3-003 的"载入失败不自动 ResetNewGame"——NoSaveFound 不是失败，是首次启动）；RecoveryError 保持不建档（M3-015 语义不变）。
2. **完整战斗循环在环验证**（临时 World + 真实 Tick，复用脚手架）：新游戏首启（NoSaveFound→NewProfile）→ 进房（Trigger/StartRoom+BeginWaves）→ 敌人接近并**攻击玩家**（玩家 HP 下降）→ 玩家击杀敌人（敌人死亡）→ 全清 Cleared → Claim（XP/装备入账——**不再 RejectedNoProfile**）→ 穿戴 → 保存 → 模拟重启 → 恢复一致。
3. **玩家受伤/死亡/重试链**：敌人攻击 → 玩家 HP 下降 → 打死玩家 → PlayerDied → Failed → RetryRoom → 玩家复活 HP 满。
4. 既有测试全绿（M3-003 的"载入失败不自动 ResetNewGame"语义不变——NoSaveFound 与 RecoveryError 分支保持）。

## 文件范围

- 禁改：其他全部（GameFlow 之外的生产接线已就绪）。

## 独立验收

- NoSaveFound 首启 → Profile 自动建立（CharacterId 有效/Level1/XP0）
- 完整循环：进房→受伤→击杀→清关→领奖→穿戴→存档→重启恢复 全链在环通过
- RecoveryError 分支仍不建档（语义不变）；既有测试全绿
