### 0.1 键类型与事件键（§2 讨论稿的类型映射）

| 头文件类型 | 底层 | 语义 |
|---|---|---|
| `FCombatEpoch` | uint64 | 战斗代际：全局递增，每个 CombatComponent 生命周期铸一次（既有 `M1_019_NextInstigatorId` 会话级原子计数模式的正式化）；World EndPlay/离房/重试使旧 Epoch 整体失效。从 1 起，0 非法。 |
| `FEntityId` | uint64 | 世界内 Actor 唯一（010 注册表分配），旧 `GetUniqueID` 用法兼容；从 1 起，0 非法。 |
| `FShotId` | uint64 | 一个 Epoch 内的射击/动作序列槽位：`FCombatEventKey::ShotId` 必须取 010 注册表按 (Epoch, SourceEntity) 统一分配的公共 ActionSequence（近战/火器/载具共用单调序列）。近战旧 AttackInstanceId 与火器局部 ShotSequence 仅作关联字段，不直接充当公共 Key；不同能力局部序列都为 1 时仍产生不同公共 Key。从 1 起，0 非法。 |
| `FPelletIndex` | uint8 | 多弹丸 0..N-1（单弹丸恒 0）；255 为非法哨兵。 |
| `FTargetId` | uint64 | 目标唯一标识，旧 `GetUniqueID` 兼容直到 010 替换来源；从 1 起，0 非法。 |
| `FCombatTick` | uint32 | 本地 EpochTick 计数器值类型（见 0.4）。 |

- `FCombatEventKey { FCombatEpoch Epoch; FEntityId EntityId; FShotId ShotId; FPelletIndex PelletIndex; FTargetId TargetId; }`：五元组全等即"同一次命中"，就是去重面；`operator==`/`GetTypeHash` 已在头文件定义，值语义、trivially copyable、可直接入 TSet/TMap。同一 Shot 不同 Pellet 可对同一目标分别伤害（不同 Key），该 Shot 的浮空/倒地控制仍按 (Epoch, EntityId, ShotId, Target) 去重一次。EventId 由完整 Key 稳定派生（010 负责），不用指针值。
- 类型映射（语义不变，FGuid 收敛为本机 uint64 值语义 ID）：WorldEpoch→`FCombatEpoch`、SourceEntityId→`FEntityId`、TargetEntityId→`FTargetId`、ActionSequence→ShotId 槽位、PelletOrHitGroup→`FPelletIndex`。`FHitRequest` 内 `WeaponItemInstanceId`/`ProjectileInstanceId` 仍为 FGuid（物品/弹丸实例身份），由 022/027 冻结签名时确认。

### 0.2 非法值识别

- constexpr 哨兵：`InvalidCombatEpoch` / `InvalidCombatEntityId` / `InvalidCombatShotId` / `InvalidCombatTargetId` = 0；`InvalidCombatPelletIndex` = 255。
- constexpr 判定：`IsValidCombatEpoch` / `IsValidCombatEntityId` / `IsValidCombatShotId` / `IsValidCombatTargetId` / `IsValidCombatPelletIndex`、`IsUsableCombatEventKey`（四个 ID 字段全部有效才算可用键）。运行时对旧 Epoch、未知实体、注销后目标、同 Key 重复请求按 §2 约定拒绝；非法/半空键不得进入 Ledger。

### 0.3 决策枚举

- `EHitDecision : uint8 { Apply=0, Block_Invulnerable=1, Block_Immune=2, Block_Ignore=3 }`，UENUM(BlueprintType)，扩展 M1-019 的命中/拒绝语义：拒绝必须带显式原因，禁止只回 bool。Apply=接受并经 012 单入口恰好应用一次；Block_Invulnerable=无敌窗口（如起身保护拒绝整次命中）；Block_Immune=目标策略对该伤害/控制免疫（免疫 tag、韧性）；Block_Ignore=评估前过滤（旧 Epoch、未知实体、重复 Key、被过滤来源）。只增不改号；新增值必须同步扩展测试 `UEMMO.Tasks.M5_002.HitDecisionCoverage` 的全覆盖列表。

### 0.4 两种时钟与 SimulationTick 采样（不混用）

- `GameClockSeconds` = UWorld::GetTimeSeconds()，Pause 冻结：攻击帧/输入截止、火器冷却、弹道寿命、追踪沿用 §4 现状。
- `EpochTick` = 组件自增的 `FCombatTick` 计数：不是全局时钟、不是秒、跨组件不可比较、与 GameClockSeconds 不可比较或换算。HitStop 冻结 action clock 与 pin 的注入时钟（M3 现状）但不冻结 EpochTick 计数；Pause 随世界停。
- §4 留给 002 的 SimulationTick 采样规定：`FHitRequest::SimulationTick` 取发起方组件当时的 `FCombatTick` 值——本机单调事件标签，不是截止时间也不是服务器时钟。

### 0.5 所有权阶梯与指针禁令

- Profile（存档/业务值）= GameInstance 级生命周期，跨 World 存活，不引用 World Actor 或瞬态战斗状态。
- World/Session（实体注册表、Epoch、投射物、载具）= UWorld 级生命周期；EndPlay/离房/重试使旧 Epoch 失效并清弱引用、定时器、输入。
- CombatComponent（动作状态/计时/本地 Tick）= Pawn 级；HealthComponent 仍是生命唯一所有者。
- 指针禁令：本头文件全部事件/键类型都是值快照，不得持有 World/Actor 裸指针（头文件与测试均以静态断言钉死 `FCombatEventKey` 五个成员）；消费方只经 010 注册表弱引用解析 Actor。003/004 的 Definition 是不可变配置值，同样不持有 Actor。
- 状态唯一来源不变：CombatComponent 拥有动作状态/计时，HealthComponent 拥有生命；接受与拒绝只经 012 统一入口流过一次并桥接旧 OnHitConfirmed。免疫/霸体仍是策略标志，不是新动作状态。

### 0.6 空间与模块挂点

- 三维坐标 X 横向、Y 纵深、Z 高度；Facing ±1 只镜像 X（与 §4 一致，头文件注释同文）。
- §1 首次所有者表即冻结的挂点分配：后继任务只在各自新文件实现策略，不再编辑本头文件或他人文件；公共契约需要变更时先由协调者改本节与头文件并提交，再派依赖任务。

## 2. ID 与事件

```cpp
struct FCombatEventKey {
    FGuid WorldEpoch;
    FGuid SourceEntityId;
    uint64 ActionSequence = 0;
    int32 PelletOrHitGroup = 0;
    FGuid TargetEntityId;
};
struct FHitRequest {
    FCombatEventKey Key;
    FName WeaponDefinitionId;
    FName DamageProfileId;
    FName AttackReactionId;
    FGuid WeaponItemInstanceId;
    FGuid ProjectileInstanceId;
    FVector HitLocation;
    FVector Direction;
    int64 SimulationTick = 0;
    FString ConfigRevision;
};
struct FHitOutcome {
    EHitDecision Decision;
    float AppliedDamage = 0;
    bool bControlAccepted = false;
    bool bKilled = false;
    FName RejectReason;
};
```

实际UE反射/委托由002按本机编译确认，字段语义不可随意改。伤害倍率/装备属性由服务解析合法上下文，不让外部请求指定最终扣血。ActionSequence由010注册表按(Epoch,SourceEntity)统一分配，近战/远程/载具动作共用单调序列。旧AttackInstanceId和局部ShotSequence仅作关联字段，不能直接用作公共序列；不同能力局部序列都为1时仍须产生不同公共Key。EventId由完整Key稳定派生，不用指针值。

运行时接收旧Epoch、未知实体、注销后目标、同Key重复请求返回拒绝，无伤害/冲量/表现。一个Shot多个Pellet可分别伤害，控制去重另用 `(Epoch,Source,ActionSequence,Target)`，不能让霰弹绕过浮空限制。Ledger会话结束清理，不能淘汰尚活跃Shot/Attack的Key以允许重复命中；硬容量达到后拒绝新的攻击，不能静默破坏幂等。

## 4. 时间与空间

攻击帧/输入沿用现有60Hz逻辑和150ms缓存语义；HitStop补偿按当前M3实现。反应截止读其现有输入时钟；弹道与火器冷却用Pause冻结的World时间。SimulationTick只作本机单调事件标签，由002规定采样，不替代任何截止时间或服务器时钟。

X横向、Y纵深、Z高度，Facing±1只镜像X。发射偏移从脚底；Hit/Knockback/Launch方向是世界向量，不从Yaw猜纵深。所有角度/速度/尺寸附单位。

## 5. 状态唯一来源

保留 CombatComponent 为状态/计时所有者，HealthComponent为生命所有者。ReactionResolver返回是否接受、冲量、硬直/倒地/恢复参数，不直接改另一套State。生命/动作/运动三个维度保持原接口。免疫和霸体不是新动作枚举；CanMove/CanTurn/CanAttack由CombatComponent统一查询。

默认硬直覆盖max；死亡最高优先；旧实例中断立即失效；起身默认拒绝整次命中。普通跳跃不倒地。Damage与Control分别接受；控制免疫仍可伤害，纯控制不制造虚假伤害事件。默认浮空两次1.0/0.7与0.45/0.25秒恢复不变。

## 6. 表、资产和版本

源表只有JSON一种，顶层schema_version/table/rows。required_tables与支持能力在manifest明确列出。源路径 `Data/CombatSystem`；输出 `Content/UEMMO/CombatSystem`，资源相对引用第三方仍保留原路径。Python只在UE编辑器执行，资产必须保存后新进程重载。

既有Data/items.json/drops.json沿其Schema规范化导入，只有一份权威源。Catalog还提供FItemDefinitionCatalog/FDropTable适配与TestRoom reward/spawn定义；生成资产覆盖这些内容。生产HUD/RewardService在020A接入，缺ID拒绝。测试fixture的固定替身不能继续成为新内容的唯一生产获取途径。

## 7. 存档与实例

WeaponDefinition通过item_definition_id绑定FItemDefinition；FItemInstance仍是唯一物品身份，不复制一个武器Item。`WeaponStateByItemId`仅记录该实例弹匣，`ReserveAmmoByType`记录共享备弹；切装备不初始化新弹药。

v2新增这些值类型和revision，A/B完整性计算覆盖新字段。v1读取可用、v2迁移写新槽并读回后改索引；已应用领奖ID和实例ID不变。未来版本/未知业务引用拒绝并保留文件。完整派生属性和WeaponComponent在角色BeginPlay/换地图重绑，不存瞬态Actor。

历史accessory_training->charm_training由manifest显式别名承载，046保持原InstanceId/RolledStats/装备引用；别名校验无环、目标存在、revision覆盖。别名不是允许任意未知定义回退。

ConfigRevision是溯源值，不自动拒绝所有旧档。新目录只增行且旧ID/状态约束仍兼容时加载旧v2档，按当前目录重绑，不重新发初始弹。Ammo类型变化、容量小于已装弹等不兼容变更拒绝并保留槽，除非另有显式迁移卡。048必须用新增配置前的已保存v2档验证，不只在新revision创建档再重启。

首版近战武器attack_ids只能引用现有light_01/light_02/launcher/aerial_01完整集合，X/Z取消链不因换装备更换招式；武器属性/外观及配置反应可变化。未知/不完整AttackSet在校验阶段拒绝，不能读取后静默忽略。任意近战招式集切换以后单独拆卡，不新增一套计时器。
