# M5 配置作者手册（武器 / 子弹 / 反应 / 载具 / 关卡）

> 依据 M5-048（加武器 `scatter_training`）与 M5-049（加载具 `vehicle_armored_test`）及 M6-004（加关卡 `room_combat_02`）的**实际执行步骤和结果**编写；每条命令都在对应任务报告中有成功记录。手册描述的是本仓库 2026-10-30 时点的真实管线——不是设计稿。

## 0. 总原则（三条硬约束）

1. **生产 C++ 与生成脚本零改动**。加内容 = 改表 + 重新生成资产 + 测试。若某内容需要 C++ 分支，先开任务卡，不要在配置轮里夹带。
2. **表是唯一源**。`Data/CombatSystem/*.json` 与 `Data/rooms.json` 是唯一权威；`Content/` 下的 DA 全部由脚本生成，从不手改。
3. **每步先验证再下一步**。任一门禁失败，读日志修数据，绝不绕过。

## 2. 加一把武器（M5-048 实证路径）

1. **改表**：`Data/CombatSystem/weapons.json` 加行（选 mode：melee/hitscan/projectile/burst/parabolic/homing/explosive，字段约束见该表 comment 与 `CombatDataTableParser` 的严格 schema）；需要新弹丸/伤害剖面/反应时同轮改 `projectiles.json`/`damage_profiles.json`/`attack_reactions.json`——跨表 id 必须闭合（weapon→ammo/projectile→damage_profile）。
2. **登记**：`manifest.json` 是表级注册，已在册表加行不需要改它；新增表文件才需要登记（未登记的表文件会被拒绝加载）。
3. **获取入口**（可选）：`Data/items.json` 行（staging/商店授予）与 `Data/drops.json` 池行（结算掉落）——048 的 `scatter_training` 两处都加了。字段规则见 M5-020A（items 行映射 weapon_definition_id）。
4. **重新生成资产**：跑第 1 节的生成器两遍。生成 pass 会 validate-first（任一行非法整体不写），created/updated 报告在 `Artifacts/Logs/combat-system-assets-report.json`。旧 DA 会因 revision digest 全局变化被重盖章——这是 M5-038 预警的必然现象，由 pass1 吸收，不是错误。
5. **验证**：Build → 你的定向套件（测试里用 `LoadCombatDataDirectory` 喂真实表，别用夹具双胞胎行——M5-049 先例）→ 全量 `UEMMO.Tasks` → `TestPackage.ps1 -IncludeWeaponScenario`。
6. **哈希红线**：`git diff --stat -- Source/UEMMO/ Scripts/`（过滤 Tests）必须为空——048/049 都以此作为验收第一行。

## 3. 加一辆载具（M5-049 实证路径）

1. **三张表同步加行**（跨表门要求闭合，缺一拒绝整个目录）：
   - `vehicles.json`：vehicle_id/drive_type(只支持 ground)/max_health/defense/max_speed_cm_s/acceleration_cm_s2/mesh_path/camera 三字段。值边界：HP≤100000、防≤10000、速≤3000、加速度≤10000（`create_combat_system_assets.py` 顶部常量，镜像 VehicleTypes.h）。
   - `vehicle_seats.json`：**每车必须恰一行 driver 座位**（seat_location_cm/exit_offset_cm，偏移≤1000cm）。
   - `vehicle_mounts.json`：每车一行炮塔挂载（turret_weapon_id 必须是 weapons.json 在册武器；location_cm 相对车体原点；pitch 钳 ±89 内 min≤max）。
2. **mesh 复用规则**：新美术属独立素材卡；049 复用样车网格。
3. **重新生成资产**（同第 1 节，载具段在同一生成器里）：created 会列出 `DA_Vehicle_<id>/DA_VehicleSeat_<id>/DA_VehicleMount_<id>`。
4. **验证**：定向套件喂真实表断言行镜像 + 行为差异（049 的三套件是模板：统一入口伤害公式分流 `round(Base×100/(100+防))`、生产武装挂本行武器、弹匣按行消耗）→ 全量 → `-Section Vehicles`。
5. **当前骑乘模型说明**：hull 挂在 pawn 上随行走（M5-H03 审计模型），车辆速度/加速度当前为数据面镜像（驾驶分量待后续驾驶卡消费）；伤害/防御/武器差异是行为化的。

## 4. 加一个关卡（M6-004 实证路径）

1. `Data/rooms.json` 加行：room_id/display_name/map_path/spawn/bounds/reward_table_id/rules/waves（schema 2，生成器 validate-first）。
2. 克隆地图：`Scripts/CloneRoomMap.ps1 -TaskId <ID> -TargetMap /Game/UEMMO/Maps/L_<名>`（战斗房，带触发器/出口）；菜单面用 `-StripRoomActors`（纯外壳）。参数是唯一配置源。
3. `Scripts/PrepareRooms.ps1 -TaskId <ID>`：逐行生成 `DA_<room_id>` 并把每张带触发器地图的触发器接向本行资产（无触发器地图跳过）；双进程复载校验。
4. 菜单自动列出（行序=菜单序，`Data/rooms.json` 随包携带）；无需改 C++。
5. 验证：PrepareRooms 证据 → 定向套件 → `TestPackage.ps1 -IncludeMultiLevelScenario`（含源表隔离与双采集）。

## 5. 打包与发布候选

`Scripts/Package.ps1` 输出固定到 `Artifacts/Package/Windows`（UAT 追加 Windows，禁其他路径）；`package-info.json` 记录 source 提交与 exe SHA256。发布候选跑：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File Scripts/TestPackage.ps1 -IncludeMultiLevelScenario
```

含 M6_004 包内门禁（零豁免）、开发树源表隔离（Data 改名→运行→恢复→SHA 逐文件校验）与双采集。Section Full（`TestCombatSystemScenario.ps1 -Section Full`）跑 M5-054 全循环（空档→菜单→载具→清怪→记录/申领/装备→保存→二次实例恢复）。
