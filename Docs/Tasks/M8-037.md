## 现状与设计

- 现状：`TryCast` 零生产调用（launcher 组件形同虚设）；槽位输入走 `SkillLoadout::
  TryActivateSkill(槽)`（经济+交付一体）；M8-031 part2 草案在 TryCast 内"经济后再交付"存在
  **双重起手缺陷**（loadout 路径已起手，交付步再 TryStartAttack 被拒或弹体叠加）——零调用掩盖。
- 设计（零生产行为变化）：
  1. **TryCast 语义修正**：loadout 在线=经济+交付全走 loadout 槽位路径（其策略即交付，组件不重复
     交付，只补组件侧 CastSound/OnCast）；loadout 缺席=组件按自身 spec 交付（近战起手/弹体生成，
     组件隔离与无 loadout 职业形态）。
  2. **槽位路由**：`HandleSkillSlotPress` → `FindAbilityForSlot(槽)`（组件 AttackId==槽位攻击 id）
     → 命中组件走 `TryCast`（经济经 loadout，行为与直调逐字一致）；未配置槽位（两个待定技能、
     buff 行）保持直调。查找规则抽 `USkillAbilityComponent::FindAbilityForSlotAttack` 静态纯函数。
  3. **四组件配置**：SkillAbilities[0..3] = skill_light_01→light_01、skill_light_02→light_02、
     skill_launcher→launcher（弹体 spec 不变）、skill_aerial_01→aerial_01（近战 spec）；[4][5]
     留空待用户技能表。light 系/aerial 不在热吧六槽内（热吧=launcher/singlekick/damagelowkick/
     throwsand/earthbreak/stomp），配置零生产影响。X 基础链输入缓冲完全不动。

## 验收自动化（`SkillAbilityTests.cpp` 新增 `UEMMO.Acceptance.M8_037.SkillComponentCastAndIsolation`）

- 四命名攻击各自经组件独立施放：TryCast 真值、OnCast 广播接受、快照 AttackId 归属、**下一 tick
  状态机派生 Windup**（方案验收原句）；launcher 弹体从组件 spec 生成（计数 +1）且不起始近战实例。
- 组件隔离：硬销毁 light_01 后 light_02/aerial_01/launcher 仍各自施放成功。
- 路由查找：按攻击 id 命中配置组件、未配置/空 id 返回 null。
