# M7-002 多角色存档与旧档迁移

## 背景

Docs/DNF-Research/02-多职业功能实施方案.md §5 与 §9 第 3 步。前置：M7-001 职业与等级配置底座 DONE。

## 边界与内容

新增 Roster 角色 A/B/Index 事务（CharacterId、ProfessionId、显示名、存档前缀、活动标记）；新角色
前缀从 CharacterId 稳定派生，现有 Profile_A/B/Index 保持为旧角色原始槽；新建角色先写可恢复
pending 项再完整保存读回验证后提交。存档 schema v4：新增 ProfessionId、SkillId→Rank、UnspentSP、
技能槽映射、ProfessionConfigRevision、DungeonClears；FProfileSerializer 显式迁移 v1→v2→v3→v4，
旧档 ProfessionId 填 prototype、既有四招固定 rank 1、初始 SP=0，其余字段原值不变。启动顺序改造
GameFlowSubsystem：先探测 Roster，无 Roster 且有旧档时一次性迁移（旧档原字节只读），损坏即报错
保留文件。主菜单先显示角色列表再显示地城/自由选关；新建角色明确选职业。

## 验收条件（02 文档 §9 第 3 步）

旧档的角色 ID/等级/物品/弹药/已领奖/清关记录逐值不变、坏档回退、未来 schema 拒绝、两个角色
等级/背包/装备/清关隔离；真保存后重启验证；全量回归通过。
